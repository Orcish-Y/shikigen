### 1.1 原稿、截图与代码的使用规则

- 视觉目标尽量贴近 HTML 原稿：外壳比例、白色画布、冷灰侧栏、靛蓝主操作、字体层级和紧凑留白。
- 两份原稿存在配色、选中态和工具栏组织差异。沿用 PRD 的取舍：展开原稿统一定义菜单与基础视觉，折叠原稿提供 64px 图标栏及收起比例；折叠后继续使用同一套颜色、字体、菜单顺序和操作语义。
- 项目截图记录当前实际外观。当前 CSS 的简化或缺陷需要按本规范补齐；下文“当前代码规格”用于说明差距，不自动覆盖原稿目标。
- 原稿的示例数据、控件和系统装饰按已确认的业务契约适配。新增审批、资源、用量与详情继续使用相同外壳和内嵌区块；功能范围、数据真实性与执行控制遵循已定稿契约。

### 1.2 HTML 与 Tauri 窗口的尺寸换算

布局规格统一使用 WebView 内容区的 CSS px。Windows 原生标题栏由宿主绘制，40px 应用栏属于其下方的网页内容；保留平台窗口装饰。

两张 PNG 均为 2160×1393 个图片像素。图中展开主导航约 384px、收起约 96px、会话栏约 384px，与 256／64／256 CSS px 呈约 1.5 倍关系；应用栏约 60 个图片像素也与 40 CSS px 一致。整体很接近 1440×900 内容区在约 1.5 倍缩放下的呈现，这是根据截图和代码的推断，用户尚未提供实际显示缩放与内容区测量值。

对照原稿时先扣除原生标题栏、确认内容区和缩放，再比较侧栏宽度、内容上限与字体比例。窗口变宽后侧栏保持 256／64px，消息与输入保持最大 840px 并在剩余主区内居中；窗口变窄按第 6 节响应式收缩。截图物理宽度不直接用作断点或字号。

## 2. 视觉方向

现有应用是浅色、紧凑的开发者工作台：白色主画布、Slate 冷灰侧栏、靛蓝操作色、1px 结构线、少量轻阴影与小圆角。信息组织依靠侧栏、工具栏、文字层级和区块之间的留白。

新页面沿用这套方向：同一应用栏、主导航、字体、图标、焦点样式与控件密度。主内容根据任务使用列表、键值行、表单和覆盖式详情；保持现有可读比例。选中会话左侧的 2px 靛蓝细线是已有视觉标记。

用户和 Agent 消息均左对齐。用户正文放在浅灰容器，Agent 正文直接排在白色画布；代码、工具与审批以有语义的内嵌区块承载。主操作使用实心靛蓝，次操作使用白底细边框或文字按钮。

常用间距为 4、8、12、16、24、32px。当前消息组间距为 26px，头像与正文间距 12px，段落间距 10px，内嵌代码/工具区块顶部间距 14px。向原稿对齐时，消息组间距采用约 24px，正文约 14px / 24px；头像与正文间距继续使用 12px。新增内容先复用相邻组件的间距。

当前阴影：次按钮/选中会话为 0 1px 2px #00000005；输入区为 0 4px 20px #0F172A0F；模态层为 0 12px 40px #0F172A20；覆盖侧栏为 8px 0 24px #0F172A0F。新常规内容区域保持平面，阴影主要用于悬浮、覆盖与选中反馈。

输入区向展开原稿的柔和悬浮效果对齐，目标阴影可使用原稿的 0 12px 32px rgba(15,23,42,0.08)，继续保持 8px 圆角、1px 细边框和白色主体。原稿使用 Material Symbols；实现沿用当前 Phosphor regular，以同等大小和描边密度匹配图标。

## 5. 工作台布局

Tauri 初始窗口 1440×900，最小 390×600；见 [tauri.conf.json](src-tauri/tauri.conf.json)。保留平台原生窗口装饰，内容栏不绘制假窗口按钮。

| 区域 | 当前代码规格 | 继承要求 |
| --- | --- | --- |
| 应用栏 | 全宽 40px；水平 padding 16px | 品牌、状态摘要、命令入口固定在同一层级 |
| 主导航 | 展开 256px、收起 64px；左右 padding 8px | 菜单顺序与可用性在两态保持一致 |
| 导航头 | 当前至少 52px，“工作空间”与折叠控制 | 目标按展开原稿采用约 48px 品牌／折叠控制行，下方恢复“核心工作台”分组；版本只显示实际值 |
| 历史栏 | 256px；padding 16px 12px 12px；内部 gap 14px | 标题、过滤、列表、用量各自明确 |
| 会话工具栏 | 至少 56px；padding 8px 24px；gap 12px | 左侧标题和 Run 状态，右侧导出与详情 |
| 消息外容器 | max-width 840px；padding 18px 12px 32px | 目标顶部留白约 24px；主区居中、头像列独立、内容可收缩 |
| 输入外容器 | max-width 888px；padding 12px 24px 12px | 内部输入框最大约 840px，与主内容共用中轴；目标底部留白约 16px |
| 输入框 | 当前 padding 10px；textarea 三行、最小 62px、最大 180px | 目标初始两行、约 48px；随内容增高至 180px 后内部滚动，保持原稿紧凑比例 |
| 桌面详情 | 右侧覆盖，宽 min(400px, 100vw)，从 y=40 到底部 | 默认关闭，不改变底层 Grid 的列宽 |
| 命令面板 | 宽 min(480px, 视口减 32px)，距顶部约 15vh | 原生 dialog，轻量动作列表 |

当前外壳是纵向 Flex；工作区使用 Grid：主导航宽度 + 256px 历史 + minmax(0, 1fr)。主区使用 Flex，消息时间线占剩余空间，输入区占据实际布局高度并呈现轻微悬浮感。沿用这一实现，保证输入区不覆盖最后一条消息或审批按钮。

历史列表与主时间线独立滚动，所有可收缩区域保留 min-width/min-height 为 0 的约束。新增工具结果与 JSON 不能撑宽整页。托盘错误提示占据真实布局高度，复核时需考虑其与顶部栏、侧栏覆盖层和详情位置的共同关系。

### 待补：真实消息、工具与完整查看

Agent 正文渲染安全 Markdown；用户和工具字符串保留原文。明确的 type=text 内容块按所属角色展示，额外字段与未知对象提供完整 JSON；保持原顺序。消息正文仍位于既有白色画布或用户浅灰容器内。

段落、列表、引用、标题和表格使用当前字体、正文宽度与间距；表格仅在自身区块横向滚动。真实代码复用浅灰代码块、标题条、等宽字体与复制按钮，行号不进入复制内容。长代码、工具输出和 JSON 在最高约 320px 区块内滚动，完整查看复用桌面 400px 抽屉和窄屏底部面板；数据不因高度限制被截断。

工具调用放在发起调用的 Agent 消息下，按原调用顺序排列；结果更新对应卡片，找不到对应调用时保留独立工具结果。状态使用“等待结果／已返回／工具失败”；失败图标与错误文字匹配，工具状态不替代 Run 状态。非 null artifact 放在“附加数据”折叠区，完整只读显示。

### 待补：中止消息

取消／失败也保存后端已经接入的全部生成正文。已保存的中止消息在正文外显示“因取消中止／因失败中止”，不把提示拼进正文；正常完成的其他消息保持原呈现。取消标记采用中性色，失败标记采用错误语义色与可读文字。

终态已知但最后保存内容尚未读到时，在所属消息位置显示“正在读取已保存内容”；读取失败保留正文并提供手动读取。复制预览标为“复制当前片段”，后端完整事实到达后才作为已提交消息导出。新增 generation_status 和原子结算细则见消息契约。

### 待新增：本地图片与文件确认

仅识别 Agent Markdown 中明确的本地图片／文件链接，路径以当前 Agent 的 workspace_root 为范围。本地图片自动加载，宽度不超过正文，保持比例，聊天中最大高度约 320px；完整查看复用现有只读详情层。加载、缺失和读取错误就近显示，保留引用及重试入口，资源错误不覆盖运行状态。

网页链接经受控入口用系统浏览器打开；本地图片的“用系统打开”同样使用文件确认。只读资源接口与 Tauri 桥接仍待新增，具体字段见消息契约。

### 待新增：内嵌审批

每项默认未选择，不提供批量按钮；拒绝原因可选，切换到批准时隐藏并保留文字。全部动作选完后卡片开放“提交决策”，旁边保留次操作“取消运行”。底部和工具栏的“处理审批”只定位卡片，统一在卡片提交；窄屏保留这些入口。

required 未核实时只读，resolved 展示服务端实际决策并标记“已处理”，invalidated 显示因 Run 取消失效。请求确认前审批与取消互斥，pending 在对应操作区显示；提交、保存、恢复与竞态细则见[审批与取消交互契约](../docs/wayfinder/frontend-completion/tickets/003-approval-cancel.contract.md)。审批草稿跨重启保存，核实同一请求后恢复；折叠和关闭详情不丢失选择。

## 9. 操作、可访问性与动效

沿用原生 button、details/summary 与 dialog。图标按钮提供名称，选中导航提供 aria-current，折叠提供 aria-expanded。dialog 支持 Esc、焦点约束、关闭后返回焦点；侧栏覆盖同样有遮罩与关闭入口。

当前焦点为 2px 靛蓝 outline、3px offset；搜索容器为 2px offset。过渡为按钮约 150ms、Grid 约 160ms，遵守 prefers-reduced-motion。新增动画只说明进行中的状态，状态变化使用适量 aria-live，避免逐 token 播报。

可发送时 Enter 发送，Shift+Enter 换行；不可发送时拦截普通 Enter，仅 Shift+Enter 换行，不把 Enter 映射为取消或审批。中文输入法组合及候选确认期间不发送，并保持候选确认可用。用户上翻阅读后不抢夺滚动，提供回到最新消息。审批、取消和重连入口在窄屏始终可达。取消确认、参数详情、焦点返回与结果反馈遵循已定交互契约；全局键盘、滚动和响应式目标均已定稿，实际表现实施后验收。
