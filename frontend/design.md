# Shikigen 前端设计规范

## 依据与范围

视觉依据：[主导航展开态](../design/demo.html)、[主导航收起态](../design/front-end-demo.html)。功能边界依据：[前端 PRD](../docs/frontend-prd.md)，并沿用[设计草案](../design/design.md)中的产品约束。

设计定位：面向 Agent 开发者的浅色桌面工作台。白色对话画布、冷灰双侧栏、靛蓝操作色、细边框与紧凑工具栏；保持两个 demo 的布局比例和信息层级。展开与收起是同一页面的布局状态。

本阶段搭建页面框架：用显式标注的示例会话验证消息、代码和工具区块；本地交互可用。真实会话持久化、HTTP/SSE、审批与运行控制属于后续集成，界面不伪造连接状态或执行指标。

## 布局

| 区域       | 规格                        | 原因                             |
| ---------- | --------------------------- | -------------------------------- |
| 应用栏     | 高 40px，全宽               | 品牌、连接状态、命令入口保持稳定 |
| 主导航     | 展开 256px，收起 64px       | 为图标与中文入口提供足够空间     |
| 历史栏     | 宽 256px，独立滚动          | 导航折叠时仍可切换会话           |
| 会话工具栏 | 高至少 56px                 | 标题、导出、运行详情             |
| 消息区     | 最大宽 840px，内边距 12px   | 双方左对齐，保持代码可读性       |
| 输入区     | 内容最大宽 840px，外围 24px | 与消息区同轴，轻阴影形成悬浮感   |
| 运行详情   | 桌面右侧覆盖宽 400px        | 不压缩消息阅读宽度               |

整体用 CSS Grid 定义列，主区域用 Flex 分配工具栏、滚动时间线和输入区。输入区占据实际布局空间，确保长消息不会被遮住。使用 `100dvh` 与 `min-height: 0` 限定滚动边界。

响应式：≥1440px 首次默认展开；1280–1439px 首次默认收起，可手动展开；768–1279px 固定图标导航，历史通过覆盖侧栏打开；<768px 单栏，导航与历史分别覆盖显示，详情改为底部面板。桌面折叠偏好保存在 localStorage，窄屏 CSS 不覆盖该偏好。

Tauri 保留平台原生窗口装饰，不在应用栏绘制假窗口按钮。初始窗口采用 1440×900，最小 390×600。

## 视觉 token

| Token       | 值                  | 用途                     |
| ----------- | ------------------- | ------------------------ |
| canvas      | `#ffffff`           | 主画布、弹层             |
| sidebar     | `#f8fafc`           | 导航、用户消息、代码底色 |
| hover       | `#f1f5f9`           | 悬停、代码标题           |
| border      | `#e2e8f0`           | 1px 分隔线               |
| text        | `#0f172a`           | 标题、正文               |
| secondary   | `#475569`           | 次要正文                 |
| muted       | `#64748b`           | 辅助文字                 |
| accent      | `#4f46e5`           | 主操作、选中、焦点       |
| accent-soft | `#eef2ff`           | 选中底色                 |
| success     | `#047857 / #ecfdf5` | 工具结果                 |

Geist 为拉丁字体，中文回退 PingFang SC / Microsoft YaHei；JetBrains Mono 用于代码。字体通过 `@fontsource` 本地打包，无运行时字体 CDN。图标统一使用 Phosphor regular；品牌使用仓库现有 logo.svg。

正文 14px / 约 24px；标题 15px / 500–600；导航和角色 13px；辅助文字 11–12px；代码 12px / 20px。10px 仅用于非关键标签。间距采用 4、8、12、16、24、32px。控件圆角 6px，消息、代码、输入区 8px；输入阴影 `0 4px 20px #0f172a0f`。不使用大面积渐变或厚重卡片。

## 组件及交互

- 主导航：会话与对话、工具与技能编排、知识库与向量空间、提示词与评估、运行日志与追踪。首项选中，其他禁用并说明暂未支持。收起态保留图标及可访问名称。
- 历史：今天/昨天分组，本地标题过滤，新建、选中状态、无匹配反馈；底部固定当前 Run 用量。新增会话和草稿保留在页面内存，刷新后重置。
- 消息：28px 头像列与 12px 间距；用户浅灰容器，Agent 无外框；段落间距 10px，消息间距 26px。
- 代码：文件说明、复制反馈、行号、独立横向滚动。剪贴板失败时明确提示。
- 工具：原生 details/summary 折叠，示例结果显式标注。
- 输入：多行 textarea、草稿按会话隔离，未连接后端时禁止发送。空会话的建议任务填入草稿并聚焦输入。
- 详情：当前展示未知运行字段和空事件状态；不把示例当作真实 Run。
- 命令面板：新建、折叠、查找会话、运行详情。Cmd/Ctrl+K 打开，Cmd/Ctrl+N 新建；浏览器可能保留系统快捷键，界面按钮始终可用。
- 导出：下载已加载示例消息为 Markdown，包含代码及工具结果，标注示例来源，不包含草稿。

## 可访问性与动效

按钮用原生 button，图标按钮有 aria-label，选中项有 aria-current；折叠控件有 aria-expanded。2px 靛蓝焦点环，状态附带文本。原生 dialog 提供模态焦点约束，Esc 关闭并返回之前焦点。窄屏侧栏支持遮罩和 Esc 关闭。

过渡约 150–160ms，仅用于布局与操作反馈；遵守 prefers-reduced-motion。代码横向溢出限制在代码容器；历史和消息各自滚动；正文可选择复制。

## 实现边界与后续 API

| 做什么               | 为什么             | API / 实现                                              |
| -------------------- | ------------------ | ------------------------------------------------------- |
| 布局与草稿           | 保持交互状态独立   | React useState，CSS Grid/Flex                           |
| 折叠偏好             | 重载后恢复桌面偏好 | localStorage，异常时回退内存                            |
| 会话持久化（待接入） | 恢复真实会话       | GET/POST `/api/threads`                                 |
| 历史消息（待接入）   | 重建服务端事实     | GET `/api/threads/{thread_id}/messages`                 |
| 启动运行（待接入）   | 发起任务并观察     | POST `/api/threads/{thread_id}/stream`，fetch SSE       |
| 恢复观察（待接入）   | 切换会话后继续读取 | GET `/api/threads/{thread_id}/runs/{run_id}/stream`     |
| 审批/取消（待接入）  | 明确执行控制       | POST 同一 run 路径下的 `/approval-decisions`、`/cancel` |

`App.tsx` 负责页面状态与组合；`components/Sidebar.tsx` 负责双侧栏；`Conversation.tsx` 负责时间线与输入；`Overlay.tsx` 负责模态展示；`data/demo.ts` 隔离预览数据。接入后端时替换数据来源，保持展示组件边界。

验收尺寸：1440×900、1280×800、1024×768、390×844。检查两种导航宽度、草稿保留、搜索、新建、代码复制、导出、模态关闭及独立滚动。真实流式运行不在本次框架验收范围。
