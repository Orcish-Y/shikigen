# Windows 桌面应用与后端生命周期

Status: ready-for-agent

日期：2026-09-28  
来源：已关闭的 Windows 后端生命周期 Wayfinder 地图及其最终接口契约。  
交付性质：实现规格；状态表示需求可实施，不表示功能完成，也不改变用户主导代码实现的约定。

## Problem Statement

用户需要从 Windows 桌面应用直接进入 Agent 工作环境，并让任务在窗口关闭后继续执行。目前 Tauri 入口只有基础 Builder，尚未托管 Python 后端；Python HTTP 入口已通过共享 `open_runtime()` 装配和释放资源，但尚缺桌面控制协议、就绪检查及跨入口数据独占。

如果启动、退出和重试各自独立处理，用户可能遇到服务尚未就绪就发送请求、重复后端争用数据库、关窗丢失后台工作、退出后残留工具进程，以及重试连接到旧后端的问题。需要明确由桌面宿主管理后端及所属进程，让用户看见真实状态、保留故障原因，并仅在旧实例已确认回收后手动重试。

## Solution

Windows 10 或更新版本上的 Tauri 单实例应用负责启动并托管一份 Python 后端。窗口先显示启动状态；本次后端完成初始化、历史状态恢复和健康检查后，页面才获得实际服务地址。

正常关窗隐藏到托盘，后端和 Agent 任务继续运行；托盘支持恢复窗口和显式退出。显式退出先请求 Python 清理执行与存储，超时再强制回收所属进程。宿主异常终止时由 Windows Job 机制兜底。故障保留原因、提供本次启动日志，确认回收后允许手动重试。

桌面、手动 HTTP 和 CLI 共享 runtime 数据独占规则。进程托管能力通过平台适配接口隔离，为未来 macOS 实现保留替换位置。

## Implementation Decisions

以下决策沿用最终接口契约；模块名称描述职责，不限定实现文件组织。

### 职责与接口

| 做什么 | 为什么 | API / 接口 |
| --- | --- | --- |
| Rust `BackendManager` 串行协调启动、就绪、超时、重试及退出 | 为所有生命周期竞争提供一个决策入口 | 状态快照、页面命令、控制协议 |
| 平台适配层创建和回收完整托管实例 | 将平台资源归属与公共状态分离 | `spawn(spec)`、标准流访问、`wait_exit()`、`terminate_tree()`、`wait_tree_empty()` |
| Python 桌面启动器持有 runtime 并协调 HTTP 服务 | 初始化期间即可接收退出，避免重复装配 | `open_runtime()`、Uvicorn `Server.serve(sockets=[socket])` |
| 共享 runtime 入口负责独占数据、初始化、恢复与资源退出 | 所有入口遵循同一数据所有权规则 | `open_runtime()`、`runtime.lifecycle.shutdown()` |
| React 统一 HTTP/SSE 客户端消费宿主快照 | 重试切换地址时能清理旧连接并过滤迟到结果 | Tauri command/event、HTTP、SSE |

`spec` 描述可执行文件、参数、工作目录和环境变量。`spawn` 仅返回完整托管实例；部分失败由适配层清理。主进程退出、终止请求返回、全部所属进程退出是不同结果。确认失败后必须保留继续观察的能力。

### Windows 进程所有权

每次启动创建独立且非继承的 Job，由宿主持有并启用 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`。通过 `CreateProcessW` 的 `PROC_THREAD_ATTRIBUTE_JOB_LIST` 在创建进程时完成归属，不留下先创建再关联的窗口。禁止 Job 句柄传给子进程，不开放 breakaway；标准流采用句柄白名单继承，并关闭宿主持有的子端副本。并发创建时必须遵守机制调查记录的句柄继承约束。

强制回收使用 `TerminateJobObject`，保留 Job 句柄并以 `QueryInformationJobObject` 查询活动进程是否为零。仅回收本次拥有的后端及其后代，不接管或终止外部服务。

未来 macOS 可替换进程适配及路径、数据锁实现；公共状态、命令、协议和 Python 生命周期保持一致。宿主异常退出后的回收能力必须在目标平台独立验收。

### 开发态启动与配置

以 `env!("CARGO_MANIFEST_DIR")` 的编译期目录向上两级定位项目根，生成绝对路径并检查项目元数据、配置和虚拟环境 Python。直接启动项目 Windows 虚拟环境的 Python，cwd 为项目根；依赖由开发者提前 `uv sync`。路径失效时报错，项目移动后重新构建。缺环境或依赖时展示准备说明，不回退到系统 Python。

启动参数使用列表传递 `--config <绝对路径>`、`--startup-id <本次唯一标识>`、`--port <本次起始端口>`，不拼接 shell。Python 在加载配置前用 `python-dotenv` 显式加载根目录环境文件，`override=False`；文件缺失可继续，必要变量缺失只报变量名，不输出密钥值。Rust 不加载模型密钥。

托管 Uvicorn 关闭 reload；Python 修改后通过托盘退出再重开生效。

| `backend` 字段 | 默认值 | 校验 |
| --- | --- | --- |
| `port` | 43127 | 1～65535 的整数 |
| `startup_timeout_seconds` | 60 | 大于 0 的有限数值 |
| `shutdown_timeout_seconds` | 10 | 大于 0 的有限数值 |

分组或字段缺省使用默认值；拒绝未知字段、显式 null、布尔值和数字字符串。错误说明字段及原因，不静默回退。Python `AppConfig` 与 Rust 托管配置解析采用相同规则。

每次启动或重试重新读取配置，无运行中热重载。Rust 固定本次 `backend` 快照，以参数传递起始端口，退出期限也沿用该快照。Python 的其他配置从指定文件读取，不保证整个配置文件跨进程原子快照。

### 绑定与就绪

Python 仅绑定 IPv4 `127.0.0.1`，Windows 使用 `SO_EXCLUSIVEADDRUSE`。从本次起始端口递增：占用错误继续；10013 记录原始原因后跳过；其他绑定错误立即失败。到 65535 或启动总期限耗尽即失败，不回绕、不重新计时。成功后持有原 socket 并交给 Uvicorn，不关闭后重新绑定。

启动器在耗时初始化前建立 stdin 监听，持有共享 runtime 上下文并将 runtime 提供给 HTTP 应用。托管 HTTP lifespan 不重复装配。统一地址为 `http://127.0.0.1:<实际端口>`。

Rust 收到 `bound` 后立即探测 `GET /health/ready`。runtime 初始化、历史状态恢复及 HTTP 可访问均满足后，响应必须为 HTTP 200，包含数值 `version: 1`、匹配的 `startup_id` 和 `status: "ready"`。启动检查不额外请求模型生成内容。

未就绪时每隔 250 毫秒重试，单次请求最多 1 秒，不并发，也不越过启动总期限。连接失败、HTTP 503 可以继续等待；标识不符、版本不兼容或格式错误立即失败并清理。通过检查前不给页面服务地址。

### 控制协议与日志

stdin 接收控制消息，stdout 仅输出结构化消息，stderr 接收普通日志与堆栈。消息使用 UTF-8 逐行 JSON，每条以换行结束且最多 64 KiB；读入时限制缓冲，不能等换行后才检查。

共同字段为数值 `version: 1`、字符串 `startup_id` 和字符串 `type`。

| 方向 | `type` | 其他字段 |
| --- | --- | --- |
| Rust → Python | `shutdown` | 无 |
| Python → Rust | `bound` | 实际整数 `port` |
| Python → Rust | `startup_error` | 字符串 `code`、`message` |

`bound` 只表明绑定完成。退出结果由平台观察确认，不依赖自报；启动标识用于区分启动，不是认证凭据。

版本不兼容、损坏、缺必要字段或超长的当前消息导致协议错误和清理。Python 收到无效控制命令时记录 stderr 并退出清理。可识别为旧启动的消息忽略；不可解析的消息不能假定属于旧启动而放过。仅桌面托管模式将 stdin EOF 视为退出请求，卡住时由宿主期限与平台回收兜底。

Rust 持续消费 stderr，内存只保留最近 1 MiB。`get_backend_logs` 返回带 `startup_id` 的日志快照，错误页按需读取。重试清空旧日志并隔离迟到输出，退出后不保存；日志读取失败不能阻碍回收。

### 退出与回收

正常退出先停止接受新任务并通知 Uvicorn 停止服务，立即开始 `runtime.lifecycle.shutdown()` 结束执行，让 SSE 收尾；不得等全部 SSE 断开后才清理 runtime。请求和执行清理完成后退出 runtime 上下文、关闭存储，最后释放数据锁。

初始化中收到退出需取消初始化并清理已打开资源，不以 runtime 装配完成为前提。正常清理由 Rust 统一计时，不按步骤重新计时，也不等待 Agent 自然执行完成。

| 情况 | 处理 |
| --- | --- |
| 显式退出且主进程仍在 | 发送 `shutdown`，正常清理期限耗尽后强制回收 |
| 启动总期限耗尽 | 停止探测，保留启动超时原因，先正常清理再按需强制回收 |
| 主进程意外退出 | 立即检查并强制回收所属残留，不再等待正常清理期限 |
| 宿主异常退出 | Windows Job kill-on-close 回收所属进程 |

强制回收确认固定最多等待 5 秒。主进程已退出且全部所属进程回收后才开放重试。查询失败或超时显示“无法确认后端已完全退出”，禁止重试并继续观察。显式退出时保留错误窗口，后续确认后自动退出；其他故障在确认后开放手动重试，不自动启动。

默认启动超时路径预算约为 60 + 10 + 5 秒，之后呈现已回收或回收未确认的失败结果；不是操作系统保证进程必定退出的硬期限。

### 页面状态与手动重试

| 快照字段 | 语义 |
| --- | --- |
| `state` | `starting` / `ready` / `stopping` / `reclaiming` / `failed` / `stopped` |
| `revision` | 同一次宿主运行期间递增，后端重试不归零 |
| `startup_id` | 本次启动标识，尚未启动为空 |
| `base_url` | 仅 ready 有值 |
| `can_retry` | 管理器计算的当前重试能力 |
| `error` | 错误代码与可读说明，无错误为空 |

`get_backend_state` 返回快照，`backend-state-changed` 推送相同结构。页面先完成订阅再查询；初次接收后只接受更新的 revision。页面刷新不启动后端。

`retry_backend` 立即返回 `accepted`、拒绝原因 `reason` 与当前 `snapshot`，不等待就绪。管理器再次校验重试资格，接受后串行进入 starting 并生成新标识，后续通过事件通知。重复点击不能产生新进程。

| 事件 | 状态及约束 |
| --- | --- |
| 接受启动或重试 | starting，新标识，不可重试 |
| 本次健康检查通过且无退出意图 | ready，提供地址 |
| 发起正常清理 | stopping，撤销地址，不可重试 |
| 开始强制回收 | reclaiming，不可重试 |
| 故障清理完成且非应用退出 | failed，保留原始原因，可以手动重试 |
| 启动失败且没有资源需清理 | 可直接 failed，不虚构清理阶段 |
| 回收未确认 | failed，不可重试，继续观察 |
| 显式退出且已确认回收 | stopped，退出应用，不可重试 |

退出意图优先于迟到 ready，旧启动不能改变新启动状态。关窗隐藏不设置退出意图；故障清理完成不以 stopped 覆盖错误。

离开 ready 即清除地址并停止新请求。重试成功后统一客户端切换地址，重取 Thread、消息及 Run 状态，清理旧连接、忽略旧启动迟到响应。不自动重发消息或重新执行失败任务。

### 单实例、托盘与窗口

使用 Tauri Single Instance 插件，在启动后端前完成单实例检查。第二次启动仅通知已有实例恢复并聚焦窗口，随后退出。已有后端启动中或失败时只展示状态；已有实例退出中则继续退出，不取消退出也不创建后端。

托盘左键恢复并聚焦窗口，右键提供“打开主窗口”和“退出应用”。正常关窗隐藏并保留后端任务；托盘创建失败则保留窗口、展示原因，此时关窗走正常退出。

隐藏时发生生命周期故障自动恢复窗口并展示错误与重试能力；同一次故障仅唤起一次，用户可再次隐藏。单个 Agent 任务失败沿用任务页面处理。

### 运行数据独占

共享 `open_runtime()` 在初始化和恢复前，对聊天库与 SQLite checkpoint 实际文件分别非阻塞加独占锁；相同文件去重，内存 checkpoint 不加持久锁。固定顺序取得全部锁，任一失败释放本次已得锁并报数据正在使用，不影响既有 runtime。

锁持有至数据库连接关闭后，桌面、手动 HTTP、CLI 均遵守。同一应用的多个 Thread 共用 runtime 所有权，不按消息加锁。

使用稳定旁路锁文件，锁接口封装 Portalocker 3.2.0；Windows 显式采用 `Win32Locker` 与 pywin32，不修改全局后端。解锁关闭但不删除锁文件；占用权威为原生锁，不是文件存在或 PID。异常退出后仍须实际取锁成功方可启动，锁句柄不得泄漏给工具子进程。

第一版仅支持本机普通路径。相对路径转绝对路径并统一资源身份；检测到硬链接、符号链接、目录联接或网络共享时明确拒绝。父目录链接及路径别名也纳入平台检查，不能仅以绝对路径字符串去重。未来 macOS 使用对应 flock 实现，升级依赖时复核接口并分别验收平台行为。

## Testing Decisions

测试以公开行为、资源归属和用户可观察结果为依据，不绑定私有方法、内部调用次数或具体文件组织。不把 fake 平台测试通过视为 Windows 已验收。

测试边界建议已向用户核对；未获额外调整时采用以下方案。这是本规格的测试组织建议，地图已确认的验收条件保持有效。

1. **主入口为 BackendManager 公开命令和状态快照。** 在既定平台适配接口注入受控进程行为、健康响应和时间推进，验证启动、重试、退出、清理及竞争。优先经此入口覆盖协议错误与期限结果，避免为每个私有组件再开测试入口。
2. **复用共享 runtime 与 HTTP 边界。** 使用 `open_runtime()` 验证锁竞争、初始化取消及资源释放；通过 HTTP 检查就绪响应和业务可用性。真实 Uvicorn 与持续 SSE 场景检验退出协调，因为内存 ASGI 测试不能证明网络服务退出行为。
3. **Windows 原生验收验证系统能力。** 启动真实后端和测试后代，分别只强杀宿主、只强杀 Python，观察所属进程、端口及可重新取得的锁。另行保留外部服务作为不受影响的对照。托盘、重复打开及窗口聚焦在真实桌面环境验收。
4. **客户端公开交互验证。** 检验订阅后查询的交错、revision 过滤、地址切换、旧 SSE 关闭与迟到请求隔离；检查不自动重发消息。
5. **复用既有测试实践。** 配置测试已有临时配置及非法值校验；runtime 测试已有异步上下文与资源清理；server 测试已有 `httpx.ASGITransport` 与 lifespan；恢复测试已有独立子进程故障注入；确定性 Agent fixture 可避免联网和真实模型调用。Rust 管理器与 Windows 平台验收是新增覆盖。

| 场景组 | 必须观察到的结果 |
| --- | --- |
| 配置及路径 | 缺省正确；未知字段、null、布尔值、数字字符串、非有限值和越界值被拒绝；缺环境有说明；空格路径和不同 cwd 可用；重试读取新配置，本次期限不被中途修改 |
| 绑定与健康 | 默认、自定义、连续占用、10013、端口耗尽均按契约处理；仅回环监听，绑定后不重绑；bound 不等于 ready；错误标识、版本及格式触发清理 |
| 协议与输出 | 损坏、缺字段、超长无换行消息不能无限缓冲；旧启动可识别消息被隔离；stderr 洪泛不阻塞退出，日志上限及启动归属正确 |
| 初始化与正常退出 | 初始化各阶段可处理 shutdown/EOF；持有 SSE 与执行中也能清理；关闭连接后才释放锁；初始化卡住仍按期限进入回收 |
| 进程所有权 | 部分创建失败无半托管进程或句柄遗留；杀 Python 清理后代；仅杀宿主触发 Job 回收；外部独立服务保持运行 |
| 状态竞争 | 连点重试、重试与退出竞争、迟到 ready、事件与查询交错、旧请求迟到均不破坏新状态；revision 重试不归零 |
| 回收未确认 | 禁止重试并继续观察；保留原始错误；后续确认后按退出意图退出或开放手动重试 |
| 单实例与托盘 | 同时、启动中、退出中重复打开均无第二后端；关窗任务继续；托盘可恢复和退出；托盘失败不导致应用失联；同故障不重复抢焦点 |
| 数据独占 | 同库及部分库重叠不能并存；不同 Thread 正常；取锁失败回滚；无锁的残留锁文件可用；异常退出后可重新取锁；不支持的路径明确拒绝 |
| 客户端恢复 | 非 ready 无地址且不发新请求；新启动刷新 Thread、消息和 Run；旧响应被忽略；不自动重发或重跑 |

验收记录需区分自动测试、Windows 手工操作与尚未验证的场景。完成标准是上述可观察行为满足最终契约，不是仅编译成功或空闲退出成功。
