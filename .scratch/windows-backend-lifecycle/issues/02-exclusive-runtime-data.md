# 让多个入口安全争用运行数据

Status: ready-for-agent

## Parent

[Windows 桌面应用与后端生命周期 PRD](../PRD.md)。本票范围服从 PRD 的最终接口契约；ready-for-agent 表示信息可实施，代码仍由用户主导，助手实现需另行委托。

## What to build

CLI 和手动 HTTP 等共享 runtime 入口在初始化、恢复前取得全部持久数据的独占权；争用者明确失败，既有 runtime 继续工作。后续桌面入口自然遵循同一规则。

**接口与设计原因：** 在 open_runtime() 资源边界封装 Portalocker 3.2.0；Windows 显式使用 Win32Locker 与 pywin32，不修改全局锁后端。平台路径身份和锁实现保留可替换边界。

## Acceptance criteria

- [ ] 聊天库与 SQLite checkpoint 的实际资源分别非阻塞独占；相同文件去重，内存 checkpoint 不取得持久锁；固定顺序取锁。
- [ ] 全部锁取得前不初始化数据库、不执行恢复；任一锁失败释放本次已取得的锁，报告数据正在使用，不影响现有 runtime。
- [ ] 锁覆盖整个 runtime 生命周期，数据库连接关闭后才释放；同一 runtime 内多个 Thread 正常并行使用，不按消息重新加锁。
- [ ] 稳定旁路锁文件解锁后不删除；文件存在或 PID 不是占用权威。残留无锁文件可重新使用，异常退出后必须重新取锁成功才能继续。
- [ ] 仅支持本机普通路径；统一相对路径及资源身份，检查父目录与路径别名，明确拒绝硬链接、符号链接、目录联接和网络共享，不能只按绝对路径字符串去重。
- [ ] 锁句柄不继承给工具子进程；一个 runtime 结束后不因存活的工具子进程继续占锁。
- [ ] Windows 多进程验收覆盖同库、仅部分库重叠、不同库、取锁失败回滚、异常退出和连接关闭后的锁释放；记录实际测试与尚未验证的场景。
