# 首版 Tauri 聊天工作台与后端补全规格

Status: ready-for-agent

日期：2026-10-04。范围：已定稿的前端补全地图 Destination，即原 PRD 首版 17 条验收标准，以及用户追加的中止消息保存、工作目录图片预览与文件确认打开。

实施归属：用户主导代码与测试，助手负责解释、指导和 review；需要助手实现时由用户明确委托。ready-for-agent 表示规格信息齐全，应用实现和实机验收仍待完成。

## Problem Statement

用户已有 Tauri 前端模板、HTML 设计原稿和桌面两态截图，希望把工作台补成能持续使用的真实 Agent 应用。新增内容需要尽量贴近原稿，保持现有外壳、配色、字体、图标与信息密度。

后端已经支持真实消息、发送 SSE、既有 Run 全量观察、工具审批与同 Run 恢复、取消、持久事件和累计用量。现有前端仍缺少完整接入：会话列表没有分页和运行状态，历史没有用于恢复的运行状态，普通 Run 快照与事件没有独立纯读 HTTP 查询；前端还会丢失部分消息字段、过早清空输入，缺少完整审批、取消、工具记录、用量和导出呈现。

这些缺口影响的不只是正常发送。刷新、切换会话、隐藏窗口、断流、审批继续、取消与自然完成竞争时，用户需要知道后台任务的真实结果、当前连接情况和操作是否已经被接受。取消或失败后，已经生成的正文也必须保存并可再次读取，不能只剩客户端临时预览。

用户还需要直接阅读 Agent 明确引用的工作目录图片，以及经过确认后用系统程序打开文件。现有模板尚未具备相应的目录身份、资源读取与受控原生打开契约。首版的全部交互和接口方案已确认，现在需要一份统一规格供实施与验收使用。

## Solution

补齐首版聊天工作台及其所需后端能力：通过带状态的会话游标列表和历史消息发现当前／最近运行，通过既有 SSE 全量重建和实时跟随，通过新增纯读快照与事件解释运行结果和用量；审批与取消使用统一事实投影和用户主动操作。

聊天完整保留用户、Agent、工具消息及公开字段，分别呈现已提交事实与流式预览。运行取消或失败时，后端原子保存已经接入的正文和真实终态；前端取得保存事实后再开放完整导出。消息、审批选择和结果待确认记录按会话保留，重开后先查询核实。

沿用浅色工作台、冷灰侧栏、靛蓝操作、Geist／JetBrains Mono 和 Phosphor regular，补齐同风格审批卡片、完整内容查看、资源确认与运行详情。桌面两态、平板覆盖和手机单菜单共享数据及行为，全部首版操作在四档内容区视口可达。

实施按已确认的八批任务推进。各批新增组件从开始就遵守视觉基准，最终用真实 Windows Tauri 操作验证首版 17 条及跨项场景。

## User Stories

1. 作为应用用户，我希望新增功能尽量贴近现有设计原稿，以便继续使用熟悉的工作台。
2. 作为应用用户，我希望导航展开和收起时菜单、颜色与状态一致，以便快速识别同一功能。
3. 作为桌面用户，我希望主动选择的导航展开状态跨重启保留，以便保持自己的工作习惯。
4. 作为窄窗口用户，我希望侧栏以互斥覆盖方式打开，以便聊天内容仍有足够空间。
5. 作为手机尺寸窗口用户，我希望一个菜单默认打开会话列表并可切换主导航，以便快速切换会话。
6. 作为应用用户，我希望宿主启动、观察连接和运行状态分别显示，以便理解当前可用操作。
7. 作为应用用户，我希望从工作台新建并进入会话，以便开始真实任务。
8. 作为应用用户，我希望迟到的新建响应不抢走我后来选择的会话，以便继续当前工作。
9. 作为普通用户，我希望界面统一称为“会话”和“会话列表”，以便理解导航内容。
10. 作为会话用户，我希望列表显示未开始、运行中、等待审批及真实终态，以便判断每次任务的结果。
11. 作为会话用户，我希望优先看到服务端标题或已核实的临时标题，以便辨认会话。
12. 作为会话用户，我希望临时标题跨重启保留并由真实历史核对，以便再次找到之前的内容。
13. 作为会话用户，我希望会话按真实更新时间倒序排列并按本地日期分组，以便找到最近任务。
14. 作为会话用户，我希望看到相对时间及可查看的完整时间和时区，以便准确理解更新时间。
15. 作为会话用户，我希望每页自动加载 20 条更早会话，以便逐步浏览历史。
16. 作为会话用户，我希望第一页定期更新并按 ID 合并去重，以便看到最新状态而保留已加载历史。
17. 作为会话用户，我希望原始短页或空游标时显示“没有更多”，以便知道本轮分页边界。
18. 作为会话用户，我希望过滤明确只搜索已加载会话，以便理解未匹配的实际范围。
19. 作为键盘用户，我希望列表到底操作也能触发自动分页，以便无需使用额外加载按钮。
20. 作为会话用户，我希望加载、失败、空列表、无匹配和分页结束有不同提示，以便选择正确操作。
21. 作为会话用户，我希望下一页失败时保留当前列表和对话并原位重试，以便不中断阅读。
22. 作为会话用户，我希望打开会话时读取真实历史和最近运行身份，以便继续之前的任务。
23. 作为会话用户，我希望运行中的会话自动通过 GET 恢复观察，以便刷新后继续看到输出。
24. 作为会话用户，我希望等待审批时恢复真实待审批请求，以便继续处理同一个 Run。
25. 作为会话用户，我希望已完成、已取消和运行失败的状态一直保留，以便再次查看任务结果。
26. 作为会话用户，我希望切换会话后旧响应和旧输出不进入新会话，以便记录保持准确。
27. 作为会话用户，我希望完整消息与重复回放合并为一份记录，以便重连后不出现重复消息。
28. 作为会话用户，我希望每个流式片段按到达顺序追加，以便完整阅读实时回答。
29. 作为会话用户，我希望重连尚未成功时保留已有正文，以便继续阅读已经看到的内容。
30. 作为会话用户，我希望意外断流自动进行有限次数的 GET 恢复，以便短暂故障后继续观察。
31. 作为会话用户，我希望自动恢复停止后保留手动重连和状态查询入口，以便自主决定后续操作。
32. 作为会话用户，我希望等待审批或终态的正常连接结束不变成运行失败，以便正确理解任务状态。
33. 作为会话用户，我希望长工具执行没有文字时仍保持真实状态，以便避免错误的故障提示。
34. 作为桌面用户，我希望隐藏窗口暂停读取而后台运行继续，以便使用托盘时不取消任务。
35. 作为会话用户，我希望重新显示窗口时立即核实当前事实，以便看到后台期间的真实变化。
36. 作为输入用户，我希望发送正文保留首尾空白、换行与缩进，以便准确提交粘贴内容。
37. 作为输入用户，我希望全空白内容不能发送，以便避免无效任务。
38. 作为输入用户，我希望草稿按会话跨切换和重启保存，以便不丢失未发送文字。
39. 作为输入用户，我希望运行中和等待审批时可编辑下一条草稿，以便提前准备后续消息。
40. 作为输入用户，我希望当前运行结束后仍由我手动发送草稿，以便控制每次任务的开始。
41. 作为键盘用户，我希望可发送时 Enter 发送、Shift+Enter 换行，以便高效输入。
42. 作为键盘用户，我希望不可发送时 Enter 被拦截且仅 Shift+Enter 换行，以便不误触取消或审批。
43. 作为中文输入用户，我希望输入法候选确认和长按不重复提交，以便安心编辑。
44. 作为输入用户，我希望发送接受确认只清空对应版本草稿，以便保留请求期间新写的文字。
45. 作为输入用户，我希望发送结果未知时保留原文且不自动重发，以便避免重复执行任务。
46. 作为输入用户，我希望能查询并人工核对未知发送结果，以便决定确认记录或主动发起新任务。
47. 作为新会话用户，我希望示例填入或追加到草稿而不自动发送，以便先编辑自己的任务。
48. 作为阅读用户，我希望首次打开定位最新、切回恢复阅读位置，以便继续之前的阅读。
49. 作为阅读用户，我希望主动上翻后停止自动跟随，以便不被新输出拉走。
50. 作为阅读用户，我希望通过“回到最新”恢复跟随，以便继续观察新内容。
51. 作为阅读用户，我希望图片加载和布局变化保持正在阅读的消息位置，以便稳定阅读长对话。
52. 作为阅读用户，我希望代码和 JSON 在区块内滚动并可完整查看，以便主时间线保持可用。
53. 作为审批用户，我希望看到全部真实工具动作、来源和参数，以便判断是否批准。
54. 作为审批用户，我希望每项初始未选择且没有批量按钮，以便逐项作出决定。
55. 作为审批用户，我希望全部 Interrupt 的动作选完后统一提交，以便完整响应同一请求。
56. 作为审批用户，我希望拒绝原因可选且临时切换选择时保留文字，以便继续编辑自己的理由。
57. 作为审批用户，我希望参数默认折叠但可完整查看与复制，以便兼顾浏览与核对。
58. 作为审批用户，我希望跨重启的选择只有核实同一请求后才恢复，以便不误用旧决定。
59. 作为审批用户，我希望新的 checkpoint 或动作内容出现时重新选择，以便每次审批针对当前请求。
60. 作为审批用户，我希望提交与取消在请求确认前互斥，以便避免本客户端同时发出竞争操作。
61. 作为审批用户，我希望提交接收确认与后续运行观察分别表达，以便不用等待整段 SSE 才结束 pending。
62. 作为审批用户，我希望历史决策只显示后端实际接受的内容，以便核对真实审批记录。
63. 作为审批用户，我希望底部“处理审批”定位聊天卡片，以便在窄屏也能找到统一提交入口。
64. 作为审批用户，我希望无法完整解析的请求只读保留并说明原因，以便不提交不完整决策。
65. 作为运行用户，我希望运行中和等待审批时均可主动取消，以便结束当前任务。
66. 作为运行用户，我希望每次取消前看到一次确认并理解已有工具操作不会撤销，以便明确取消意图。
67. 作为运行用户，我希望取消与自然完成竞争时显示首个真实终态，以便不把已完成任务误标为已取消。
68. 作为运行用户，我希望取消或审批响应未知时先 GET 核实，以便决定下一次主动操作。
69. 作为消息用户，我希望 Agent 回答渲染 Markdown，以便阅读列表、表格和代码。
70. 作为消息用户，我希望用户和工具字符串保留原文，以便核对实际输入与输出。
71. 作为消息用户，我希望内容块保留原顺序及未知字段，以便完整查看真实记录。
72. 作为消息用户，我希望复制代码不包含行号、围栏和界面提示，以便直接使用原始代码文本。
73. 作为消息用户，我希望长内容可在现有抽屉或底部面板完整查看，以便保持一致操作习惯。
74. 作为工具用户，我希望调用和结果按真实 tool_call_id 关联，以便核对每项参数与输出。
75. 作为工具用户，我希望没有对应调用的结果仍独立保留，以便不丢失可读事实。
76. 作为工具用户，我希望工具失败与运行失败分别显示，以便正确理解失败范围。
77. 作为工具用户，我希望失败结果首次展开但尊重我之后的收起选择，以便兼顾错误发现与长对话阅读。
78. 作为工具用户，我希望 artifact 的空值、零和 false 均按真实数据保留，以便完整核对附加数据。
79. 作为运行用户，我希望取消后再次打开仍能看到已经生成的完整正文，以便保留已完成的部分工作。
80. 作为运行用户，我希望执行失败后已经生成的正文也被保存，以便阅读和导出已有结果。
81. 作为消息用户，我希望中止原因在正文外独立标记，以便分清正常完整回答与中止回答。
82. 作为消息用户，我希望迟到的片段或旧快照不能改写已保存的终态正文，以便历史稳定可靠。
83. 作为消息用户，我希望保存尚未确认时明确提示读取状态，以便不把临时预览当成已保存记录。
84. 作为消息用户，我希望网页链接由系统默认浏览器打开，以便 Tauri 主窗口保留当前会话。
85. 作为消息用户，我希望 Markdown 不自动读取网页图片或执行未知协议，以便所有资源入口符合已定行为。
86. 作为消息用户，我希望 Agent Markdown 明确引用的本地图片自动显示，以便直接查看生成结果。
87. 作为消息用户，我希望本地访问限定在当前 Agent 工作目录，以便文件与现有工具使用同一范围。
88. 作为消息用户，我希望图片缺失、越界、变化、过大或不支持时就地说明，以便理解并重试读取。
89. 作为消息用户，我希望可查看图片原始引用、实际目标和完整图片，以便核对当前磁盘内容。
90. 作为文件用户，我希望每次点击文件先展示真实路径并确认打开，以便决定是否交给系统程序。

116. 作为项目维护者，我希望实施结果按真实 Tauri 行为和持久事实逐项验收，以便分清规划完成、代码完成与验收通过。

| 后端 Runtime 与持久层 | 保有会话、运行、消息、事件、审批和用量事实，补纯读查询及中止正文结算 | 为刷新、重开与竞态提供真实依据 | 已有运行写接口、持久查询、事实事务和公开事件投影 |
| HTTP／SSE 适配 | 暴露分页、历史、快照、事件与资源查询，沿用发送、观察、审批、取消 | 让桌面客户端使用一致公开契约 | 本节列出的 HTTP 端点与既有四类 SSE 帧 |
| Tauri 宿主 | 沿用后端托管、单实例、托盘、启动身份，补可见状态及受控系统打开 | 提供窗口生命周期与原生能力边界 | 现有宿主状态桥接、可见状态桥接和受控打开命令 |
| BackendSession | 维护当前地址租约、请求取消、结构化错误和 SSE 解析 | 隔离动态地址及旧启动的迟到响应 | startup_id、base_url、AbortSignal、HTTP 与 SSE |
| 工作台数据层 | 按会话／Run 保有完整事实、预览、输入、审批与查询状态 | 使列表、聊天、详情消费同一份事实 | 统一接入 POST／GET SSE 和纯读查询结果、本地存储 |
| 工作台 UI | 派生状态、操作资格、消息呈现、导航、阅读与模态 | 保持原稿风格及一致操作语义 | 共享页面动作、既有 dialog、Clipboard、Blob 下载、滚动和视口能力 |

工作台事实和输入的所有者独立于可卸载的 Workspace，也独立于某次 BackendSession 寿命。宿主退出 ready 时可继续使用既有故障页，恢复后重新查询；已有应用内事实和未提交文字保留。

### 2. 会话与运行 HTTP 契约

| 端点 | 实施要求 |
| --- | --- |
| POST /api/threads | 沿用创建和 thread_id 返回；创建只因用户主动动作发出 |
| GET /api/threads | 裸列表改为分页 data／next_cursor，增加同一 Run 的 run_id／run_status 摘要 |
| GET /api/threads/{thread_id}/messages | 保留 data 完整历史与 seq ASC，每条消息外层增加 run_status |
| POST /api/threads/{thread_id}/stream | 沿用 ChatRequest.message 原文发送及返回 SSE |
| GET /api/threads/{thread_id}/runs/{run_id}/stream | 沿用全量重建并跟随，不接受查询游标或 Last-Event-ID |
| GET /api/threads/{thread_id}/runs/{run_id}/messages | 沿用既有运行消息查询，终态后补齐可能未收到的最后完整消息 |
| GET /api/threads/{thread_id}/runs/{run_id} | 新增 data: RunSnapshot 的纯读 JSON 查询 |
| GET /api/threads/{thread_id}/runs/{run_id}/events | 新增 data: RunEvent[]，按 seq ASC 返回查询时全部已提交公开事件 |
| POST /api/threads/{thread_id}/runs/{run_id}/approval-decisions | 沿用提交全部 Interrupt 响应、恢复同一 Run 和返回 SSE |
| POST /api/threads/{thread_id}/runs/{run_id}/cancel | 沿用取消和 RunSnapshot 返回，补齐中止正文的原子结算 |

- 会话列表只接受可选的不透明 cursor，每页固定 20 条，按 updated_at DESC、id DESC 排序。摘要保留 id、user_id、title、created_at、updated_at，新增 run_id 与 run_status；尚无 Run 时两字段均为 null，存在 Run 时两字段均有值。
- 有未终结 Run 时摘要指向它，否则指向最近发起的 Run；旧 Run 用量晚结算不改变“最近发起”的身份。每个会话最多一个未终结 Run，沿用运行创建与首条用户消息原子提交，使列表与历史末条定位一致。
- 游标记录签发时末条的更新时间与 ID，不根据边界会话后来变化的时间改写位置。格式或内容无效返回 422。末页外返回 20 条；原始短页 next_cursor=null，空列表为 200、空 data、空游标。跨页不承诺固定快照。
- 创建、发起、审批继续及运行状态变化更新会话时间，状态与排序时间同次提交；查询不更新时间，delta 不逐 Token 更新时间。
- 历史 run_status 是消息所属 Run 在查询时的已提交当前状态，同一响应内同 Run 一致；不写进消息正文。工具 content.status 仍只表示工具结果。
- RunSnapshot 保留 id、thread_id、status、error、error_code、created_at、updated_at、completed_at、usage、usage_pending。边界将 snapshot.id 与 SSE run_id 统一；不修改现有 cancel／SSE 身份格式。
- RunEvent 与 SSE event 共用公开投影，保留 seq、created_at、category、event_type、payload。类别为 message、lifecycle、approval；不直接暴露另一套数据库事件格式，不返回 delta。首版事件不分页、不加服务端过滤。
- 会话列表、历史、快照与事件四个 JSON GET 只读已提交事实，设置 no-store。Run 归属不符或不存在返回 404，暂不可读返回 503 和 Retry-After: 1，损坏／其他服务端错误返回 500。
- 纯读快照不得直接调用含 interrupted 恢复校验写入的旧 read_run 路径；纯读请求不执行 Graph、不审批、不取消、不写入 Run error。GET stream 继续保留既有后端恢复校验。
- 快照和事件各是请求时刻的事实，两个响应不承诺同一事务时刻。状态发现不增加 active_run、latest_run 包装或独立历史 Run 列表。

### 3. 会话状态与操作资格

| 已确认事实 | 中文状态 | 普通发送 |
| --- | --- | --- |
| 尚无 Run | 未开始 | 可用 |
| running | 运行中 | 禁用 |
| interrupted | 等待审批 | 禁用 |
| completed | 已完成 | 可用 |
| cancelled | 已取消 | 可用 |
| error | 运行失败 | 可用 |

普通发送还要求宿主 ready、当前身份与状态已核实、无提交 pending 或发送结果待确认、正文非全空白。读取中、读取失败或未知状态不等同于未开始。

running／interrupted 期间允许编辑和保存下一条消息草稿；没有排队或自动发送。底部主操作分别为“取消运行”和“处理审批”，后者定位聊天卡片。终态继续保留原中文结果，用户主动发送下一次任务后才进入新 Run。

### 4. 身份隔离与事实权威

- 请求绑定 startup_id、base_url、AbortSignal；选择与观察各自有代次，另绑定 thread_id／run_id。切换、重建、新 Run 或租约撤销后，旧响应和计时器不能发布到当前目标。
- 当前有效观察的 SSE metadata 提供 Run 当前状态，同步同身份列表行。列表、历史、普通快照和历史 lifecycle 不覆盖该状态；无有效观察时允许适用的新查询更新状态。
- 同 Run 已确认终态不回退为非终态。interrupted 可继续为 running，状态不能按固定等级比较新旧。有效取消写响应与普通快照分别处理，前者可立即确认真实终态。
- 列表更新时间只使用服务端事实，较旧摘要不回退已知时间；SSE 不提供时间时立即更新状态，排序等后续摘要补齐。
- metadata 按实际携带字段更新，省略保留。usage=null 表示用量未知，不能填零或把缺少 usage_pending 当 false；error、completed_at 等可空字段按各自契约解释，不一概视为未知。
- 快照字段按请求期间的状态、同组字段及执行阶段变化判定适用性。旧 error=null／completed_at=null 不清除新失败或终态事实；取消后的用量可能不更新 Run.updated_at，不得仅靠该时间丢弃更新。
- 完整消息按会话 seq 合并去重，完整事实覆盖同 seq 预览；delta 在当前观察按到达顺序追加，不按 seq 或文字去重。seq 允许空洞，查询漏返回某条不删除已知事实。
- 事件按 thread_id／run_id／seq 合并；同身份同 seq 冲突是协议问题，保留已确认记录。未经协议校验的载荷仅可作为只读错误原文，不接入消息、事件或当前审批事实。

### 5. 打开会话与全量恢复

1. 可见且 ready 时读取历史；缓存可先显示并标明更新。成功空历史才表示该时刻尚无 Run，有更新的运行线索时再查询收敛。
2. 从末条消息取 run_id／run_status。running、interrupted 建立既有 GET Run stream；终态先显示历史，进入后读一次纯读快照，事件按详情需要读取。
3. 新 GET 观察取得有效 metadata 后，只重置目标 Run 的未提交预览，再积累本次回放。metadata 前失败保留原内容，完整事实与其他 Run 不清空。
4. 后端负责 interrupted 的持久审批／checkpoint 一致性校验；前端按 seq 回放 required、resolved、invalidated 重建有效请求。只有当前仍 interrupted、全量回放正常结束且有匹配有效请求时才开放审批。
5. JSON snapshot／events 可补状态和历史，不能替代审批的 GET stream 校验。历史生命周期不覆盖当前 metadata，正常 interrupted EOF 不进入重复重连。
6. 第一页发现不同 run_id 时先读历史核实再换目标，不按 UUID 大小判新旧。关旧观察不调用 cancel；新 Run 不继承旧状态、用量或审批。

### 6. 观察、重试与窗口可见性

- 分别表达未建立、连接中、已建立、重试等待、正常结束、主动暂停与恢复停止。观察失败不是 Run error，长工具执行无 delta 不是断流。
- 最后状态仍 running 的意外 EOF、网络故障、GET 503 和可恢复 SSE error 进入 GET 恢复；原故障后依次等待 1、2、5 秒，最多三次，503 不早于 Retry-After。
- 一个恢复轮次只有一个任务，error 与随后 EOF 不重复安排。首帧 metadata 不重置失败计数；连续正常建立 30 秒或正常完成 interrupted／终态回放才重置。
- 三次失败后保留数据与手动入口，列表轮询不不断重开同 Run 恢复。手动重连、重新进入／显示或新有效租约可开新轮次，仍遵守 Retry-After 和请求互斥。
- 正常 interrupted／终态 EOF、主动 Abort 和租约失效不计为网络失败，不隐式取消。GET 400／500、不可恢复 error 或解析失败停止自动恢复。
- 隐藏、切换或宿主非 ready 时停旧 SSE、相关 GET 和计时器；保留完整事实和文字。重新显示／选择／ready 后立即读历史定位，合并同时到达的恢复信号。失去焦点不暂停，布局和详情变化不重建观察。
- 新增 get_workspace_visibility 与 workspace-visibility-changed，均提供 revision、visible。先订阅再查询，按 revision 丢弃旧结果；visible 是成功操作后的实际显示状态，区别于焦点。获取失败保留已知值，首次未知按可见处理。
- 第一页在 visible 且 ready 时每 5 秒轮询，不重叠；503 推迟下一轮，不叠加三次恢复任务。只轮询第一页不承诺发现任意数量同时变化的会话，显式重载重新建立分页位置。

### 7. 草稿、发送与新建

- 草稿、版本、本次提交原文和必要待确认记录按应用命名空间／会话 ID 本地保存，所有者不随 Workspace 卸载。恢复文字不恢复执行；动态端口、租约、连接、delta、计时器不作为有效状态持久恢复。
- trim 只判全空白，ChatRequest.message 使用原文。既有无效 Unicode surrogate 替换继续沿用，不裁剪正常文字。
- 可发送时 Enter 与按钮共享动作；Shift+Enter 换行。不可发送时普通 Enter 被拦截且不换行、不取消、不审批，Shift+Enter 仍换行。输入法组合优先，候选确认和 repeat 不提交。
- 发送 pending 时仍可编辑新版本，禁止第二次普通发送。本次 POST 有效 metadata 确认接受后只清对应版本；旧 Run 或 GET metadata、HTTP 200、相同正文不能证明本次接受。
- 接受前网络／解析／POST 500／主动中止等未知结果保留原文和记录，只 GET 核实；已有 run_id 后断流按已接受 Run 的观察恢复。应用重开时旧 pending 变待核实，不假定请求仍在。
- 没有客户端请求关联标识，查询未发现新任务也不证明旧 POST 永不生效。用户可核对消息后确认记录，或主动“作为新任务发送”；后者说明创建新任务，仍受发送资格约束，绝不自动重发。
- 本地存储失败回退内存、保留文字并提示“本地保存不可用”；Thread 404 不静默删除草稿，可复制或转到新会话。
- 新建返回有效 thread_id 且意图仍当前时选中；用户已切别的会话则保留创建结果并提示，不抢选择。后续列表失败不把已确认创建改成失败、不再 POST，更新时间等待服务端事实。
- 创建 POST 的结果未知时 GET 会话列表供用户核对，不自动再次创建，不改原会话草稿；没有 thread_id 时不能假定已取得可恢复的运行目标。
- 无有效会话时提供新建，不把文字存到空 thread_id。真实空会话提供解释目录、查找工具注册、总结指定网页三例；空草稿填入，有原文则空行分隔追加，聚焦但不发送。迟到读取不抢其他输入或模态焦点。

### 8. 会话列表、标题与时间

- 按 ID 更新已有字段、插入新项、去重后按服务端规则排序。第一页轮询不清更早页、不动选择／草稿／已建立的下一页游标；第一页缺项不表示删除。
- 到底自动加载，每页 20，无正常“加载更多”按钮。原始 data 少于 20 或 next_cursor=null 即停止并显示“没有更多”；过滤数和新增去重数不作为边界。
- 无过滤且列表未填满可视区时自动填充；过滤仅匹配已加载显示标题，不因输入过滤连续读完历史。过滤后不能滚动时，明确向下滚动或聚焦列表的 End／PageDown 仍可触发一页。
- 首次无事实显示等高 skeleton，刷新保留列表，下一页只显示底部加载。失败保留游标与对话，原位重试遵守 Retry-After；失败哨兵不能无限重试。无效游标可显式重载第一页。
- 区分加载、失败、无会话、无匹配、无更多；过滤提示“仅已加载会话”，隐藏当前行不切换会话。
- 标题优先服务端非空 title，其次本地临时标题，再“新会话”。临时标题由首条已提交用户消息的明确文本形成一行短标题，不改正文、不取未发草稿、不猜未知块。
- 临时标题按会话缓存跨重启，当前历史读取后重新核对；不为列表批量读取所有历史，不写回后端、不新增标题编辑或 PATCH。列表、工具栏、命令和过滤使用同一显示标题，完整标题可键盘／触控查看。
- 日期按本地日历分“今天／昨天／更早”。不足一分钟“刚刚”，不足一小时／一天／七天分别分钟／小时／天，七天起本地日期；相对差值与日历分组各自计算。
- 完整时间含本地日期、时间、时区，UTC 原值可复制。可见时每分钟刷新显示，重新显示立即重算，不增加 HTTP。未来时间用绝对日期，无法解析显示“时间未知”；未来日历或未知日期单列“日期待确认”，不编造排序时间。

### 9. 审批卡片与草稿恢复

- required 在所属 Run 时间线位置呈现一张卡片，按 seq 定位；Interrupt 及 action_requests 保留原顺序，namespace 为空显示“主流程”并保留原值，真实工具名、description 和允许选择可读。
- 每项默认未选择，仅支持 allowed_decisions 中首版支持的批准／拒绝，没有批量按钮。显示已选 X／Y，全部 Interrupt 的全部动作选完后统一提交；不支持或无法完整解析则整组只读，保留恢复和取消入口。
- 参数默认折叠，可展开完整格式化 JSON、复制与放大只读查看；详情不编辑参数、不放第二套审批按钮。
- 拒绝时显示可选原因；切批准隐藏但保留，切回继续编辑。批准不带原因，纯空白拒绝原因可省略，非空按原文提交。
- 审批草稿包含 Run、完整 checkpoint 坐标、Interrupt ID／namespace、动作原位置及内容、review_configs。恢复核对工具名、完整 args、description 等全部内容；对象键顺序不影响等价，数组顺序保留，不能仅按工具名复用。
- 跨切换／重启先显示核实，经过正常全量 GET 校验且请求身份内容一致才复用选择，不自动提交。新 checkpoint、Interrupt、namespace 或动作变化默认未选择。
- 历史 resolved 只显示后端实际 decisions／原因；invalidated 显示实际失效。只知道终态但未取得事件时说明不可提交，不伪造已处理事实。确认处理／失效后仅清理匹配旧草稿，404 保留只读核对内容。
- 底部和工具栏“处理审批”定位当前卡片及标题／未选项；尚未恢复则定位提示和恢复入口，不生成空表单。

### 10. 审批提交、取消与未知结果

- 审批提交要求 ready、正确身份、有效全量恢复、全部允许选择、无同 Run 写请求 pending、前次未知结果已核实且等待已到期。
- 沿用 responses 按 Interrupt ID 映射 decisions，覆盖全部当前 Interrupt，按动作顺序发送；批准只含 type，拒绝可含 message。checkpoint 只用于客户端身份保护，现有 body 不发送 checkpoint，不新增客户端请求标识或服务端条件提交承诺。
- 提交时捕获完整内容，锁本组编辑、提交与同 Run 取消。本次 POST 有效同 Run metadata 即确认接受并结束 pending，后续 SSE 继续观察；不等 EOF，不将 GET metadata 当提交确认。
- 取消 pending 锁同 Run 审批编辑／提交和再次取消。实际请求失败后结束 pending，进入待核实；不留下永久处理中，也不自动再 POST。
- 取消要求核实同一 running／interrupted 目标及无互斥 pending，不依赖审批参数可解析、选择已完成或全量审批校验；纯读状态查询足以核实取消目标，仍不能因此开放未经 GET stream 恢复校验的审批提交。
- 取消每次先显示“取消本次运行？”弹窗，说明“取消不会撤销已经发生的工具操作，已开始的操作也不保证立即停止。”按钮“继续运行／确认取消”，默认焦点继续运行；Esc、关闭、遮罩均不发请求。
- 确认瞬间重查身份、选择、租约与资格。切会话、隐藏、目标变化或宿主失效关闭确认；已有终态不再取消。取消只针对实际 Run，不是 AbortController 停观察。
- 有效取消快照立即确认返回的 cancelled／completed／error，分别显示已取消／已完成／运行失败，结束 pending；身份不符、解析失败或非终态响应只作为协议问题 GET 核实，不能显示假取消。
- 取消失败或未知时 GET 同 Run；终态按真实结果收敛，仍非终态且已核实时恢复手动确认入口。一次 GET 不能证明先前请求不会迟到生效。
- 审批 409 重建当前请求，422 保留选择及实际校验信息，503 遵守 Retry-After；未知结果先查询。原请求仍有效时可人工重新提交，变更则重新选择，已处理则以真实事件为准。其他客户端和自然完成仍可竞争。

### 11. 中止正文与原子结算

- AIContent 新增 generation_status，与正文和 tool_calls 同级，值为 complete、cancelled、error；新消息显式写入，旧缺省按 complete，包括幂等比较。未知值提示协议问题，不猜测正常或中止。
- 取消／失败保存截至结算停止接收时已经接入的所有非空、未提交 AI 正文，保留原 message_id 和预留 seq，按原顺序拼接且不 trim；无正文不造空消息，不等待模型补写剩余回答。
- 已提交用户、Agent 和工具记录不变；不从不完整 delta 造 tool_calls、参数或 reasoning。等待审批、断开观察、切换和隐藏不产生中止保存。
- 同一事务提交中止消息、Run 终态、生命周期和必要审批失效事实；事务成功后再封口与发布，并按原取消协议请求协作停止。取消成功快照意味着正文和终态已共同提交，不保证工具副作用已停止。
- 正常完整消息先成功提交则保留 complete，封存先提交则保留中止；Run 取消／失败竞争服从第一次有效终态。迟到片段、Graph 快照或后续结算不能重复创建、更改原因或覆盖正文；晚到用量仍可结算。
- 回滚保留正文缓冲和可重试结算所有者，不能先清空再宣称成功。纯读 GET 不补写、不重跑模型／工具；不伪造 Graph 正常完成，后续根快照不能把封存身份当新 Run 消息。
- 前端收到完整事实后替换预览、停止光标、显示正文外中止标记。确认终态后补读一次 Run messages，重复通知去重；暂未读到时显示“正在读取已保存内容”，仍不导出预览。失败保留内容并提供手动读取，不改变终态。
- 完整保存的边界是后端已接入正文。强杀前仅在内存的片段不承诺跨进程恢复；已正常保存的消息不因 Run 后来失败而改为中止。

### 12. 完整消息、Markdown、工具与复制

- 保留公开 message_id、thread_id、run_id、seq、完整 content、tool_calls、tool_call_id、name、status、artifact 和实际额外字段，呈现折叠不裁剪事实。
- Agent 字符串使用 Markdown，用户和工具字符串原文。明确 type=text 且 text 为字符串的块按角色展示，额外字段可看完整原 JSON；未知块完整 JSON，数组原顺序，不跨未知对象拼接 Markdown。
- 保留省略、null、空字符串、空数组等区别；空工具正文说明已返回且为空，不改成等待。
- 使用已确认 react-markdown、remark-gfm、rehype-sanitize 组合；原始 HTML 转文本后净化，不启用 raw HTML／MDX／脚本／iframe／表单。任务列表只读，标题与表格沿正文层级，表格区内横向滚动，脚注按消息身份隔离。
- Markdown 图片和链接由受控入口处理，解析阶段保留 Windows 路径，不直接把原路径赋给 href／src。呈现失败保留可复制原文、显示局部错误，不清会话或改 Run。
- 代码沿用单色等宽样式，仅显示真实语言／可识别文件名，不猜测。行号只展示；复制原代码，不含行号、围栏、状态或省略号。长代码／工具／JSON 约 320px 内滚动，完整查看复用只读前景层。
- 字符串复制原文，对象／数组复制完整格式化 JSON，块数组另提供完整原始数组复制。预览仅称“复制当前片段”，复制失败保留手动选择。
- 工具在发起 Agent 消息下按调用顺序呈现，以同会话、同 Run、tool_call_id 唯一匹配结果，保留各自 seq；无唯一调用时独立结果卡片，不猜参数。不同结果名称仍保留核对。
- 尚无结果显示“等待结果”，success 显示“已返回”，error 显示“工具失败”；工具正文中的 Error 字样不改真实 status，也不表示 Run 必然失败。Run 结束无结果仍标等待并说明运行结束，不造工具取消记录。
- 默认折叠；失败首次只展开卡片／结果，参数和 artifact 仍折叠；应用内记用户收起选择，重放不重开，重启重用默认。非 null artifact 包括 0、false、空值均完整只读展示，不自动猜文件或媒体。

### 13. 工作目录与本地图片

| 新增纯读入口 | 返回／行为 |
| --- | --- |
| GET /api/workspace | data 提供 workspace_id、root，目录与文件工具共用 |
| GET /api/workspace/resources/resolve?path=... | data 提供 workspace_id、resource_id、absolute_path、relative_path、name、kind、mime_type、size、modified_at、can_preview |
| GET /api/workspace/resources/{resource_id}/image | 再核实目录、路径和文件版本，返回允许预览的图片二进制 |

- 仅识别 Agent Markdown 的明确图片／本地文件链接，不识别用户、工具、代码或任意 JSON 中裸路径；网页 http／https 链接单独处理，网页图片不自动加载。
- 相对、绝对本地路径和 file URI 统一规范化，实际目标必须在当前绑定 workspace_root 内，指向目录外的链接亦拒绝。根目录装配时解析，与现有文件工具一致，不随进程 cwd 改变。
- resource_id 是当前绑定的 opaque 身份，绑定 workspace_id、启动租约、规范路径、文件版本；后端或目录更换后重新解析。历史引用读取当前磁盘文件，不宣称生成时快照。
- resolve 只接受存在的普通文件，kind 为 file，目录打开首版不支持。mime_type 可未知，文件大小和修改时间取真实事实；只暴露必要目录信息，不暴露完整配置或凭证。
- 查询不创建 Run、不执行 Graph／工具、不修改文件。非法路径 422，目录外／不可读 403，不存在 404，版本变化 409，图片超过 20MiB 为 413，不支持格式 415；资源错误不改 Run。
- JSON 和图片 no-store；图片正确 MIME、nosniff。PNG、JPEG、GIF、WebP、BMP、SVG 自动预览，可进入可视区再读；SVG 只作为 img 源，不插入活动 DOM。
- 通过 BackendSession 获取 Blob 和受控 URL，同租约同资源去重；图片保持比例、正文内宽度、约 320px 聊天最大高度，完整查看与引用／实际路径复制可达。
- 加载／失败贴近图片，保留原引用和重试，必要时仍可准备文件确认。切换、隐藏和租约失效停未完成读取、过滤迟到结果、释放无用 Blob URL，重新显示核实，不抢阅读位置。

### 14. 系统浏览器与文件确认打开

- open_web_url 只接受 http／https，Rust 校验后用系统默认浏览器打开，返回系统已接受或结构化错误；其他协议只读可复制，不让主 WebView 离开会话。
- prepare_workspace_file_open 接受 startupId、原引用 path，宿主使用自己托管的地址核实工作目录／资源，返回 request_id、startup_id、workspace_id、absolute_path、name、mime_type、size、modified_at，此步骤不打开。
- open_prepared_workspace_file 只接受 request_id，再核实租约、目录、路径与版本后打开同一文件。意图绑定 main 窗口，一次性、五分钟过期，关闭确认、宿主失效或使用后不复用，不持久化许可。
- 通过 tauri-plugin-opener 的 open_url／open_path，不拼 shell；关闭自动链接点击脚本，Ctrl／Shift／新窗口目标不能绕过受控入口，不给前端任意路径通用打开权限，不信任调用者 baseUrl 或根目录。
- 每次文件点击包括图片“用系统打开”都重新准备，显示“打开本地文件？”，文件名、完整真实路径、默认程序说明和路径复制；按钮“取消／确认打开”，默认焦点取消，Esc／关闭／遮罩不打开。
- 切换会话、引用变化、隐藏或租约失效关闭确认；路径或版本变更需重新准备及新确认，不静默改目标。发出打开后防重复，失败保留实际原因；成功只表示系统接受，不自动重开、不改 Run。

### 16. 当前运行详情与事件

- 首版详情跟随当前会话当前／最近 Run，不增加历史 Run 切换器。进入定位后自动读一次快照，打开详情刷新快照并读完整事件，两请求可独立并行且分别去重，同目标同类不重叠。
- 已有数据刷新时保留，分区失败不清另一成功区域。工具栏、命令和用量摘要共用详情入口；没有 Run 时禁用并说明，未知／失败不误称未开始。
- 切会话关闭；新 Run 接受后仍打开的详情转新目标、清旧 UI 选择、读取新事实，旧请求失效。打开／关闭详情不新建 SSE、不停止当前观察、不取消 Run。
- 分“运行信息／本次运行用量／事件记录”，展示真实会话／Run ID、中文状态、错误与 code、创建／更新时间／结束时间，ID、完整错误和 UTC 可复制；时间含本地时区，终态缺结束时间说明未取得，不用接收时刻替代。
- 默认事件只显示 lifecycle／approval，开关可包含 message；按 seq ASC，记录中文类别、真实 created_at 与 seq，未知载荷保留完整原文，序号空洞不报丢失。
- required／resolved／invalidated 全由已提交事实解释；当前终态、本地点击或 HTTP 200 不生成审批历史。缺对应事件说明未读到。
- 事件默认折叠、完整 JSON 与复制、约 320px 区内滚动；完整查看复用前景只读子视图，返回保留位置与焦点，不叠模态。JSON 链接／文件／图片不执行，详情不另放审批或直接取消控件。
- 详情打开期间，正常 interrupted／终态 EOF 或取消终态补一次 events；确认前已在读时最多合并一次确认后补读，重复通知不不断排队。关详情停专属事件读取／重试，保留事实，SSE 和摘要继续。
- “处理审批”关详情并定位卡片；“刷新详情”只读快照／事件，“重新连接／核实审批”复用 GET stream；终态可返回会话，不提供含糊的自动重新执行入口。

### 17. 用量与有限结算核实

- 用量为本次 Run 已记录累计值，含审批继续前的部分；显示 total_input、total_output、total_tokens、calls，by_model 用实际键和 input／output／calls，不重算总量、不补模型或缺省零。
- calls 表示模型完成回调的已记录次数，不是工具次数、全部尝试或供应商计费次数；用量不表示上下文占比、会话所有 Run 合计、费用、速度或准确耗时。
- usage=null 显示暂无数据，实际 0 如实显示。usage_pending=true 是仍在结算，false 仅对当前执行阶段有效，省略／未知显示待确认；Run 终态与用量结算分别表达。
- 同 Run 审批继续开启新阶段，保留累计值，撤销旧阶段“已保存”结论；重建无法确认阶段时先待确认。适用新字段更新可淘汰旧查询，按需合并一次新读取，不反复排队。
- 会话栏底部“本次运行用量”显示输入／输出、合计／已记录调用、结算提示和详情入口，数字本地分组、长值可换行，新目标不闪旧值。
- 正常 interrupted／终态观察 EOF 补一次快照；取消快照立即收敛结果，后续读取与已有请求协调。终态消息补读、事件补读与用量确认各自负责，不相互替代。
- 可见、ready、当前目标为 interrupted／终态且已确认 usage_pending=true 时，完成请求后等 5 秒再读快照，一轮最多 12 次后续请求，失败与重试均计入，首次补读不算。running 正常 SSE 不额外轮询。
- 适用 false 立即停；成功但仍 pending 不重置预算。可恢复错误用既有 1／2／5 秒、最多三次及 Retry-After，统一任务；三次失败停止，404／500／协议问题停止，不绕限启动另一轮。
- 达上限保留“仍在结算，自动核实已暂停”，用户“继续核实”可主动读取并开启新受限轮次。关详情不停止摘要核实；隐藏、切换和租约失效停请求及计时器，同阶段重新显示不凭空重置预算。

### 18. 阅读、命令与快捷键

- 应用本次启动首次打开会话定位最新；切回恢复内存中的消息／卡片锚点、偏移和跟随模式，重启仍首次最新。锚点暂未呈现等事实，缺失时用最近存在内容，不串到其他会话。
- 主动上翻停跟随，delta、完整替换、工具变化、图片及宽度变化不抢位置。“回到最新”或主动滚回底部恢复；新增只提示有新内容，不按 delta 数造消息数。
- 本次发送有效接受后可回最新，自动查询、状态、用量和审批事件不独立强制到底。“处理审批”仅用户主动定位。导航、列表、时间线、详情和代码区分别滚动。
- 命令面板约 480px，搜索“操作／已加载会话”，仅本地动作名和显示标题，无服务端搜索／批读历史。新建、导航两态、运行详情、切换共用页面动作与禁用原因；无匹配不默认新建。

- 平台 Cmd／Ctrl+K、N、B 在草稿和普通搜索中可用，分别命令／新建／导航；只处理对应普通组合，IME 与 repeat 不触发。

### 20. 错误反馈与实施依赖

| 情况 | 必须保留的行为 |
| --- | --- |
| 宿主非 ready／失败 | 既有宿主页反馈，旧租约失效，输入和应用内事实保留 |
| GET 网络／503／可恢复 SSE error | 所属读取区反馈，按适用预算 GET 恢复，遵守 Retry-After |
| Thread／Run 404 | 停自动重试，提供列表／重读会话，Run 不可读不删除整个会话 |
| 发送／审批 409 | 保留输入、查询实际 Run 或重建同 Run 审批，不自动写入 |
| 游标 422 | 保留列表，显式重载重新建分页位置 |
| 输入／审批 422 | 保留内容和实际校验信息，不编造具体出错项 |
| GET 400／500、解析失败、不可恢复 error | 停自动重试，保留事实，提供手动读取／连接 |
| POST 503 | 保留内容与提交记录，遵守 Retry-After，仅 GET 核实接受情况和当前事实，不自动重发 |
| POST 500、传输／解析／中止后结果未知 | 保留操作记录，只 GET 核实，不断言未执行、不自动重发 |
| 已确认 Run error | 展示真实运行失败及 code／正文，不与观察错误混用 |
| 资源／复制／导出／系统打开失败 | 内容或操作局部反馈，不改变 Run 终态 |
| 未分类响应 | 保留 status／detail／错误文字，按读取失败或提交待确认处理，不造运行结果 |

HTTP 错误不自动重启宿主，所有 POST 都由用户主动。错误贴近宿主、列表、历史、观察、提交、执行、详情或资源所属区域，保留仍有效事实、草稿和审批选择，避免用短暂 toast 代替恢复说明。

已确认顺序如下，用户可提前实现独立模块：

| 批次 | 任务 | 交付行为与依赖 |
| --- | --- | --- |
| 1 | 会话定位与只读查询 | 分页／历史状态、纯读快照／事件、客户端边界、窗口可见输入 |
| 2 | 运行投影、恢复与输入 | 统一事实／预览／请求身份、有限 GET、持久草稿及原文发送 |
| 3 | 审批、取消与中止消息结算 | 原子保存先支撑取消保存承诺，逐项审批／核实／互斥／竞态 |
| 4 | 完整消息、工具与 Markdown 导出 | 保留完整字段、安全正文、调用结果、完整复制与已提交快照导出 |
| 5 | 工作目录资源与系统打开 | 只读资源与受控桥接先于预览／确认打开 |
| 6 | 运行详情、用量与事件 | 复用查询与投影、分区详情、真实用量与有限结算核实 |
| 7 | 会话浏览、命令、响应式与视觉收尾 | 标题时间、自动分页、锚点、键盘／偏好、四档与原稿比例 |
| 8 | 首版联合验收 | 真实 Windows Tauri 全流程、边界与证据 |

实际依赖是查询边界先于消费者、稳定事实先于审批／详情、原子保存先于保存成功承诺、资源及原生桥接先于资源 UI。各批从开始继承风格；规划 closed 不替代“待实施／实施中／待验收／已验收”。

## Testing Decisions

### 验收边界与好测试的标准

- 主验收边界沿用已经完整确认的真实 Windows Tauri 用户流程：操作页面、读取可见结果、再用公开 HTTP 查询核对持久事实和身份。验证用户能做什么、系统实际提交什么，不约束组件拆分、私有字段或 reducer 的组织。
- 对可控断流、重复、乱序、迟到、请求失效和计时，优先复用现有 BackendSession 的网络／宿主状态输入，以及 Runtime／HTTP／SSE 公开入口和既有临时数据库夹具。需要可控场景时放在这些既有边界，不新增业务组件内部测试钩子。
- 原子保存、回滚和并发以公开运行／消息／事件查询结果为断言。故障注入可沿用现有测试方式，但不把内部调用顺序、私有容器或“某函数调用几次”作为产品完成标准；公开请求次数、工具是否执行及观察是否重跑执行则是有意义的边界行为。
- 真实模型任务和可控夹具分别记录范围。可控案例通过不代替真实模型、原生文件打开、IME、焦点、滚动或下载验收；固定等待后盲判成功不代替可观察状态。
- 本规格安排后续验证，未新增测试代码或运行测试／构建。

### 实机证据与完成标准

- 验收记录场景、必要 thread_id／run_id／startup_id、预期和实际结果、截图／日志位置。每批独立标“待实施／实施中／待验收／已验收”，未执行不能写通过。
- 四档尺寸均指 WebView CSS 内容区，记录实际测量、Windows 显示缩放和截图像素；原生标题栏另记。保留原稿与桌面截图基准，滚动、IME、焦点和系统打开需要实际操作证据。
- 真实模型正常任务、工具审批／拒绝、两种取消、断流／重连、刷新／重开和后台运行路径均需验收；夹具覆盖重放、竞争、写失败与计时，可复查持久结果。

- 实机发现实现缺陷进入对应修正；若需改变已确认产品行为，再开新的决策记录。原生截图不重新成为规格发布前置。
