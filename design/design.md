# Shikigen 桌面工作台设计规范（历史方案）

日期：2026-09-24 · 依据：[PRD](../docs/frontend/frontend-prd.md)、[展开 demo](demo-菜单展开.html)、[收起 demo](demo-菜单折叠.html)

本文件保留早期设计沿革；当前实施请使用 [frontend/design.md](../frontend/design.md)，阶段状态见 [开发交接](../docs/development-handoff.md)。

## 1. 设计定位与优先级

做什么：为单用户 Agent 开发者提供以对话为中心的 Tauri 桌面工作台，覆盖发起任务、观察输出、工具审批和运行排查。

为什么：开发者需要同时看清对话内容、执行事实和需要自己决策的操作。界面应该安静、精确、可追溯，不能把静态原型中的装饰数据变成产品承诺。

如何：Tauri 负责桌面窗口宿主；业务仍消费 PRD 中 FastAPI HTTP/SSE 契约。本次只交付设计规范与图片，不改前后端代码。

优先级：本次用户明确的 Tauri 定位 > PRD 的功能与状态约束 > demo.html 的导航与视觉 > front-end-demo.html 的收起布局。PRD 中“不构成桌面壳选型要求”的描述由本次用户决定补充；不因此将业务通信改成 Rust IPC。

## 2. 从两个 demo 提取的设计语言

| 继承项 | 决策与原因 |
| --- | --- |
| 窗口与顶栏 | 保留 40px 应用栏、品牌、中央连接状态、右侧命令入口；桌面窗口控制按宿主平台呈现 |
| 展开主导航 | 256px，采用新版 demo 的分组与入口顺序；帮助初次使用者识别工作区 |
| 收起主导航 | 64px，仅隐藏文字，保留相同图标、顺序、禁用状态与展开控制 |
| 会话历史 | 独立 256px，导航折叠不影响历史，避免丢失切换会话的路径 |
| 对话 | 双方均左对齐；28px 头像列；用户浅灰容器，Agent 正文直接落在白画布 |
| 内容容器 | 代码、工具与审批是有语义的内嵌区块；不套多层卡片 |
| 输入 | 下方悬浮容器，与消息内容使用同一居中轴与最大宽度 |
| 信息层级 | 紧凑工具栏、宽松正文、低对比结构线；重要决策用清晰文字与实心主按钮 |

美术方向：Pristine Light / 精密工具 / Swiss 网格秩序。遵守任务界面用途，不套用营销页 Hero、摄影背景、价格区或大字标语。四类核心组件为双侧栏、消息时间线、工具/审批内嵌区块、覆盖式详情抽屉。微动效仅用于展开反馈和流式状态。唯一细微视觉标记为选中会话左侧的靛蓝细线，与主导航选中态呼应。

## 3. 视觉 token

| 名称 | 值 | 用途 |
| --- | --- | --- |
| canvas | #FFFFFF | 主画布、弹层 |
| sidebar | #F8FAFC | 双侧栏、用户消息与代码底色 |
| hover | #F1F5F9 | 悬停、次级容器 |
| border | #E2E8F0 | 1px 分隔与边界 |
| text | #0F172A | 正文、标题 |
| secondary | #475569 | 次要正文 |
| muted | #64748B | 辅助说明 |
| accent | #4F46E5 | 发送、提交决策、Agent 头像、焦点 |
| accent-soft | #EEF2FF | 导航选中背景 |
| success | #047857 / #ECFDF5 | 已完成：勾号与文字 |
| warning | #92400E / #FFFBEB | 等待审批：警示图标与文字 |
| danger | #B91C1C / #FEF2F2 | 失败、取消确认中的危险操作 |

- 字体：Geist + Noto Sans SC / PingFang SC / Microsoft YaHei / sans-serif；代码、ID、用量用 JetBrains Mono / monospace。
- 正文 14/24px；会话标题 15/22px、500；角色名 13/20px、500；代码 12/20px；辅助 12/18px。审批说明与决策控件不低于 14px。
- 间距：4、8、12、16、24、32px；消息组间距 24px，头像与正文间距 12px。
- 圆角：控件 6px；消息、代码、审批、输入容器 8px；不采用巨型胶囊和厚重卡片。
- 阴影：选中历史行 0 1px 2px / 黑色 3%；输入区 0 4px 20px / 黑色 6%；抽屉 -8px 0 24px / 黑色 6%。
- 图标：统一 18px 线性风格、约 1.5px 线宽；头像 28px。按钮视觉高度 32px，主要决策 36px；触控布局使用至少 44px 点击目标。
- 焦点：2px 靛蓝外环与 2px 间隔。正文可选中复制；任何状态同时有文字或图标。

## 4. 窗口与布局

设计基准为 1440×900（16:10）逻辑像素。图像生成尺寸可能不同，实施尺寸以本规范为准。

| 区域 | 位置与尺寸 |
| --- | --- |
| 顶部应用栏 | x=0，y=0，高 40，全窗口宽；预留平台原生窗口控制位置 |
| 展开导航 | x=0，y=40，宽 256；内部顶部品牌控制行高 48 |
| 收起导航 | x=0，y=40，宽 64；顶部保留展开按钮 |
| 历史栏 | 展开时 x=256，收起时 x=64；宽 256，y=40 |
| 会话工具栏 | 从主区左边界开始，y=40，高 56；标题与状态左侧、导出与详情右侧 |
| 消息区 | 主区内居中，最大宽 840；横向内边距 12，组间距 24 |
| 输入区 | 与消息区共用最大宽 840，主区左右至少 24，距窗口底部 16 |
| 详情抽屉 | 右侧覆盖式，建议宽 400，y=40 至窗口底部；不改变底层布局尺寸 |

输入区默认约 112px，文本扩展后最多约 240px；时间线底部留白随实际输入高度变化。输入外层透明区域不截获鼠标事件。历史与主时间线分别滚动。

Tauri 外观：图片采用 macOS 桌面窗口控制示意，应用内容充满画布，无浏览器地址栏、设备背景或透视。Windows/Linux 换成对应平台窗口控制，不绘制重复的假红黄绿按钮。标题栏空白区域用于窗口拖动，按钮与输入保持可交互。关闭窗口与取消 Run 是不同操作，不能以关闭观察连接替代取消接口。

响应式继承 PRD：≥1440 默认 256+256；1280–1439 默认 64+256；768–1279 为 64+覆盖历史；<768 为单栏和覆盖菜单。桌面偏好单独保存，窄屏自动收起不覆盖偏好。运行详情在手机采用底部 Sheet；此次图片只覆盖桌面。

## 5. 导航与组件

主导航依次为：会话与对话、工具与技能编排、知识库与向量空间、提示词与评估、运行日志与追踪。仅第一个可用，其他为禁用并提供“暂未支持”说明。底部为当前观察连接、命令面板、禁用的系统设置、本地用户标识。收起态不引入旧 demo 的 Flow Builder 或 Plugins。

历史栏保留新建、本地标题过滤、今天/昨天/更早分组。条目仅显示实际标题、更新时间、已知 Run 状态；选中白底细边框与轻阴影。底部“当前 Run 用量”用键值行表示，不显示进度条或百分比。未知显示“暂无用量数据”。

消息：用户灰底 8px 圆角，Agent 白底无外框。角色与头像明确分开。代码头只有语言、可选的真实文件名和复制；工具头展示工具名与事实状态，展开查看完整参数与结果。只有调用无结果时用“等待结果”，不自行推断“执行中”。

审批：内嵌琥珀色边界与浅色标题带，正文仍白底。展示 namespace、每个动作名称、描述、完整格式化 args、可用决策。长参数区内部滚动并可打开详情。按原序逐项选择批准/拒绝，拒绝时显示原因输入；所有动作完成选择才启用“提交决策”。已提交锁定；取消后失效。

运行详情：覆盖当前主画布右侧；显示状态、可复制 ID、输入/输出/总 token、calls、模型分项及生命周期/审批事件。模型仅在 by_model 有数据时显示。用量未结算标记“仍在结算”；缺失显示等待数据。采用分区键值与细线时间轴，不增加图表与伪造性能指标。

## 6. 状态与主操作

| 状态 | 文案 | 输入 / 操作 |
| --- | --- | --- |
| 尚无 Run | 就绪 | 输入可用；非空才允许发送 |
| running | 运行中 | 输入禁用；取消运行 |
| interrupted | 等待审批 | 输入禁用；定位审批、提交决策、取消运行 |
| completed | 已完成 | 输入恢复；发送下一条 |
| cancelled | 已取消 | 输入恢复；发送下一条 |
| error | 运行失败 | 时间线展示真实错误；输入恢复 |

顶栏独立呈现观察连接：连接中、观察连接已建立、观察连接已关闭、观察连接异常。流结束不能把 Run 自动标为完成；终态连接正常关闭时不显示故障。

已知 run_id 的观察异常提供“重新连接”；重新 GET stream 全量重建，不重发任务。尚未拿到 run_id 时断连显示“执行状态待确认”，不提供会造成重复执行的一键重发。取消前确认：“取消运行？已开始的外部工具操作不保证撤销。”

空会话以简短欢迎语和三条可填入输入框的任务示例引导：解释目录结构、搜索项目文本、总结指定网页。无会话提供新建；列表失败原位重试；过滤无结果可清除。404 返回列表；409 重建已知 Run；422 保留选择并标记问题；503 遵守 Retry-After。

## 7. 动作与 API 边界

| 做什么 | 为什么 | API / 数据依据 |
| --- | --- | --- |
| 读取/新建会话 | 持久组织对话 | GET / POST `/api/threads` |
| 切换会话 | 重建已提交消息 | GET `/api/threads/{thread_id}/messages` |
| 发送文本 | 启动一次 Run | POST `/api/threads/{thread_id}/stream`；fetch 消费 SSE |
| 重新观察 | 恢复已知运行事实 | GET `/api/threads/{thread_id}/runs/{run_id}/stream` |
| 提交审批 | 同一 Run 继续执行 | POST `/api/threads/{thread_id}/runs/{run_id}/approval-decisions` |
| 取消 | 明确终止运行 | POST `/api/threads/{thread_id}/runs/{run_id}/cancel` |
| 用量与事件 | 显示实际运行事实 | SSE metadata / lifecycle / approval |
| 折叠、过滤、命令面板 | 本地浏览与布局 | 前端状态；折叠偏好持久化，无额外 HTTP |
| 导出 | 保存已加载的已提交内容 | 本地 Markdown 文件导出；标注导出范围 |

删除原型中的：模型切换、联网/深度思考开关、reasoning、附件与语音、共享、清空上下文、点赞、重新生成、编辑标题、单消息耗时、tokens/sec、上下文百分比、虚构版本与引擎延迟。不可用功能不出现为能点击的主操作。

## 9. 交互验收

- 折叠不重载、不清空草稿、不丢审批选择、不停止 SSE；快捷键提示按宿主使用 Cmd/Ctrl。
- Enter 发送、Shift+Enter 换行；中文输入法组合期间不发送；所有 pending 操作防重复提交。
- 用户上翻时不强制滚到底部；提供回到最新消息入口；输入区不遮审批按钮或最后一条消息。
- 详情和命令面板有 Esc 关闭、焦点锁与返回焦点；关闭不取消 Run。
- 流式动画与展开过渡约 120–180ms，遵守 reduced-motion；终态停止进度动画。
- 状态有文本，正文/操作满足 AA 对比度，长 JSON/代码只在区块内横向滚动。
- 1440×900、1280×800、1024×768、390×844 按 PRD 验证布局；生成图片不替代实际响应式和可访问性测试。
