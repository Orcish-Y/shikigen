# Resolution：验证后端托管与数据独占的底层机制

日期：2026-09-28。状态：文档与源码调查完成。

调查资产：[Windows 后端托管与运行数据独占：机制调查](../../../research/windows-backend-lifecycle-mechanisms.md)。报告包含本地版本、一手来源、建议调用顺序、失败边界及待实施验收场景。

## 回答

- Windows 10 起可在创建进程时指定 Job，避免先创建再加入 Job 之间的宿主崩溃窗口。进程与 Job 句柄、标准流端点均需由平台实现管理；主进程退出不能代替整棵所属进程树的回收确认。
- 本地 Uvicorn 0.52.1 支持接收 Python 已绑定的 socket；绑定成功与就绪是两个阶段。Windows 应核实独占选项，并区分端口冲突、候选不可绑定及其他错误。
- stdin 控制监听需在初始化前建立。取消 Uvicorn serve 不保证独立 lifespan 任务退出；退出控制器必须明确持有初始化与资源清理责任，协调 runtime shutdown 和 SSE 收尾。
- 运行数据独占可使用原生文件锁。报告给出固定版本的 Portalocker 候选及 Windows / POSIX 后端依据；锁集合必须覆盖聊天库和持久 checkpoint 的实际资源，取得锁先于数据库初始化，释放晚于存储关闭。
- 公共接口必须区分退出请求已发送、主进程退出和所属进程全部回收，明确确认失败时禁止重试。操作系统机制不能被表述为任意负载下的固定毫秒回收保证。
