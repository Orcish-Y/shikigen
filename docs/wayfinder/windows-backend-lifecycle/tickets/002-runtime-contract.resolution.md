# Resolution：确定 Windows 后端托管接口与状态转换

状态：已确认的接口契约。讨论过程见[讨论记录](002-runtime-contract.discussion.md)，底层依据见[机制调查](../../../research/windows-backend-lifecycle-mechanisms.md)。本文件汇总最终约定，覆盖早期草案中固定端口、关窗即退出等已被修订的行为。

## 1. 职责与平台接口

| 模块 | 职责 |
| --- | --- |
| React 的统一 HTTP/SSE 客户端 | 使用本次就绪地址，消费状态快照，清理旧连接并过滤迟到响应 |
| Rust `BackendManager` | 串行协调启动、状态、协议、就绪检查、超时、手动重试和退出 |
| Rust 平台进程适配层 | 创建受托管进程、连接管道、观察退出、回收所属进程并确认结果 |
| Python 桌面启动器 | 控制监听、端口绑定、持有 runtime 上下文、运行 HTTP 服务、协调内部清理 |
| 共享 `open_runtime()` | 数据独占、初始化与恢复、runtime 装配及资源上下文退出 |

平台进程接口为 `spawn(spec)`、标准流访问、`wait_exit()`、`terminate_tree()`、`wait_tree_empty()`。`spec` 描述可执行文件、参数、工作目录和环境变量；`spawn` 只返回完整托管实例，部分失败由适配器清理。

主进程退出与全部所属进程退出是不同结果。强制终止请求返回不等于回收完成。等待确认失败或超时后仍保留观察能力。

Windows 第一版要求 Windows 10 或更新版本。每次创建独立、非继承的 Job，启用 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，由宿主持有；使用 `CreateProcessW` 的 `PROC_THREAD_ATTRIBUTE_JOB_LIST` 在创建时完成归属。Job 不允许子进程继承其句柄，也不开放 breakaway。标准流通过句柄白名单继承，关闭宿主持有的子端副本；注意报告所述并发继承限制。

未来 macOS 替换进程适配实现及相应路径、数据锁实现；公共状态、命令、协议和 Python 生命周期不变。宿主异常退出后的所属进程回收是必须独立验证的接口能力。macOS 实现不在本轮范围。

## 2. 开发态启动与配置

- 从 `env!("CARGO_MANIFEST_DIR")` 所在 `frontend/src-tauri` 向上两级定位项目根目录，生成绝对路径；检查 `pyproject.toml`、`config.json` 和 Python 可执行文件。
- Windows 直接启动根目录 `.venv\Scripts\python.exe`，cwd 为项目根目录。依赖由开发者预先 `uv sync`；缺环境或依赖时显示错误与准备说明，不静默选择系统 Python。
- 路径失效时报错；项目移动后重新构建。安装包路径与 Python 分发另行设计。
- 通过参数列表传递 `--config <绝对路径>`、`--startup-id <本次唯一标识>`、`--port <本次起始端口>`，不拼接 shell 命令。具体 Python 模块名称留给实现确定。
- Python 在加载配置前显式加载根目录 `.env`，使用 `python-dotenv` 且 `override=False`。文件缺失可继续；必要变量缺失时报变量名，不输出密钥值。Rust 不负责加载模型密钥。
- 托管 Uvicorn 关闭 reload；Python 修改后通过托盘退出并重新打开应用生效。

`config.json` 的 `backend` 分组：

| 字段 | 默认值 | 校验 |
| --- | --- | --- |
| `port` | 43127 | 1～65535 的整数 |
| `startup_timeout_seconds` | 60 | 大于 0 的有限数值 |
| `shutdown_timeout_seconds` | 10 | 大于 0 的有限数值 |

分组或字段缺省使用默认值；拒绝未知字段、显式 null、布尔值、数字字符串。错误指出字段与原因，不静默回退。Python `AppConfig` 和 Rust 托管配置解析采用同一规则。

每次启动或重试重新读取配置，运行中不热重载。Rust 固定本次 `backend` 配置，并以 `--port` 传递起始端口；本次退出期限也沿用该快照。Python 其他应用配置仍从指定文件读取，不宣称整个文件具有跨进程原子快照。

## 3. 绑定与就绪

Python 实际绑定 IPv4 `127.0.0.1`，从本次起始端口递增。Windows 设置 `SO_EXCLUSIVEADDRUSE`；占用错误继续递增，10013 记录原始原因后跳过该候选，其他绑定错误立即失败。尝试至 65535 或启动期限耗尽即失败，不回绕、不重新计时，不接管外部服务。

成功后保留原 socket，交给 `Uvicorn Server.serve(sockets=[socket])`，不关闭再绑定。统一地址为 `http://127.0.0.1:<实际端口>`。

Python 启动器在耗时初始化前建立 stdin 监听，持有 `open_runtime()` 上下文并将 runtime 提供给 HTTP 应用；托管 HTTP lifespan 不重复创建 runtime。

收到 `bound` 后 Rust 立即开始探测 `GET /health/ready`。就绪需要 runtime 初始化和历史状态恢复完成、HTTP 可访问，响应为 HTTP 200 且包含 `version: 1`、匹配的 `startup_id`、`status: "ready"`。不在启动时额外调用模型生成内容。

未就绪时每隔 250 毫秒再试，单次请求最多 1 秒，不并发探测，也不能越过启动总期限。连接失败、HTTP 503 可继续等待；标识不符、版本不兼容或响应格式错误立即失败并清理本次托管进程。只有通过检查后才向页面提供地址。

## 4. 进程控制协议

stdin 接收控制消息；stdout 输出结构化消息；stderr 输出普通日志及堆栈。托管入口须避免普通输出污染 stdout。

消息为 UTF-8 逐行 JSON，逐条以换行结束，每条最多 64 KiB。读取时即限制缓冲，不能等换行后才检查。共同字段是数值 `version: 1`、本次字符串 `startup_id` 和字符串 `type`。

| 方向 | `type` | 附加字段 |
| --- | --- | --- |
| Rust → Python | `shutdown` | 无 |
| Python → Rust | `bound` | 实际整数 `port` |
| Python → Rust | `startup_error` | 字符串 `code`、`message` |

`bound` 不是 ready；退出结果以平台观察为准，不依赖自报完成。标识用于识别启动，不等同认证。

版本不兼容、损坏、缺必要字段或超长的当前消息导致协议错误和清理。Python 收到无效控制命令后记录 stderr 并退出清理。能够识别为旧启动的消息忽略；无法解析的消息不能以可能属于旧启动为由放过。

仅桌面托管模式下 stdin EOF 触发清理退出；独立 CLI、手动 HTTP 不采用此规则。卡住时仍由宿主超时及平台机制兜底。

## 5. 退出和回收

正常清理顺序：

1. 停止接收新任务，通知 Uvicorn 停止服务。
2. 立即开始 `runtime.lifecycle.shutdown()`，结束执行，使 SSE 能收尾；不等待 SSE 全部断开后才开始 runtime 清理。
3. 等请求和执行清理完成，再退出 runtime 上下文、关闭存储，最后释放数据锁。

初始化中收到退出也要取消初始化并清理已打开资源，不要求 runtime 已装配完成。正常清理由 Rust 统一计时，不为每步重新计时，不等待 Agent 自然执行完成。

| 情形 | 处理 |
| --- | --- |
| 显式退出，主进程仍在 | 发 `shutdown`；正常清理期限耗尽则强制回收 |
| 启动总期限耗尽 | 停止探测，保留启动超时原因；先正常清理，再按需强制回收 |
| 主进程意外退出 | 无需再等正常清理期限；立即检查并强制回收残留所属进程 |
| 宿主异常终止 | Windows 依赖 Job 的 kill-on-close 回收所属进程 |

强制回收确认固定最多 5 秒。Windows 使用 `TerminateJobObject`，保留 Job 句柄，通过 `QueryInformationJobObject` 查询活动进程是否为零；主进程退出及所属进程全部回收后才开放重试。

超时或查询失败时显示“无法确认后端已完全退出”，禁止重试，继续观察。显式退出时保留错误窗口，后续确认完成才自动退出应用；非退出情形下确认完成后开放手动重试，不自动启动。

默认启动超时路径的等待预算约为 60 + 10 + 5 秒，之后显示已回收或回收未确认的失败结果；该预算不是系统保证进程一定在此时间内退出。

## 6. 页面命令、状态与重试

统一状态快照：

| 字段 | 语义 |
| --- | --- |
| `state` | `starting` / `ready` / `stopping` / `reclaiming` / `failed` / `stopped` |
| `revision` | 同一次宿主运行期间递增的版本号，后端重试不归零 |
| `startup_id` | 本次标识，尚未启动时为空 |
| `base_url` | 仅 ready 时有值，其他状态为空 |
| `can_retry` | 管理器计算的当前重试能力 |
| `error` | 错误代码与可读说明，无错误时为空 |

`get_backend_state` 返回快照，`backend-state-changed` 推送相同结构。页面先完成订阅再查询，初次接收后仅接受更新 revision。刷新页面不启动后端。

`retry_backend` 立即返回 `accepted`、拒绝原因 `reason`、当前 `snapshot`，不等待就绪。接受时串行进入 starting、生成新标识，后续走事件。重复点击不创建新进程；页面缓存的 can_retry 不能替代 Rust 再次校验。

| 起点或事件 | 后续状态及约束 |
| --- | --- |
| 接受启动或重试 | starting，新启动标识，不可重试 |
| 本次健康检查通过且未退出 | ready，提供地址 |
| 发起正常清理 | stopping，撤销地址，不可重试 |
| 开始强制回收 | reclaiming，不可重试 |
| 启动或运行故障，清理完成 | failed，保留原始错误，未退出应用时可重试 |
| 无资源需要清理的启动失败 | 可直接 failed，无需虚构清理阶段 |
| 回收未确认 | failed，不可重试，继续观察 |
| 显式退出且确认回收完成 | stopped，随后退出应用，不可重试 |

退出意图优先于迟到 ready，旧启动不能改变新启动状态。关闭窗口仅隐藏时不设置退出意图。故障清理完成不以 stopped 覆盖错误原因。

离开 ready 清除地址并停止新请求；重试成功后统一客户端使用新地址，重取 Thread、消息和 Run 状态，清理旧连接并忽略旧启动迟到响应。不自动重发消息或重新执行失败任务。

Rust 持续消费 stderr，内存只保留最近 1 MiB。`get_backend_logs` 返回带 startup_id 的日志快照，错误页按需查看；重试清空旧日志，隔离迟到输出，应用退出后不保存。日志读取失败不阻碍回收。

## 7. 单实例、托盘与窗口

使用 Tauri Single Instance 插件，先检查单实例再启动后端。第二次启动只通知已有实例恢复并聚焦窗口，随后退出；已有后端启动中或失败时只展示状态，不自动重试。已有实例退出中则继续退出，不取消退出、不创建后端。

托盘左键恢复并聚焦窗口，右键提供“打开主窗口”“退出应用”。正常关窗隐藏到托盘，后端和 Agent 继续。托盘创建失败则保留窗口并显示原因，此时关窗走正常退出。

应用隐藏时发生生命周期故障，恢复窗口并展示错误及重试能力；同一次故障只触发一次，不因清理进展反复抢焦点。用户可再次隐藏。单个 Agent 任务失败沿用任务页面，不触发该行为。

## 8. 运行数据独占

共享 `open_runtime()` 在初始化、恢复前，对聊天库及 SQLite checkpoint 的实际文件分别非阻塞加独占锁；相同文件去重，内存 checkpoint 不加持久锁。固定顺序取得全部锁；任一失败释放本次已得锁并报数据正在使用，不影响既有 runtime。

锁持有到数据库连接关闭后；桌面、手动 HTTP 和 CLI 均遵守。锁是 runtime 的数据所有权锁，同一应用内多个 Thread 共用，不对每条消息重新加锁。

使用稳定旁路文件，例如 `chat.db.lock`，不以文件存在或 PID 作为占用权威。解锁关闭但不删除；异常退出交由系统释放，仍需实际取锁成功才能启动。不得将锁句柄泄漏给工具子进程。

第一版只支持本机普通路径。相对路径转绝对路径并统一资源身份；硬链接、符号链接、目录联接和网络共享不受支持，检测到则明确报错。父目录链接及路径别名也须纳入平台检查，不能仅凭绝对路径字符串实现去重。

锁接口封装 Portalocker 3.2.0；Windows 显式使用 `Win32Locker` 和 pywin32，不修改全局后端。未来 macOS 使用对应 flock 实现；升级依赖复核接口，两个平台分别验收。

## 9. 实现验收清单

以下是未来实现的验收要求，本轮未执行行为测试：

- 默认与自定义端口、连续占用、10013、端口耗尽、绑定后不重绑、仅回环监听。
- 缺配置字段、非法类型、虚拟环境缺失、带空格路径、不同启动 cwd、配置修改后重试、启动中改配置不改变本次期限。
- 同时重复打开、启动中重复打开、退出中重复打开均无第二份后端；关窗后台任务继续，托盘能恢复与退出，托盘失败不导致应用失联。
- 初始化各阶段收到 shutdown/EOF；保持 SSE 时正常退出；初始化卡住时宿主仍按期限回收。
- 杀死 Python 后清理后代；杀死 Tauri 后清理所属进程；不终止外部独立服务；部分创建失败不遗留半托管进程或句柄。
- 连点重试、重试与退出竞争、迟到 ready、事件与查询交错、旧请求迟到均不破坏新状态。
- 同库及仅部分库重叠的独立入口不能同时启动；不同 Thread 正常工作；部分取锁失败回滚，残留无锁文件可重用，数据连接关闭后才解锁。
- 无效消息、超长无换行输出、stderr 洪泛不能导致无限缓存或退出阻塞；错误窗口保留原因，日志与启动标识匹配。
- 回收确认失败时禁止重试，继续观察；后续确认完成按退出意图完成退出或开放重试。

实现文件名、Rust 具体类型、错误代码命名和任务组织由实现者按本契约确定；不得因此改变已确认的产品行为。安装依赖、代码实现、Windows 故障注入与 macOS 验证不属于本轮完成内容。
