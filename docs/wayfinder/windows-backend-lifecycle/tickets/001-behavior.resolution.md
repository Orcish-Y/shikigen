# Resolution：确定平台、生命周期归属与故障行为

2026-09-25 补录此前对话。来源：用户对 Q1、Q3 推荐的确认，Q4 明确先适配 Windows，Q5 同意手动重试，以及对 Q6—Q8 推荐的整体确认。未重新认领或重新解决此票据。

| 场景 | 已确认的行为 |
| --- | --- |
| 平台 | 第一版先适配 Windows；macOS 后续接入 |
| 启动入口 | Tauri 桌面应用，由 Rust 壳启动本次应用拥有的后端 |
| 后端初始化中 | 窗口先打开并显示启动状态，服务就绪后开放操作 |
| 初始化失败或超时 | 显示原因，允许手动重试 |
| 端口被其他服务占用 | 2026-09-26 用户修订了原“占用时报错”的决定；现行行为见[托管接口讨论记录：端口选择](../../../archive/README.md#windows-历史与验收) |
| 后端运行中崩溃 | 显示错误，允许手动重试，不自动重启 |
| 关闭窗口与退出应用 | 2026-09-26 用户修订了原“关窗即退出”的决定；现行行为见[托管接口讨论记录：单实例与托盘驻留](../../../archive/README.md#windows-历史与验收) |
| 桌面宿主崩溃或被强杀 | 回收后端及其所属子进程，允许短暂回收延迟 |
| 后端启动 MCP 或命令行子进程 | 纳入本次应用的回收范围 |
| 外部独立运行的服务 | 不受本次应用退出影响 |

Windows Job Object 是已讨论的回收方向；句柄归属、创建顺序、具体 Rust API 和关闭通道仍需设计验证，不视为已经实现或验证。
