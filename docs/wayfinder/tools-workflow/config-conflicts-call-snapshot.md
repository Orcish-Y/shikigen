## 保存与提交点

工具库只改写实际加载的原始配置中的 `tool_library`，其余分组、相对路径和环境引用保持原表达。应用内的读写和源码清理由同一把锁协调；外部编辑器不参与这把锁，应先完成外部保存，再刷新页面编辑。没有后台文件监视，也不保证与外部并发写入互斥；请求结果和草稿不跨重启恢复。

Python 保存先写入并关闭新的生成文件，随后在配置所在目录写完并关闭完整配置临时文件，再核对读取版本，最后用 `os.replace` 替换配置。配置替换成功就是提交点。写代码、准备临时配置或替换前失败，不改变旧配置引用和旧代码；未提交的新文件可能残留，后续成功保存时清理。这个顺序不是多文件事务，也不提供断电恢复保证。

提交后重新读取当前配置，只清理 `config/tools` 内符合系统生成名称且当前未引用的文件。用户命名的示例文件、目录外路径和符号链接不被删除。无法确认当前引用时停止清理；文件占用、无权限或目录枚举等清理失败只记录后端日志，不影响已提交结果。

2026-10-23 用户后续决定取消清理警告响应，改由后端后续处理。创建始终返回 201 和 `data.id`，更新／删除成功始终返回空 204，不再有保存清理 `warnings` 字段或前端提示。配置写入、校验和版本冲突等提交前错误继续正常返回；成功后详情读取失败只重读详情。

每次配置提交以及后端启动时重新扫描残留文件，覆盖工具、连接和批次写入；每次清理都重新核对当前配置引用。失败文件留在原目录，后续操作或下次启动再试，不维护失败队列、缓存或定时任务。持续占用或权限问题会使旧文件暂时残留，不影响已保存工具使用。

明确拒绝时保留草稿；收到成功响应后读取失败只重读详情；响应丢失或未知时保留草稿、显示结果不确定并锁定重复提交。恢复需要明确放弃草稿并重读，重读不证明前一次写入成功。不新增确认请求头、确认接口、缓存或自动重试。

## 版本与外部修改

读取版本覆盖原始配置字节和所有已引用 Python 文件的内容指纹；坏文件也参与版本变化，但列表仍可提供定义，详情和执行定位具体错误。版本覆盖整个工具库，修改无关分组或其他代码同样会造成旧编辑版本冲突。

工具与连接的更新、删除携带读取版本，提交前再次核对。冲突返回 409／`version_conflict`，管理错误中的 `resource_ids` 标识相关工具、连接或操作；草稿没有提交。MCP 应用使用服务端 `discovery_id` 已绑定的版本，客户端不能改写；OpenAPI 预览返回 `version`，整批导入必须提交该版本。名称、来源、类型编辑权限、schema、HTTP 映射均在整批提交前校验，后项错误不保存前项。

列表／详情、手动刷新、保存和已保存调用都读取磁盘。未编辑详情刷新后自动重读，脏草稿检测到变化后保留内容、标记冲突并禁止直接保存。工具提供“放弃草稿并重读工具详情”，连接提供对应入口；重新读取失败仍保留草稿。OpenAPI 冲突保留选择与配置，明确重新解析后取得新版本。没有静默合并或覆盖。

配置缺失、损坏或工具库无法解析时明确报错，不执行旧缓存。Python 文件缺失、不可读或路径非法时返回工具名称／ID；不执行空代码。源码接口不兼容时拒绝已保存调用，详情仍可读取源码，以便重新解析、补齐和保存。仅函数体兼容变化可直接用于下一次调用。

## 本次调用内容

每次已保存调用在一次协调读取中取得最新定义、关联连接、直接认证值和完整源码，然后交给执行器。正在读取的源码完成前，保存清理不能删除该路径；读取者取消也等待文件读取收尾再释放协调锁。

取得后不再回读持久文件：HTTP 使用已取得的地址／认证，MCP 使用已取得的连接设置，Python 在独立临时目录运行源码副本。此时修改、禁用或删除只影响下一次调用；主动取消仍走独立取消操作。工具库变更不重启后端、不自动重装当前聊天 Agent，其他配置继续使用既有生效方式。
