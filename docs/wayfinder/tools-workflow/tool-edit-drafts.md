保存请求和随后读取详情分别处理：保存明确失败时保留草稿；保存响应丢失时提示“保存结果不确定”，锁定再次提交，不推断成功，也不自动重试。用户可明确放弃草稿并重读工具库，读取失败时保留草稿，成功时恢复浏览但此前保存结果仍不确定。已收到保存成功响应而详情读取失败时，明确显示“工具已保存，详情读取失败”，保留工具 ID 和页面内容，只提供重读，不重复创建／更新，也不把读取错误归为保存失败。取得最新详情和版本前锁定编辑、保存和测试。保存并离开的情况下可重读后继续原离开操作，也可直接离开已保存的工具。此规则于 2026-10-15 按用户决定简化，不再使用保存确认接口。

## MCP 普通编辑与发现更新的接入规则

2026-10-14 用户复核指出：将 MCP 普通编辑的只读限制放进通用定义校验，会阻止未来合法的发现更新。已把该限制拆到 `ToolLibrary._check_tool_edit_permissions`，由普通保存 `save_tool` 和草稿测试 `start_draft_test` 显式调用。`_prepare_tool` 负责名称、类型、schema、专属配置校验以及系统 ID／时间处理，保留省略的 MCP 来源字段；它不决定某次操作是否有权更新来源 schema。MCP 发现应用入口尚未实现，由 ticket 07／09 接入。

后续接入遵循以下规则：

- 普通编辑和草稿测试继续调用编辑权限检查，拒绝改写 `server_id`、`remote_name`、`input_schema` 和 `output_schema`；省略或提交原值允许，本地名称、说明、启用和超时可以编辑。
- 发现应用提供独立的后端业务入口，根据实际发现结果和用户勾选核对来源及读取版本，再复用 `_prepare_tool` 准备定义，最后复用 `_commit` 提交配置。不能通过普通编辑请求中的标志绕过权限，也不能直接调用 `save_tool` 更新已有工具的来源 schema。
- 以 `(server_id, remote_name)` 匹配原工具；同来源更新保留 ID、创建时间及本地页面名称、调用名称、说明、启用和超时，只应用已选来源结构变化。不同连接或远端名称作为新来源处理，不把原 ID 改指向另一项工具。
- MCP 所选工具整批校验名称、来源身份、schema 和版本，全部通过后只提交一次。不能循环调用单工具 `save_tool` 代替批量应用，否则中途失败可能只保存一部分。发现失败、本次未发现和未选择项仍按 ticket 09 保留。
- ticket 07／09 的公开接口回归必须同时验证“普通编辑和草稿测试不能修改来源 schema”与“合法发现更新可以修改来源 schema，保留原 ID 和本地信息”，并覆盖整批失败不部分提交。

本次新增公开接口回归验证普通保存／草稿测试的四项来源字段限制、伪造发现标志被拒、本地字段可改、省略来源字段保留以及草稿不保存。拆分后工具 API 26 项回归、Ruff 和类型检查通过。未来发现更新成功路径需由 ticket 07／09 的实际接口验证。
