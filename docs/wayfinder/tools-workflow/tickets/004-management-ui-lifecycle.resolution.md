## 导航与页面

```text
扩展
├─ 工具        MCP、可执行代码（Python）、网络请求（HTTP）
```

页面沿用[前端设计规范](../../../../frontend/design.md)的全局应用栏、主导航、紧凑列表、表单与反馈样式。后续 ticket 涉及工具页时，开发与验收先读取[工具页面原型与参照规则](../../../../frontend/design.md#工具页面原型)。会话历史只在聊天工作区显示。窄屏沿用现有导航与模态交互，不把长代码编辑压入聊天详情抽屉。

## 组件库与动态表单：规格发布后补充

用户在 to-spec 发布后明确确定使用 shadcn/ui、rjsf（react-jsonschema-form）、AI Elements，并强调工具表单使用 rjsf 动态渲染 schema。这项选型纳入页面实现规则，既有数据、执行、编辑权限和保存契约继续有效。

- shadcn/ui 提供基础控件与统一样式。rjsf 用对应管理 schema 渲染公共和类型专属配置，手动测试则直接用当前有效 input_schema 渲染实际参数表单。表单主题与 shadcn 一致，专属预览、类型补齐、凭据等可用定制字段或 widget 组合。
- 管理表单 schema 描述工具配置，input_schema 描述工具业务参数；uiSchema 只控制展示，不另建业务输入定义。编辑 input_schema 本身仍使用已确认的参数表格、Python 解析预览和高级 JSON 编辑。
- Python 源码确定的参数属性与 MCP 来源结构保持只读，测试时参数实际值仍可填写。未知 Python 类型补齐后才形成可测试 schema。
- 动态参数表单与 JSON 编辑共用同一 inputs，保持嵌套与实际类型，区分缺失、空字符串、false、0、空容器和 null。适配 rjsf 的默认值等行为，不自动填业务默认值、示例、布尔或数组占位，不自动转换或删字段。前端校验用于反馈，后端校验决定执行；format 仍按执行决议处理。控件不能准确表达的受支持结构保留完整 schema，使用高级 JSON 入口并显示原因。
- AI Elements 中适用的组件展示工具输入、输出和状态；保持本项目四种 status、完整 data/error/details、真实类型及凭据遮盖。沿用现有通信与执行事实，组件选型不改变后端协议。

官方依据见 [rjsf 动态表单](https://rjsf-team.github.io/react-jsonschema-form/docs/)、[rjsf shadcn 主题](https://rjsf-team.github.io/react-jsonschema-form/docs/usage/themes/)、[rjsf 默认值行为](https://rjsf-team.github.io/react-jsonschema-form/docs/api-reference/form-props/)及 [AI Elements Tool](https://elements.ai-sdk.dev/components/tool)。依赖和主题接入仍属于后续开发，未在规划阶段安装。

## 编辑权限与参数结构

工具类型在创建后固定；改类型需创建新工具。系统 ID 与时间字段只读。公共可编辑信息、类型专属配置和字段校验依照上述关联决议执行，后端同样检查权限与一致性。

简单表格与高级编辑读写同一份 input_schema，不维护第二份参数定义。表格只编辑能准确表达的字段；复杂结构展示摘要并进入高级编辑。更新某个表格字段时保留其余说明、示例和约束，不从简化表格重建并覆盖完整 schema。不能无损表达的内容不允许直接在表格改类型。高级 JSON 无效时保留原文和定位错误，阻止测试/保存，不以空结构替代。

| 类型 | 输入结构编辑规则 | 输出结构规则 |
| --- | --- | --- |
| Python | 源码解析确定的属性只读，未知类型下拉补齐；复杂结构和补充信息用高级 schema。具体同步规则见下节。 | 可选，高级 JSON 编辑；描述业务 data，不做输出转换。 |
| HTTP | 保留 path/query/headers/body 分组；表格与高级编辑均须与地址占位符、参数映射及序列化规则一致。 | 可选，高级 JSON 编辑；导入预填及仅作参考的规则保持不变。 |
| MCP | 远端工具名、所属连接、输入及来源输出 schema 只读；本地名称、说明、启用和超时等按既定规则编辑。 | 来源提供时只读；没有时显示未声明结构。 |

没有输出 schema 时显示“未声明输出结构”，不要求补齐，也不自动从一次测试结果写回。真实测试 data 仍按其实际结构展示。

## Python 参数预览与同步

入口固定为唯一顶层同步 main，页面提供 main 模板与代码编辑，不提供入口名称选择。参数来源、支持的签名和类型范围沿用执行决议，不执行/import 用户代码来生成表单。

- 源码确定的参数名称、类型、必填性和默认值只读预览。默认表达式仅作展示和判断可省略性，不自动注入测试输入或求值执行。
- 未识别的类型显示“待补”，通过下拉选择字符串、整数、数字、布尔、对象、数组等 JSON 类型；形成有效输入结构后才能测试/保存。
- 高级 schema 可以补说明、示例、约束、未明确的容器内部结构及 **kwargs 业务字段。源码已确定的名称、类型和必填性不能通过高级编辑改写；允许 null 的补充同样遵循源码已明确的类型。
- 类型补充不修改源码，不自动把 JSON 值构造成自定义 Python 类。
- 源码修改后自动静态解析，保存/测试前再次核对当前源码。解析失败时保留代码和补充内容，显示诊断，不继续使用未核实的旧参数执行。
- 同名且类型兼容的参数保留原有补充信息；同名且仍无可识别注解的参数保留已经选择的类型。新增参数按新源码生成，未知类型待补。
- 参数删除、改名、类型不兼容或必填性变化明确展示。改名按删除旧参数和新增参数处理，不猜测迁移关系。源码出现明确注解时以源码为准，冲突提示重新补齐，不静默保留不兼容结构。
- 最终 input_schema 仍是唯一保存的输入定义；解析结果和编辑中的诊断用于核对，不另外保存一套独立参数配置。

## 草稿、启用与手动测试

保存是显式操作。测试可以真实执行当前草稿，但不会自动保存；未来工作流与 Agent 使用已保存定义。工具草稿只留在当前页面内存，首版不跨重启恢复，不将填写的密钥保存到浏览器本地存储。

离开有修改的编辑页提供“保存并离开／放弃修改／继续编辑”。保存失败保留草稿。MCP 连接编辑和导入预览中的未保存修改遵循相同原则。

新工具默认启用。禁用工具不能被消费者选择调用，用户仍能显式手动测试。手动测试与正常调用共用执行和输入校验机制，测试入口单独表达用户的测试意图，不让正常 execute_tool 绕过启用检查。

测试区按当前有效 input_schema 用 rjsf 动态渲染实际 inputs，保留高级 JSON 编辑与参数说明；两种入口使用同一参数对象。展示状态、耗时、真实 data、错误和类型专属详情，提供完整查看与复制；结构化数据不预先转成不可取字段的字符串。敏感值及凭据编辑沿用执行决议的隐藏规则。

同一编辑页一次运行一个测试，运行中锁定编辑与保存，提供取消入口。切换页面或关闭编辑页时提供“取消测试并离开／继续测试”；处理测试之后再处理未保存草稿，不让确认离开静默丢失编辑。取消的执行清理及远端限制沿用执行决议。

测试结束恢复编辑。之后修改代码、参数或连接等配置，旧结果标为“修改前的测试结果”。只保留当前工具页面内存中的最近结果；列表能够使用这些真实结果和时间，不写入配置、不建立历史库。无记录时显示“未测试”，不自动探测，不把启用或一次成功显示成持续在线。首版没有后台测试列表或重启恢复。

## MCP 保存、发现和更新

连接配置格式、必填项及类型合法即可保存，连接暂时失败不阻止保存。测试连接、工具发现、工具真实调用分别操作；保存或发现不自动调用业务工具。发现失败保留已保存工具及结构，不用空结果覆盖。

重新发现先预览，再由用户选择添加或应用更新：

- 新来源创建工具；同一来源重新发现保留原工具 ID。
- 更新已选来源结构时，保留本地页面名称、调用名称、说明、启用状态和超时，只更新选中的远端输入/输出等来源结构。
- 已入库且本次未发现的工具保留，并在本次预览提示“本次未发现”；不自动删除或禁用，实际调用仍以执行结果为准。
- 未选中的变更不写入；同一来源不重复创建工具，名称冲突等诊断在提交前明确显示。

MCP 工具的所属连接和远端工具身份只读。换到另一个连接需重新发现并创建工具。连接自身的命令、地址、凭据等可以编辑并保留连接 ID；保存后提示重新发现核对结构，不静默覆盖已入库参数。远端改名也不猜测为原工具改名。

## 保存、文件与生效

沿用执行决议指定的项目 config.json、tool_library、独立 MCP 连接及相对 code_path。保存基于原始 JSON 更新工具库分组，保留其他配置及环境引用；不回写已展开密钥或绝对路径化的运行配置。

保存操作先校验整批定义、名称、来源身份、schema 与专属映射。MCP 勾选入库和 OpenAPI 所选接口全批通过后一次更新配置，失败明确定位，不提交一半选择。

Python 代码更新使用以下顺序：

1. 将完整新代码写入 config/tools/ 下的新生成文件，例如 `<tool_id>-<生成标记>.py`，保留旧配置引用的原文件。
2. 准备完整新配置，使用配置文件所在文件系统中的临时文件替换 config.json，令它引用新代码。
3. 提交成功后清理不再引用的旧生成代码文件。

工具 ID 不变；生成标记用于文件保存，不提供工具历史版本功能。只清理受工具库管理、位于规定目录且已不被当前配置引用的生成文件，不任意删除用户其他文件。

config.json 替换成功是保存生效点。此前失败保留原定义和原代码；此后旧文件清理失败返回“已保存，旧文件清理失败”，保留新配置并提示残留。删除同样以配置更新生效为准，清理失败显示“已删除，文件清理失败”。保存响应须区分未提交失败和已提交附带清理问题，不引导用户重复创建。

请求断开、页面未收到结果时显示“保存结果待确认”，重新读取核实，不自动重试创建或认定未保存。文件顺序保证的范围见管理接缝调查，不将其称为多文件事务或断电保证；首版不建设事务日志和崩溃恢复平台。

每次调用开始时读取最新已保存定义、关联连接、凭据和完整源码，作为本次执行使用的内容；修改、禁用、删除影响之后的调用，已开始的调用继续执行且可单独取消。已经构建的 BaseTool 封装也在新调用开始时重新核对最新定义和资格。完整源码读取与保存/清理需要协调，避免读取旧路径后文件被提前删除；执行使用取得的源码临时副本。

工具库更新无需重启；既有模型等其他配置遵循原有生效规则，不因保存工具而重新装配当前聊天 Agent。

## 外部文件修改与删除

打开列表/详情、手动刷新、保存及开始已保存工具调用时检查相关配置和代码文件变化；首版不增加后台文件监视。

未编辑页面重新读取最新内容。有未保存草稿时保留草稿，提示磁盘变化；检测到版本冲突则拒绝直接保存，需重新读取后再修改。保存服务协调自身写入并在提交前核对文件版本；普通外部编辑器不参加这项协调，首版按先完成外部保存、再页面刷新编辑的方式使用。

配置缺失、损坏或不能解析时明确诊断，不偷偷用旧配置执行。个别 Python 文件缺失、路径非法或源码与保存结构不一致时明确定位受影响工具，不执行空代码。外部代码只改函数体、接口仍兼容时，可在新调用中使用最新完整源码；接口不兼容则先在页面重新解析、补齐并保存。

删除工具确认后从工具库直接移除，首版无回收站。确认中说明未来引用该 ID 会报工具不存在；本轮不查工作流/Agent 引用关系。删除 MCP 连接列出旗下工具和数量，确认后一次移除连接及这些工具，避免留下没有连接的定义。删除不撤销已经开始的工具操作。

自动保存的 config/tools/ 作为本地配置目录加入 Git 忽略；开发时落实此规则。可分享的示例另放可提交目录。此规划阶段不修改 .gitignore 或生成工具源码。

## 最小后端管理契约

以下是行为契约，具体方法名、路由和 DTO 按项目风格实现，不额外建设通用管理框架。

| 操作 | 必须具备的行为 |
| --- | --- |
| 工具列表/详情 | 稳定 ID、公共信息、类型配置和编辑版本；管理响应隐藏实际凭据，Python 编辑可读取源码，但持久定义只保存路径。 |
| 创建/编辑/启用/删除 | 服务端校验编辑权限、类型、名称、来源、schema 和映射；编辑/删除带读取时版本，冲突明确返回；返回提交结果及必要清理提示。MCP 来源结构通过发现应用，不通过普通编辑任意改写。 |
| MCP 连接列表/详情/保存/删除 | 连接身份稳定；只保存合法配置；删除可核对旗下工具；敏感字段按保留/替换/显式清空规则处理。 |
| MCP 测试连接/发现/应用选择 | 测试和发现不执行业务工具；预览与保存分开；应用选中项前检查连接和工具库未发生冲突，整批提交并保留原 ID。 |
| Python 静态解析 | 输入源码及当前补充结构，返回参数预览、合并候选和诊断；不执行源码，强制 main 与已识别属性的只读边界。 |
| OpenAPI 预览/批量保存 | 文档诊断、接口选择、补配置与完整批次保存；能力边界沿用 OpenAPI 决议。 |
| 开始/查询/取消测试 | 支持已保存 ID 或有效草稿，使用统一执行器；测试资格独立于普通启用检查；临时身份用于观察和取消，不建立持久测试历史或完整 Agent Run。 |
| 后续消费者复用 | get_tool、build_tools、execute_tool 的既定接口继续有效，实际调用按最新保存内容检查，明确返回缺失、禁用、配置或执行问题。 |

界面校验用于尽早反馈，后端校验决定能否保存/执行。所有读取、错误、结果与提交诊断遵循已确认的凭据隐藏规则。管理 API 不对整个原始配置文件提供无约束覆盖入口。

## 开发检查场景

- 扩展下分别管理工具与 MCP 服务；统一工具列表含三类工具，技能明确暂未开放。
