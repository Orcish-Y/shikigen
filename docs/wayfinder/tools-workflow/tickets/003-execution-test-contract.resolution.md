# 确定 MCP、Python 与 HTTP 的执行和测试边界：决议

状态：已确认，2026-10-13。用户逐项确认执行、配置保存、超时、会话及结果规则，明确采用“源码自动解析、未知类型再补充”，并要求主入口固定为 main；对修订后的完整草案回复“就这样子，不用调整了”，确认整个执行契约。本决议完成规划，不表示产品代码已实现。

## 已确认的选择

- Python 每次调用启动独立的本机子进程，执行结束退出；这是本机权限下的执行进程，不是安全沙箱。用户确认 Q2。
- MCP 区分连接测试、发现工具与真实工具调用；初始化和发现不自动调用业务工具。用户确认 Q3。
- 凭据允许在页面直接填写并保存。用户对 Q4 明确选择此方式，取代环境变量引用作为唯一录入入口的建议；存储、回显与编辑细则已由 Q15 确认，见下文。
- 支持测试未保存的草稿定义，检查和执行规则与已保存定义一致，不自动保存。未来工作流与 Agent 仍使用已保存定义。用户确认 Q5；启用状态、表单布局和编辑生命周期留给[工具管理页面与增删改生效规则](004-management-ui-lifecycle.md)。
- 手动测试与未来调用均按保存或草稿的 `input_schema` 校验类型、必填、枚举、范围及嵌套约束；不自动转换类型，不自动注入默认值或示例。`format` 注解保留与展示，首版不强制检查；schema 不支持或无法解析时明确报错，不跳过校验执行。用户确认 Q6。
- 三类工具共用状态、实际内容、错误、耗时与类型专属详情；HTTP 保留状态和响应内容，Python 保留返回值与调试输出，MCP 保留多个内容块、结构化结果和附加数据。已知凭据在可显示结果中遮盖。用户确认 Q7；具体字段和分类见下文。
- 工具定义写入项目的 `config.json`；Python 源码单独保存到 `config` 下的文件夹，定义保存代码文件路径。用户对 Q8 指定此方式，取代 SQLite 工具存储建议；具体结构与路径基准已由 Q15 确认。
- Python 使用后端的同一个解释器，支持标准库和环境已安装依赖；不自动安装依赖或建立每工具环境。每次执行使用独立临时工作目录，执行结束清理临时执行文件；本机权限边界不变。用户确认 Q9。
- 每项工具独立设置 `timeout_seconds`，默认 30 秒、范围 1–300 秒，创建时即可设置；执行预算包含启动/连接、业务执行和读取结果。MCP 连接测试/发现也默认 30 秒，可按连接调整。支持取消测试，结果区分成功、失败、超时与取消；Python 终止并回收本次子进程，HTTP/MCP 取消本次等待并清理连接，不承诺派生进程或远端操作已停止，不自动撤销或重试。用户确认并补充 Q10。
- HTTP 2xx 为成功，其他状态为失败并保留响应内容；首版不跟随 HTTP 工具重定向。合法 JSON 按 JSON 展示，其他受支持响应展示为文本；空响应保留为空，文件/二进制响应明确未支持。HTTP 输出 schema 不强制验证。用户确认 Q11。
- HTTP 可选参数缺失时不发送；path/query/header 显式 null 报错，空字符串保持空字符串；JSON body 中的 null 保留，整个 body 显式为 null 时发送 JSON null，body 缺失时不发送请求体。布尔值编码为 true/false，其余按已确认映射编码。用户确认 Q12。
- MCP 首版每次发现或调用创建独立会话后关闭，不保证跨调用的进程内状态；保留原始多内容块、结构化返回及错误内容，isError 或 SDK 协议校验异常为失败。用户确认 Q13，并要求为常驻会话与跨会话调用升级预留边界；会话获取/释放由适配器依赖的会话提供者负责，不写死在公共工具定义或统一执行接口中，首版不实现会话池。
- 实际返回内容上限 1 MiB，超出明确失败，不将截断数据当作完整成功结果；Python stdout/stderr 调试输出保留最后 64 KiB 并标明截断。首版固定上限，不增加大小配置页面。用户确认 Q14。
- 用户确认 Q15 的完整配置保存建议：tool_library 分组、独立 MCP 连接、相对代码路径、直接保存密钥及其隐藏/编辑规则；具体见下文“配置与代码路径”。
- 用户对 Q18 回复“可以，就这样子”，确认从源码静态解析参数、保留具名参数并按字段名调用；未知类型再补充，不将未知类型自动放宽为任意 JSON。
- 用户明确要求“强制要求主函数为main”：Python 入口固定为顶层 main，不再提供可配置入口函数名。参数保留具名形式，仍由源码解析；固定函数名称不要求将全部参数包进 args。

## 已确认的执行契约

公共 ToolDefinition 增加每项工具独立的 timeout_seconds。Python 专属字段包含 code_path，入口 main 由适配器约定，不新增 entry_function 配置；MCP 工具仍以 server_id/remote_name 指向独立服务连接；HTTP 专属字段沿用[OpenAPI 导入范围决议](005-openapi-import-scope.resolution.md)。服务连接保留 stdio 的 command/args/env/cwd 或 Streamable HTTP 的 url/headers 等类型配置，并独立设置连接测试/发现预算。没有混合所有种类的通用工具 config 字典。

### 三类工具输入输出

三类工具都接受一个参数对象 `inputs`，其字段由 `input_schema` 唯一声明；统一执行入口返回同一种工具结果结构，业务返回值位于 `data`。工具种类决定适配器怎样使用参数，不改变工作流按属性取值和传值的方式。

| 类型 | 参数对象送到哪里 | 结构化返回 data |
| --- | --- | --- |
| Python | 固定 main 入口，将 inputs 按参数名绑定给函数，通过 `main(**inputs)` 调用。 | main 返回的 JSON 值。 |
| HTTP | 根据保存映射把 inputs.path/query/headers/body 编成请求。 | 实际响应的 JSON 值或文本。 |
| MCP | 按远端输入 schema，把 inputs 作为工具的 arguments 传入；不额外套一层 args。 | 优先为 structuredContent；没有时为原有内容块数组。 |

不强制不同业务工具拥有相同字段名称。HTTP 的既定输入分组保留；MCP 保留远端原字段与结构；Python 从源码静态解析所需字段，类型不明时要求补充。工作流按下游真实 schema 组装参数，例如映射到 `path.order_id` 或 `body.amount`，而非把所有工具都扁平化或猜测字段含义。

input_schema 用于输入字段和约束，output_schema 用于描述 `data` 的业务结构；status/error/details 等公共结果字段由统一结果类型描述。输出 schema 继续可选且不承担输出转换；MCP 来源提供的 schema 仍只读，HTTP 导入输出规则保持已确认范围。

有输出 schema 时，后续工作流可据此展示候选输出属性、提示明显的类型不匹配；没有 schema 时，仍提供真实结构化 data，可借助测试样本了解字段，但不能承诺提前知道所有字段。文本、数组和 null 也保留真实类型：对象可映射属性，数组可由后续映射层选择元素，标量可整体传入对应类型的参数。仅返回文本时不自动猜测其业务字段；需要字段化的数据可先传给 Python 解析工具处理。

连线仅说明值的来源。运行时先取得实际上游值，组装下游参数对象，再按下游 input_schema 校验。缺少源字段、必填值缺失、类型或约束不符时明确失败，不把错误输入继续送给下游工具，不自动转换类型。消费者应检查上游 status；错误结果即使带有响应内容，也不能因此视为成功输出。静态结构提示不替代运行时校验，schema 类型正确也不承诺业务含义自动正确。

### Python 入口与后续字段映射

按用户最新要求，Python 主入口固定为顶层同步函数 main，保留具名参数，例如 `def main(quantity: int, unit_price: float, discount: float = 1)`。inputs 按字段名作为关键字参数调用；输入 `{"quantity": 2, "unit_price": 10}` 时执行 `main(**inputs)`，函数自己的 discount 默认值生效。无需把这些参数全部包进 args，也无需在页面配置函数名。源码可以包含辅助函数，解析和调用始终以 main 为入口；复制来的辅助代码可由 main 调用。

首版约定支持普通具名参数、函数默认参数、仅关键字参数和 **kwargs；**kwargs 收到哪些额外字段仍受 input_schema 控制。仅位置参数 `/`、可变位置参数 `*args`、异步/生成器入口、类方法等不自动猜测，先明确提示未支持，需要额外调用规则时再扩展。用户确认此首版范围，不将“保留具名参数”解释成任意 Python 调用约定都已支持。

页面通过 Python 标准库 AST 静态解析源码，定位唯一的顶层 main，并自动生成它的参数列表与 input_schema；常见函数无需重复填写参数名称、数量和必填性。首版注解范围为 str/int/float/bool、普通 list/dict、list[T]、dict[str, T] 及 T | None / Optional[T] 的常见 JSON 类型表达；不运行导入来解析任意别名或自定义 Python 类型。必填由是否有默认值决定，与是否允许 null 分开。生成的最终 schema 仍保存在 config.json，供输入校验和未来字段映射使用，不另存独立的参数定义。

解析阶段不执行/import 用户代码，不 eval 注解或默认表达式；默认表达式只用于判断可省略性，能够静态识别的字面值可用于展示，不从一个默认值武断推断全部允许类型。源码解析失败、缺少/重复定义顶层 main 或签名超出支持范围时明确诊断。基础注解不自动提供枚举、长度、格式等业务约束；这些仍可由高级 schema 补充。

没有注解或注解无法识别时，将相应字段标为类型待补，要求补充后形成有效 schema 才可测试/保存，不猜成字符串或自动使用任意 JSON。普通 list/dict 可确定外层类型，但不能自动知道业务元素、键或枚举范围；所需嵌套约束由用户补充，允许明确声明开放容器。**kwargs 的业务字段也需由 schema 声明或明确允许附加属性，不假装从签名发现全部字段。涉及自定义 Python 对象时，还需要对象构造/转换规则，不承诺仅补 JSON Schema 就能原样运行任意复制代码。

input_schema 仍是公共调用输入的权威结构；函数签名是源码中的实际接收约束。校验输入后，还需检查入口存在及参数可绑定；缺少函数必需参数、多出不接受的字段或名称无法绑定时明确报错。Python 的 inspect.Signature.bind 可检查参数绑定，但不代替 JSON Schema 类型校验。schema 的 default 继续不自动注入；函数本身声明的默认值按 Python 规则正常生效。读取签名的运行操作放在已授权的测试/执行子进程中，保存/展示不通过运行用户代码来推断参数。

返回严格 JSON 值，禁止 NaN/Infinity 或不可序列化对象。print/stdout/stderr 是调试输出，不承担返回协议。入口缺失、语法错误、运行异常或不合法返回分别报告明确错误。

未来工作流先把上游结果字段映射成下游输入对象，再调用工具；具名参数同样支持逐属性映射。例如上游 `data.customer.id` → 下游 customer_id，上游 `data.total` → 下游 amount，实际输入为 `{"customer_id": "c-1", "amount": 20}`，适配器调用 `main(customer_id="c-1", amount=20)`。嵌套对象同样可作为某个具名参数传入；连接线、字段路径选择器及映射规则本身由后续工作流模块实现，本工具模块提供 schema 与结构化结果。

不需要经过 LLM。例如假设 HTTP 查询订单返回 `data = {"order_id": "o-1", "quantity": 2, "unit_price": 10}`，Python 接收这三个字段并返回 `{"order_id": "o-1", "total": 20}`，MCP 更新工具接收 order_id 与 total：HTTP → Python → MCP 的参数传递都由字段映射和直接工具调用完成。

### 配置与代码路径

- 使用后端实际加载的 config.json；在原始文档中新建 `tool_library`，包含 `tools` 和独立的 `mcp_connections` 集合。每项工具仍使用公共基类与专属子类字段，不设置混合类型的通用工具 config。
- 原有 model、mcp、database 等分组保留；工具库 MCP 连接与原有启动自动装配的 `mcp.servers` 分开，避免将新建工具自动挂到当前聊天 Agent。
- Python 保存 `code_path`，源码放在配置文件旁的 `config/tools/` 下，由系统生成文件名，例如 `config/tools/<tool_id>.py`；以 config.json 所在目录解析相对代码路径，不依赖进程 cwd。持久配置不内联 Python 源码，编辑/草稿测试仍可提交源码。
- 代码文件缺失、无法读取或配置路径不合法时，明确返回配置错误，不执行空代码或自动替换。调用取得完整源码后，在本次临时执行目录运行。
- 页面直接填写的凭据以真实字符串保存到同一配置文件，首版不加密。页面使用密码框；管理 API 读取只返回已设置标志；留空保留原值，填写替换，清空用显式操作。内部执行配置可取得实际值用于认证，敏感值不进入日志、对外读取结果或错误回显，可展示结果做遮盖。
- 工具库 schema、说明、示例、路径与直接填写字符串按字面保存/读取，不递归套用旧配置的 `$ENV_NAME` 替换；旧分组的环境引用继续保留原表达。保存基于原始配置文档更新工具库，不回写已解析/绝对路径化的 runtime.config。
- 多文件一致性、批量保存、删除清理、外部编辑刷新及本地代码目录的版本控制处理由生命周期票据决定。

### 统一执行与结果

工具测试和运行时 BaseTool 复用同一后端执行入口与各类型适配器。入口按定义及输入校验、准备本次执行、设置预算、调用对应适配器、处理取消/清理并返回完整结果；未来工作流可直接使用此入口。get_tool/build_tools 的已确认接口保持有效，不要求消费者了解文件存储与会话实现。

最小后端复用契约补充 `execute_tool(tool_id, inputs)`，按 ID 取得已保存定义、检查调用资格并返回完整工具结果，无需创建 Agent 或调用模型。草稿测试经同一个内部执行入口传入校验后的草稿定义。BaseTool 只是 Agent 侧的封装，不能成为非 LLM 调用的前置条件；完整执行结果在封装时仍须保留，避免只用普通 ainvoke 丢掉状态或附加数据。具体方法名可随代码风格调整。

统一结果字段：

| 字段 | 含义 |
| --- | --- |
| `status` | `success`、`error`、`timeout`、`cancelled`。 |
| `data` | Python 返回值；HTTP 实际 JSON/文本；MCP 优先 structuredContent，否则为内容块数组。失败时有可用业务响应也保留，未取得时为 null。 |
| `error` | 成功时为 null，其他情况提供 code、message 及必要的字段/位置；不回显秘密。 |
| `duration_ms` | 本次执行的已耗时，包含已完成的清理；超时是执行预算，清理可能额外耗时。 |
| `details` | Python 调试输出/退出码/截断标记，HTTP 状态/响应类型/脱敏响应头，MCP 完整原始返回及来源信息等类型专属详情。 |

保留结构与类型，不把结构化 data 预先转换成一段字符串。结果上限针对原始实际返回的 UTF-8 JSON/文本表示，MCP 包含内容块的编码数据；超过上限明确 output_limit 错误。HTTP 对有响应内容的失败保留状态与受支持响应体；限额失败或未取得结果不伪造完整数据。可显示结果与后续消费者取得的结果均遵循凭据遮盖规则。

错误按配置/文件/凭据问题、输入校验、启动/连接/传输、Python 执行或返回、HTTP 状态或响应类型、MCP 业务/协议、结果过大等提供可识别分类；超时和取消另用独立 status。适配器的未预期异常转换为执行错误，不把异常文本当作成功业务结果。

## 开发检查场景

- 有常见类型注解的函数自动生成参数，无需重录；无注解参数标为待补，补齐后才可测试/保存；默认值只影响可省略性，不自动注入 schema 默认值。
- 只解析并调用顶层 main，辅助函数不作为另一个入口；缺少或重复定义 main 明确报错，不提供入口名称配置。
- 两个非 LLM 消费者可以通过 execute_tool 取得并传递 JSON 字段；下游实际输入仍需校验，字段缺失或类型不符明确失败。
- 草稿测试不自动保存，已保存 Python 定义指向相对代码文件；修改启动 cwd 不改变路径解释，缺失文件明确报错。
- 保存工具库保留配置其他分组及其环境引用，不因保存工具把它接到当前聊天 Agent。
- HTTP 非 2xx 保留失败响应，JSON body 缺失与 null 区分，超大/二进制结果明确反馈；不强制响应 schema 校验。
- MCP 多内容块、structuredContent 和错误业务结果保留；协议异常、超时、取消明确反馈，会话升级不需要改稳定工具引用。
