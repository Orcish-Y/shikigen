# 确定 OpenAPI 导入的首版范围：决议

状态：已确认，2026-10-12。用户逐项确认入口、创建流程、参数和引用范围、认证、编辑与再导入、诊断及输出规则，并对 Q12 的完整草案回复“同意”，确认包括方法列表、参数序列化与 schema 边界在内的首版清单。本决议完成规划，不表示产品已经实现。

事实依据见[主流 Agent 调查](../../../research/tool-configuration-fields.md)中 OpenAPI 部分；下文的支持子集是本项目的首版选择，完整规范与主流产品功能清单不等同于本项目已支持。

## 已确认的入口与流程

- 支持上传或粘贴一份 JSON/YAML OpenAPI 文档；首版不从 URL 下载文档。HTTP 工具仍可以调用配置的接口地址。
- 识别 OpenAPI 3.0.x、3.1.x，支持下文清单中的常用子集；Swagger 2.0 与完整规范兼容放到后续。
- 保留从空白表单手工创建 HTTP 工具，和导入共用 `HttpToolDefinition` 及 HTTP 运行适配器。
- 导入流程为“解析文档 → 勾选接口 → 预览并补配置 → 保存工具”；一个接口生成一个 HTTP 工具，只保存勾选项。
- 预览显示名称、方法、路径和需补配置或未支持的内容；导入过程不会自动调用所选接口。

## 已确认的地址、名称与参数来源

- 分别读取接口地址、调用名称和请求参数，不从参数名称或值猜测接口名称。
- 方法和路径来自 OpenAPI 的 `paths` 下对应 operation；调用名称优先从 `operationId` 生成候选值，缺失时由方法和路径生成。用户可以在预览中修改和确认，重名按已确认的工具库命名规则区分。
- 路径、查询和请求头参数从 `parameters` 读取原名、位置和结构，请求体从 `requestBody` 读取；缺少定义或不受支持的结构明确诊断，不自动猜测字段。
- 服务器地址按 operation > path > 文档级的顺序读取；多个服务器可以选择，地址可以手工修改。相对地址或未填写的地址变量需要补齐，生成有效请求地址后才能保存。
- 工具调用名称不决定 HTTP 请求发到哪里；运行时根据保存的方法、地址与参数映射构造请求。改名称保持工具 ID。

页面名称可以从接口的 `summary` 预填，用途说明可以从 `description` 或 `summary` 预填；没有说明时需要用户补充。调用名称的合法性、工具库内唯一性和避开内置工具名，沿用[定义、适配器与引用决议](002-definition-adapters-references.resolution.md)。来源名字只作为候选，不据此推断业务参数或实际请求地址。

## 已确认的请求与引用范围

- 支持 path、query、header 的普通值以及常见 query 数组；请求体先支持 `application/json`，包含嵌套对象和数组。调用输入按 `path`、`query`、`headers`、`body` 分组，避免不同位置的同名参数互相覆盖；手工创建与导入共用此范围。
- 文件上传、表单、cookie 参数和复杂参数序列化留到后续。
- 支持同一份文档内部的定义引用，保留常见类型、必填、枚举、范围和数组/对象约束，并处理 3.0 与 3.1 的常见可空类型差异。
- 外部文件/URL 引用、循环引用和复杂组合结构先明确提示未支持，指出受影响的接口；不删除约束后继续导入。

### 首版支持清单

| 项目 | 支持范围与反馈 |
| --- | --- |
| 方法 | `GET`、`POST`、`PUT`、`PATCH`、`DELETE`、`HEAD`、`OPTIONS`；其他方法给出未支持诊断。 |
| 地址 | HTTP/HTTPS 地址模板；补齐服务器地址及变量后保存，路径占位符需对应已定义的必填路径参数。 |
| 参数合并 | 合并路径级与接口级参数；按 `(name, in)` 识别同一参数，接口级定义覆盖路径级定义。同一层的重复或冲突定义明确报错。 |
| path/header | 字符串、整数、数字、布尔等标量，支持普通 `simple` 序列化；数组、对象及 `label`、`matrix` 等特殊形式暂不支持。 |
| query | 普通标量以及标量数组；支持 `form`。数组支持重复键（`tags=a&tags=b`）与逗号分隔（`tags=a,b`），按照文档的 `explode` 选择；未声明时按相应默认值处理，不自行换一种格式。 |
| 复杂序列化 | query 对象、`deepObject`、`spaceDelimited`、`pipeDelimited`、参数 `content` 序列化和要求特殊保留字符规则的请求先诊断为未支持；普通值按位置进行编码。 |
| 请求体 | 无请求体或 `application/json` 请求体，支持普通 JSON 类型、嵌套对象和数组；存在多种媒体类型时选择受支持的 JSON 类型，只有表单、文件或其他未支持类型时诊断为未支持。 |
| 输入结构 | 顶层为对象，按需包含 `path`、`query`、`headers`、`body`；无参数时为空对象 schema。保留每个参数、字段以及整个请求体的必填性。 |
| 内部引用 | 支持所选请求实际使用的文档内部 `#/...` 引用，包括 schema、parameter、requestBody；无法解析或发现循环时指出接口及引用位置。 |
| 常见 schema | 支持普通类型、对象属性、必填、枚举、数值范围、字符串长度/模式、数组长度/元素结构和普通附加属性约束；嵌套对象与数组保留完整层级。 |
| 可空类型 | 处理 3.0 的常见 `nullable` 和 3.1 的单一类型加 `null`，包括等价的“一个普通结构或 null”表达；通用 `oneOf`、`anyOf`、`allOf` 及其他超出子集的组合或自定义 dialect 先明确提示。 |
| 来源内容 | 保存与所选接口相关的原始来源片段供查看与诊断；schema 的说明、示例等来源信息保留。`format` 等注解的实际校验策略由执行票据明确，不把保留注解等同于已经完成校验。 |

上述输入侧未支持的结构阻止相应工具保存；输出侧复杂结构按后面的输出规则处理。仅有嵌套对象不属于递归引用。

`input_schema` 仍是输入结构的唯一权威来源。HTTP 专属参数映射保存参数的位置、目标名字、输入取值位置和必要序列化规则，不另外维护一套独立的类型与必填定义。编辑 schema 或映射时，保存前校验它们一致；路径占位符等必要信息不能悬空。

例如同时存在 path 参数 `id` 与 query 参数 `id` 时，调用输入分别为 `path.id` 与 `query.id`。JSON 请求体作为 `body` 整体传入，不把其中字段自动拆成查询参数。简单表格与高级编辑器的无损切换方式留给页面票据。

## 已确认的认证、编辑与诊断

- 首版认证范围为无认证、Bearer Token、API Key（header/query）。导入读取文档的认证要求，用户选择受支持的认证方案并补齐该方案要求的全部凭据；不支持的认证不会自动退化为匿名请求。凭据不进入模型调用参数；录入、保存及隐藏方式由执行票据决定。
- 导入后可以编辑名称、说明、地址、方法、参数映射、输入结构和认证；修改保持工具 ID。再次导入生成新的预览，保存为新工具，不覆盖已有工具；首版不做文档自动同步或自动合并更新。
- 按接口显示“可保存 / 需要补配置 / 未支持”及原因；只检查所选接口及其引用内容。一项不支持不阻挡其他正常接口；所选项需全部补齐，或取消选择有问题的接口后再批量保存。文档整体格式错误时明确报错。

导入时使用接口级认证要求，未指定时继承文档级要求；显式无认证按文档表达处理。有多个备选方案时允许选择一个受支持的方案，同一方案的多个认证要求需要全部满足。凭据目标位置冲突或要求不支持时明确诊断；不将凭据放进公共输入 schema。用户为选中的接口补齐适用的认证配置；凭据的录入、保存及复用细节留给执行票据。

诊断包含受影响的方法、路径、字段或引用位置，以及可采取的补配置动作或未支持原因。整体无法解析、版本不支持等属于文档级错误；接口级错误留在相应预览项，不由未勾选接口的复杂内容阻止已选项保存。

## 已确认的输出规则

文档只有一种可支持的 JSON 成功响应结构时，自动填入可选的 `output_schema`。存在多种不同成功结构、结构超出子集或没有可用结构时，留空并提示，保留来源响应定义供查看；不自动挑一种当作所有响应的结构，也不强行合并不同结构。

输出 schema 只作参考，不做输出映射或强制响应校验。输出结构复杂不阻止请求配置完整且受支持的接口导入；测试仍展示实际返回的 JSON/文本，响应状态等统一结果由执行票据决定。

## HTTP 定义与导入器边界

导入器生成 `HttpToolDefinition` 的公共字段及 HTTP 专属字段：请求方法、地址模板、参数位置与映射、JSON 请求体规则、认证要求与绑定、可选导入来源信息。来源信息仅用于预填、查看和诊断；用户修改后，执行以最新保存的工具定义为准。

各专属字段可以使用明确的 HTTP 子模型，沿用公共基类加专属子类的契约，不引入混合各类型字段的通用 `config`。手工创建与导入产生同一类型，由同一个 HTTP 适配器执行；`openapi` 不是新的运行工具类型。

一个工具执行一个请求；解析文档、预览和保存都不会自动调用接口。再次导入保存新工具时生成新 ID，旧工具及其 ID 保持不变；编辑旧工具保持旧 ID。首版没有来源自动同步、版本迁移或工作流引用表。

## 用于开发的检查场景

| 场景 | 预期 |
| --- | --- |
| operationId 与参数名称完全不同 | 调用名称与请求参数分别读取，参数原名及位置保留。 |
| 同名参数分别位于路径和查询中 | 两个参数分别映射，互不覆盖。 |
| 文档缺服务器地址或存在未填写变量 | 预览要求补齐，不生成无法定位地址的工具。 |
| 一个接口使用外部请求引用，另一个接口为普通 JSON 请求 | 前者显示具体未支持原因，取消勾选后可保存后者。 |
| 只有输出结构复杂，请求本身受支持 | 输出 schema 留空并提示，可保存工具，测试展示实际结果。 |
| 同一份文档再次导入 | 生成新预览与新工具 ID，不修改旧工具；新调用名称仍需满足唯一性。 |
| 导入后修改参数结构或映射 | 校验结构与映射一致后保存；保持工具 ID，未来调用读取最新定义。 |
