# 确定工具定义、适配器与稳定引用契约：决议

状态：已确认，2026-10-12。用户先提出公共基类与专属子类，逐轮确认 MCP 保存方式、代码登记适配器、稳定 ID 引用最新定义、名称冲突策略和 MCP 编辑边界，再明确同意完整契约与最小复用入口。本决议完成规划，不表示产品代码已经实现。

## 定义结构

使用公共数据基类 `ToolDefinition`，并由 `McpToolDefinition`、`PythonToolDefinition`、`HttpToolDefinition` 继承。基类表达共有管理与调用字段，各子类声明自己的专属字段，通过 `kind` 区分类型。

这些类是可保存、校验与传输的工具定义。`BaseTool` 是运行时可调用工具，由适配器构建；数据基类不包含执行逻辑。专属配置字段放在相应子类中；需要分组时可以使用明确的专属子模型，不设置混合所有类型字段的通用 `config` 字典。

| 公共字段 | 首版契约 |
| --- | --- |
| `id` | 系统生成的稳定身份；改名称或配置不改变 ID。 |
| `kind` | 对应子类的类型标记，首版为 `mcp`、`python`、`http`。 |
| `display_name` | 页面名称，可中文、可重复；发现或导入可以预填。 |
| `name` | 工具调用名称；自动生成合法且唯一的名称，允许用户修改。 |
| `description` | 工具用途说明，供模型选择工具；MCP/导入可预填，用户可以编辑。 |
| `input_schema` | 保存完整 JSON Schema，是输入结构的唯一来源；无参数也表达为对象 schema。 |
| `output_schema` | 可选，保存来源提供或用户定义的输出结构；不要求填写，也不承担输出映射。 |
| `enabled` | 用户是否允许工具被选择使用；不表示连接或执行一定成功。 |
| `created_at`、`updated_at` | 系统维护的创建与更新时间。 |

简单参数表格与高级编辑器读写同一份 `input_schema`，不另外维护一份独立参数定义。复杂 schema 的显示及无损切换由[工具管理页面与增删改生效规则](004-management-ui-lifecycle.md)决定。

MCP 子类至少包含 `server_id` 与 `remote_name`，分别关联服务连接及服务内的工具身份。Python 子类包含代码及其执行字段；HTTP 子类包含单请求定义及其执行字段。Python/HTTP 完整字段与限制分别由执行和 OpenAPI 票据明确，本票据不提前锁定代码入口或认证配置。

## MCP 服务连接与工具

MCP 服务连接独立于工具定义保存，拥有稳定连接 ID 和连接配置。同一连接可以提供多个工具，工具引用该连接，避免重复保存连接命令、URL 或凭据。

连接后发现工具，只将用户勾选的工具加入工具库；它们各自有启用状态。未勾选工具可在以后重新发现时添加。对同一 `(server_id, remote_name)` 再次发现，识别为原有工具并保留工具 ID；首版一对来源身份对应一项入库工具。具体更新确认、远程工具消失以及本地编辑保留规则由页面生命周期票据决定。

MCP 本地页面名称、用途说明、调用名称及启用状态可编辑；远程工具名、输入 schema 和服务提供的输出 schema 由发现结果决定，在页面只读。这些 schema 保存发现时的完整内容；重新读取及应用变化见后续[页面决议](004-management-ui-lifecycle.resolution.md)。Python 参数来源和可编辑范围以[执行决议](003-execution-test-contract.resolution.md)及页面决议为准，HTTP 导入后的编辑边界由 OpenAPI 票据决定。

## 名称与稳定引用

页面名称不充当唯一身份。调用名称在工具库内唯一，并避开内置工具名；生成名称时处理来源重名，已有工具的调用名称保持稳定。手动名称冲突在保存或装配之前明确报错，不依赖现有 `ToolRegistry` 静默忽略重复工具。

2026-10-13 用户补充职责边界：名称建议在前端生成，使用已加载的工具名称和列表返回的 `reserved_names` 避开已知占用；新建时随页面名称更新，手动修改后保留，编辑已有工具不重新生成。后端提供 `GET /api/tools/validate-name?name=...&tool_id=...` 校验格式、重名及内置名称占用，编辑时可排除自身。名称限 1–64 个英文字母、数字或下划线，首字符为字母或下划线；保存必须提交明确的 `name`，后端复用同一规则再次校验，不生成名称。预校验不预占名称，列表过期或并发导致的冲突由保存明确拒绝。移除原 `name-candidate` 接口。

例如两个 MCP 服务都提供 `search`：各自保留远程工具名 `search`，本地调用名称自动区分；按各自服务连接和远程名称执行。改变本地调用名称不改变远程名称。

后续工作流和定制 Agent 通过 `tool_id` 引用工具，使用时读取最新已保存定义。改页面名称或调用名称不使引用失效；首版不建设工具版本或历史定义快照。改参数结构后，旧调用参数仍需要校验，不承诺自动兼容或迁移。

## 适配器与最小复用入口

在后端代码中登记 `kind -> adapter`；适配器接收对应定义与必要的执行依赖，构建一个 `BaseTool`。工具管理服务负责定义保存、按 ID 读取和选择检查；适配器处理类型转换及运行细节，不自行维护另一套工具定义存储。

```text
ToolDefinition
├─ McpToolDefinition ──── MCP 适配器 ────┐
├─ PythonToolDefinition ─ Python 适配器 ─┼─ BaseTool → ToolRegistry
└─ HttpToolDefinition ─── HTTP 适配器 ───┘
           ↑
    OpenAPI 导入器生成 HTTP 定义
```

OpenAPI 导入器负责生成 HTTP 工具定义，使用同一个 HTTP 运行适配器；不再增加一种 `openapi` 运行类型。新增工具类型时增加专属定义、登记适配器并增加对应表单；首版不建设动态插件安装体系。

首版提供两个后端应用接口，具体命名可随代码风格调整：

- `get_tool(tool_id)`：读取保存的工具定义，供管理、编辑及后续复用。
- `build_tools(tool_ids)`：读取选中的最新定义，检查存在、启用及类型支持，再按适配器构建 `BaseTool` 集合，交给任意需要工具集合的调用方。

ID 不存在、工具禁用、适配器不支持或构建失败时，明确返回对应问题，不静默跳过所需工具。手动测试的调用与输入校验入口由执行票据定义；它应复用同一适配器。

后续消费者只需保存选中的工具 ID；首版不创建工作流/Agent 的引用关系表，也不自动挂载到当前聊天 Agent。后续引用删除策略、运行中修改的生效时点及重复发现的更新行为，由页面生命周期票据决定。
