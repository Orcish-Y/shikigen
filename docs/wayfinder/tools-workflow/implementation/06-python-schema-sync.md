# 06: Python 类型补齐与源码变更同步

> 历史开发票：2026-10-23 从本机 scratch 迁入，保留原状态、验收项和阶段记录。当前实现与后续修订先读[开发指南](../README.md)和[实施索引](index.md)。

**页面原型：** 涉及工具页的开发与验收，先读取并遵循[工具页面原型与参照规则](../../../../frontend/design.md#工具页面原型)。

**What to build:** 用户为无法静态识别的 Python 参数选择类型，补充复杂结构和业务约束；修改源码后保留兼容配置并看到需要重新处理的变更。完整覆盖首版 main 签名与注解范围，不增加任意 Python 调用协议。

**Blocked by:** 03：工具编辑、启用、删除与草稿测试；05：创建并测试带注解的 Python 工具。

**Status:** completed

- [x] 无注解或无法识别的类型显示待补，下拉支持字符串、整数、数字、布尔、对象、数组等 JSON 类型；未形成有效 input_schema 时保存和测试被后端及页面阻止，不自动推成字符串或任意 JSON。
- [x] 支持首版普通 list/dict、list[T]、dict[str, T] 及常见 Optional/T 加 null 注解；已识别外层类型只读，容器内部业务结构可补充或明确开放，是否必填仍由函数默认值决定。
- [x] 支持仅关键字参数和额外关键字参数；额外业务字段由 schema 声明或明确允许附加属性，不假装从签名知道全部字段。仅位置参数、可变位置参数、异步/生成器入口、类方法明确未支持，自定义对象不自动构造。
- [x] 高级 schema 可补说明、示例、枚举、范围、嵌套约束及未知类型细节，但不能改写源码确定的名称、类型和必填性，允许 null 的补充也遵循源码；服务端同样拒绝越界编辑。
- [x] 修改源码自动静态重解析，保存和测试前重新核对；同名兼容属性保留补充，同名仍未知保留类型选择，新未知字段待补。只保存最终 input_schema，不另外持久化解析参数表。
- [x] 删除、改名、不兼容类型和必填变化明确展示；改名按旧字段删除加新字段，不猜迁移。新增明确注解以源码为准，冲突要求重新补齐，不静默沿用不兼容约束。
- [x] 解析或高级 JSON 失败保留源码、补充和错误原文，不继续用未核实旧参数执行。有效 schema 更新后动态测试表单重新渲染，保留可识别实际输入并对不匹配值诊断，不暗中删除或自动转换。
- [x] 源码编辑和保存保持工具 ID、相对代码路径及既定文件提交顺序；只在显式测试/执行中运行代码，草稿测试不提交修改。
- [x] 公开 API 与真实子进程验证未知补齐、容器、nullable、关键字参数、额外属性限制、只读边界及源码兼容/不兼容变更；页面验收预览、类型下拉、高级补充和重解析诊断，并完成相关后端、前端测试与构建。
