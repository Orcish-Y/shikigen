# 02: HTTP 参数映射与动态表单

> 历史开发票：2026-10-23 从本机 scratch 迁入，保留原状态、验收项和阶段记录。当前实现与后续修订先读[开发指南](../README.md)和[实施索引](index.md)。

**页面原型：** 涉及工具页的开发与验收，先读取并遵循[工具页面原型与参照规则](../../../../frontend/design.md#工具页面原型)。

**What to build:** 用户手工配置带参 HTTP 接口，编辑输入结构和请求映射，再通过 rjsf 动态表单或 JSON 编辑填写参数、真实调用并查看结果。一个工具执行一个请求，实际字段、约束与发送内容保持一致。

**Blocked by:** 01：创建并测试第一个 HTTP 工具。

**Status:** done

- [x] 创建并测试 GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS 工具，可配置 HTTP/HTTPS 地址模板、固定请求头、参数映射和 JSON 请求体；不支持的方法、地址或请求结构有明确诊断。
- [x] inputs 保留 path、query、headers、body 分组，不同位置同名参数互不覆盖。映射记录取值位置、目标名和必要序列化规则，不重复保存类型和必填定义；后端核对 schema、映射和必填路径占位符的一致性。
- [x] path/header 标量采用 simple 序列化；query 支持 form 标量及标量数组，按 explode 或相应默认规则采用重复键或逗号分隔；JSON body 保留嵌套对象、数组和实际类型。已排除的表单、文件、cookie 和复杂序列化不能悄悄放宽执行。
- [x] 简单参数表格和高级 JSON 编辑读写唯一 input_schema，修改单字段保留其他约束、说明和示例；复杂结构无法无损表达时转高级编辑，不从表格重建全部 schema。无效 JSON 保留原文、定位错误并阻止保存/测试。
- [x] 实际参数由 rjsf 根据当前有效 input_schema 动态渲染，uiSchema 只影响展示；表单与 JSON 模式共用一个 inputs 对象。动态控件不能准确表达受支持结构时可使用高级 JSON 入口，不删除 schema 或原输入。
- [x] 可选缺失不发送，path/query/header 显式 null 拒绝，空字符串保留；body 缺失不发请求体，整个 body 为 null 则发送 JSON null，内部 null 同样保留。布尔按 true/false 编码，false、0、空数组/对象不因真假判断丢失。
- [x] 后端严格校验类型、必填、枚举、范围、字符串/数组和嵌套约束；不转换类型、不注入默认值/示例，不支持或无法解析 schema 时明确失败。format 保留展示但不强制检查，前端不能增加与此冲突的阻断。
- [x] 使用已固定的 rjsf/AJV 依赖配置实际 schema 方言和校验选项，不把默认 draft-07 当作全部来源已兼容；默认格式校验和原生控件不能因 format 额外阻断后端允许的输入。无法准确渲染的受支持结构走高级 JSON 与后端诊断，不修改/删除来源约束。
- [x] 测试表单初始展示不能自动产生 schema default、首个枚举、必填布尔 false 或 minItems 占位等业务值；用户明确提供的值才能参与输入。切换模式和 schema 更新不静默删字段或修正输入。
- [x] 可选 output_schema 用高级 JSON 编辑，描述 data 的业务结构；未填写显示未声明，HTTP 响应不强制按它验证或转换，也不从一次成功自动写回。
- [x] 本地 HTTP 服务通过公开 API 断言真实方法、参数位置、两种数组编码、body 和空值；验证输入错误未触发请求。使用现有 Testing Library/jsdom 操作真实 rjsf Form，检查初始默认值、方言/format、模式切换和真实提交 inputs，不以假表单替代；Tauri 页面验收嵌套、切换无损、主题及实际校验环境，并完成相关后端、前端测试与构建。
