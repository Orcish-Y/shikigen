**Blocked by:** 04：HTTP 认证；10：OpenAPI 基础导入与工具编辑。涉及凭据管理前需统一设计。

**04 当前范围（2026-10-15 用户调整）：** HTTP `auth` 数组、稳定绑定 ID、组合注入与冲突校验保留，密钥直接使用 `auth[].value`。通用 credential 模型、特殊编辑协议和共享遮盖模块已移除，后面统一设计；不能继续按旧契约复用。所选同一方案的多个要求仍映射为多个绑定，密钥不进入业务输入；涉及凭据管理和隐藏的验收项需先完成统一设计。当前状态见[HTTP 认证记录](../http-auth-credentials.md)。

- [x] 解析所选请求使用的文档内部 schema、parameter、requestBody 引用，保留完整请求层级及常见类型/对象/数组、必填、枚举、范围、字符串模式/长度、数组边界和普通附加属性约束；说明、示例和来源保留，不把嵌套对象误判成循环。
- [x] 处理 3.0 nullable 与 3.1 单一普通结构加 null 的等价表达。通用 oneOf/anyOf/allOf、自定义 dialect、无法解析/循环/外部请求引用明确未支持，定位受影响接口及位置，不删除约束继续导入。
- [x] 严格遵循手工 HTTP 请求范围及序列化：路径占位符有对应必填参数，path/header 普通标量、query form 标量或标量数组、JSON 请求体。多媒体类型可选择受支持 JSON；文件、表单、cookie、对象 query、特殊序列化、参数 content 和特殊保留字符要求有具体未支持原因。
- [x] 认证按 operation 优先、缺省继承文档，显式无认证按来源表达；多个备选方案选择一个受支持方案，同一方案多个要求全部满足。支持无认证、Bearer、header/query API Key，缺凭据提示补齐，未支持要求或目标冲突不降级匿名。
- [x] 认证凭据仍是专属配置，预览可录入并在保存时按隐藏规则处理，不进入业务 schema。所选补齐接口生成同一可执行 HTTP 定义，本地认证服务收到完整认证及实际参数。
- [x] 按接口显示可保存、需要补配置、未支持，诊断包含方法、路径、字段/引用位置、原因及可采取动作；只检查所选接口依赖的请求内容，未勾选复杂结构不阻断正常接口，整体格式错误仍单独反馈。
- [x] 所选输入全部就绪或取消问题项后才整批保存；选中任一无效不部分提交。候选与保存字段/映射保持一致，相关原始来源可查看，format 仅作保留注解而不额外强制检查。
- [x] 单一受支持 JSON 成功结构预填 output_schema；多成功结构、复杂或没有可用输出则留空说明并保留来源，不挑一个假装覆盖全部，也不因输出复杂阻止有效请求导入；实际响应保持完整类型。
- [x] 用 JSON/YAML 混合兼容样例经公开 API 验证内部引用、两种可空、全部支持的约束和认证备选/组合；不支持项精确诊断，取消其选择能保存其他项，不能保存一半。页面验收状态、补配置和来源查看，并完成相关后端、前端测试与构建。
