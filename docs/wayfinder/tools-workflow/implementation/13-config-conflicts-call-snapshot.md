**现有保存规则（2026-10-15 用户决定）：** 首版本地保存不增加确认请求头、确认接口或缓存；未收到响应时保留草稿并提示“保存结果不确定”，禁止重复提交，可明确放弃草稿并重读工具库恢复浏览。不能用定义字段相同或凭据 `is_set` 推断本次保存成功。已收到成功响应但详情读取失败时只重读详情。后续补齐本票时参照[保存结果记录](../http-auth-credentials.md#保存结果)。

- [x] 原始配置替换成功是提交点：新代码写入或配置替换前失败保留原定义与原代码；提交后旧生成文件清理失败只记后端日志，保存／删除仍返回成功；后续配置提交或启动时重新核对引用并重试，不将已提交当作整体失败引导重复创建。
- [x] Python 保存先关闭完整新生成代码，再准备同文件系统完整配置临时文件并替换，最后仅清理管理目录内未被当前配置引用的旧生成文件。保留原始其他配置/环境引用，不把过程称为多文件事务或断电恢复保证。
- [x] 所有更新、删除和已存在批次操作带读取版本，服务协调自身写入并在提交前重新核对；名称、来源、schema、类型权限与映射整批合法才提交，不能半保存。后续 OpenAPI/MCP 应用接入同一规则。
- [x] 保存回复中断或未知显示“保存结果不确定”，保留草稿、不自动重试创建或认定成功／失败；延续现有明确放弃并重读的恢复方式，不通过凭据已设置标志核实替换。页面分别表达未提交失败、提交成功和结果不确定；不展示清理警告。
- [x] 打开列表/详情、手动刷新、保存及开始已保存调用时检查配置/代码变化；未编辑页重读，脏草稿保留并提示冲突，拒绝直接覆盖，需要重读后再修改。不增加后台文件监视或跨重启恢复。
- [x] 外部编辑器不参与应用写入协调，首版按先完成外部保存、再刷新页面编辑使用，不承诺同时外部写入互斥；API 的冲突定位足以让用户理解受影响定义。
- [x] 配置缺失、损坏或无法解析明确失败，不执行缓存旧配置；Python 文件缺失、不可读、非法路径、源码接口不一致定位受影响工具，不执行空代码。函数体兼容外部修改可在新调用使用，不兼容先重解析、补齐、保存。
- [x] 每次调用取得最新保存定义、关联连接、凭据和完整源码，固定为本次执行内容；取得后修改/禁用/删除不改变当前调用，下次按最新定义和资格检查。源码读取与保存清理协调，执行使用已取得临时副本，旧路径不能在读取完成前被提前清理。
- [x] 连接修改同样影响下一次调用，工具库更新不重启后端、不自动重装当前聊天 Agent；其他配置保持既有生效方式，主动取消当前调用仍由其独立取消操作完成。
- [x] 通过公开 API 与临时真实文件制造写入/替换/清理失败、回复不明、外部变动、坏配置和缺失代码；用可控正在执行调用验证当前/下次生效，不以私有函数调用次数作断言。页面验收冲突、结果待确认及普通成功反馈，并验证后续重试清理，并完成相关后端、前端测试与构建，包含 Windows 替换/清理行为检查。
