# 运行详情、用量与事件视图：讨论记录

日期：2026-10-03。所属票据：[确定运行详情、用量与事件视图](005-run-details.md)。状态：用户已完整确认、规划已定稿；应用实施待完成。

## 已核实的现状

- 当前运行详情位于 App 的覆盖抽屉，只有 Run ID、原始状态、输入和输出 Token；没有会话 ID 复制、累计总量、调用次数、模型分项、完整时间或持久事件。
- 会话历史栏底部固定显示“暂无用量数据”，没有消费当前 Run 的真实用量。
- 后端 Usage 已包含 total_input、total_output、total_tokens、calls、by_model；模型分项包含 input、output、calls。
- RunSnapshot 已包含会话与运行身份、状态、错误和错误码、创建／更新／结束时间、usage 和 usage_pending。快照与事件的纯读 HTTP 查询仍是前置契约确认但尚未实施的目标。
- usage 是已提交执行阶段的累计用量；没有结算记录时为 null，不表示零消耗。usage_pending 表示存在尚无结算记录的执行阶段，与 Run 是否终结分别表达；取消后的用量可以晚于终态补齐。
- 重建 SSE 的首帧 metadata 可包含已知用量与结算标志；直接发起执行时首帧只提供身份和运行状态。后续 metadata 是部分更新，不能因字段省略清空已知值或推断已经结算。
- 事件查询与 SSE 共用 message／lifecycle／approval 的公开事件形状，含 seq、created_at、event_type 和完整 payload。现有前端只消费消息和少量生命周期文字，没有保留完整事件视图。
- 关闭运行详情不能停止所属会话的观察；GET 详情不替代 interrupted 的 GET stream 恢复校验。历史审批只能展示服务端事实，不能用本地选择或点击伪造事件。

## 第一项：快照与事件的读取时机

助手建议：定位当前会话的最近一次 Run 后，读取一次只读快照，供历史栏摘要与运行详情共用；进入会话时不立即请求完整事件历史。打开运行详情时刷新快照并补读事件，已有 SSE 继续更新同一事实投影。关闭详情不关闭观察或取消运行；后续结算刷新、局部错误和时间线布局分别讨论。

用户反馈：“可以  你来”。读取时机按推荐确认；助手继续整理其余细节，形成可整体核对的草案。此反馈不表示应用代码实施授权，也不提前确认尚未呈现的其余方案。
