## 2. 最后核对的边界细则

- **分页边界：**停止条件使用服务端原始数量，不能使用过滤或去重后数量。无过滤且不满视口可自动填充；过滤只查已加载会话，不因输入而读完全部页，用户向下滚动意图或键盘到底仍可加载一页。失败保留原位重试，不能由哨兵无限重试。
- **空状态与迟到：**读取中／失败、确实无会话、空对话和过滤无匹配分别显示。已确认创建不会因后续列表失败再次 POST；用户期间改选时迟到新建结果不抢当前选择。异常日期明确待确认，不伪造时间。
- **输入与阅读：**发送接受只清对应草稿版本；失败保留原文，不覆盖后来输入。阅读位置按稳定锚点恢复，工具区内滚动与主时间线分开，图片、布局变化及后台查询不主动跳到底。
- **模态与偏好：**侧栏覆盖、命令、详情、参数／图片、文件和取消确认共用单前景模态与焦点规则。桌面只有用户主动选择写偏好，跨断点被动布局不写；软键盘、长内容及托盘提示并存时保留必要操作。
- **剩余 fog：**长内容／提示并存及未分类异常已有阅读、操作可达与错误归属规则。建议具体缺陷在实施后实机验收发现并修正，需要改变产品行为时再开决策记录；保留全部检查，无需重新把原生截图设为规划前置。

## 3. 已确认的八批实施顺序

1. **会话定位与只读查询：**分页、历史状态、Run 快照／事件和窗口可见桥接，建立真实读取边界。
2. **运行投影、恢复与输入：**统一事实／预览、身份与代次、自动 GET／手动核实、持久草稿与原文发送。
3. **审批、取消与中止消息结算：**先完成原子保存，再接入逐项审批、选择恢复、取消确认和竞争结果。
4. **完整消息、工具与 Markdown 导出：**保留完整内容，接入真实工具关联、长内容查看／复制和已提交快照导出。
5. **工作目录资源与系统打开：**先补资源接口和受控桥接，再接本地图片自动加载、文件每次确认打开。
6. **运行详情、用量与事件：**复用纯读查询和投影，完成真实用量、事件与有限结算核实。
7. **会话浏览、命令、响应式与视觉收尾：**落实本次交互选择，统一原稿比例、桌面偏好与窄屏可达性。
8. **首版联合验收：**在真实 Tauri 中逐项核对 PRD 17 条及新增要求，记录预期、实际和证据。

各批从新增组件开始遵守视觉基准。用户可以提前实现独立模块；接口／事实投影／原子结算／打开桥接是实际依赖，任务编号不限制用户自主安排。
