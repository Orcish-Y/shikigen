# 审批与取消的完整交互：讨论记录

日期：2026-10-03。所属票据：[确定审批与取消的完整交互](003-approval-cancel.md)。

状态：已结束。用户选择“可以定稿（推荐）”，确认[审批与取消交互契约](003-approval-cancel.contract.md)；最终结论见[决议](003-approval-cancel.resolution.md)。本文件保留真实交流及源码事实，应用行为待实施。

## 1. 本轮核实的事实

- 审批策略目前覆盖 write_file、bash，只支持 approve / reject。拒绝的 message 可省略或为空，不支持编辑工具参数。[审批策略与校验](../../../../packages/harness/shikigen/core/approval.py)、[审批载荷](../../../../packages/harness/shikigen/contracts/events.py)。
- 一次响应必须包含全部当前 Interrupt ID；每个 Interrupt 的 decisions 与 action_requests 保持相同长度和原始顺序，且动作与 review_configs 按位置匹配。[审批策略与校验](../../../../packages/harness/shikigen/core/approval.py)。
- 审批 POST 先提交 approval_resolved 与 running 事实，再继续同一 Run 并返回 SSE；观察断开不撤销已经接收的响应。409 返回冲突和同 Run stream 路径，422 为响应校验错误，503 带 Retry-After。[Run 路由](../../../../app/routes/run.py)、[运行转换](../../../../packages/harness/shikigen/runtime/runs.py)。
- 取消 POST 对 running / interrupted 提交 cancelled；等待审批时还提交 approval_invalidated。若 Run 已是终态，则返回已有终态，不覆盖先发生的结果。[运行转换](../../../../packages/harness/shikigen/runtime/runs.py)。
- 取消先保存并发布事实，再通知本地执行协作停止；接口返回不是外部工具副作用已经回滚的保证。[运行执行](../../../../packages/harness/shikigen/runtime/run_execution.py)。
- 当前前端只提示等待审批，尚无审批表单、审批 POST 和取消操作入口。[应用入口](../../../../frontend/src/App.tsx)、[HTTP/SSE 客户端](../../../../frontend/src/backend-client.ts)。
- PRD 已要求内嵌审批、完整参数、全部动作选择后一起提交、工具栏定位入口和一次取消确认。样式继续使用现有细边框、浅色区块、靛蓝主按钮与琥珀提示。[PRD](../../../frontend/frontend-prd.md)、[当前设计规范](../../../../frontend/design.md)。

## 2. 已确认：逐项选择的初始状态

## 3. 已确认：拒绝原因可选并保留编辑内容

用户选择：“原因可选，切换选择时保留文字（推荐）”。拒绝时显示可选文本框；切到批准时隐藏但保留文字，切回拒绝继续编辑。批准的提交仅包含 type，不携带拒绝原因；未填写原因的拒绝不强制生成说明。

## 4. 已确认：参数默认折叠

用户选择：“默认折叠参数，点击后查看完整内容”。动作的工具名称、说明、允许决策和选择控件保持可见；参数默认折叠，点击后展示完整 JSON，不以截断摘要替代原始参数。参数查看和复制复用现有区块与只读详情样式，不将审批选择放入详情层。

## 5. 已确认：审批草稿跨重启保存

用户选择：“跨重启保存，核实同一请求后恢复（推荐）”。按会话本地保存未提交的审批选择和拒绝原因；切换、刷新、重开应用或宿主改变后先 GET 核实。只有 Run、checkpoint、Interrupt 和动作内容都一致时才复用；新请求默认未选择，绝不自动提交。

## 6. 已确认：审批与取消在请求确认前互斥

用户选择：“请求确认前互斥，核实后恢复操作（推荐）”。发出审批或取消时防重复点击，暂时禁用同 Run 的另一操作及审批编辑。审批收到本次 POST 的有效 metadata，或取消收到有效快照后结束请求 pending，不等待整段 SSE 结束。请求失败先 GET 核实实际事实，再恢复对应操作；不自动重发 POST。

## 7. 已确认：底部定位审批，卡片统一提交

用户选择：“使用确认弹窗（推荐）”。每次取消先显示沿用现有样式的弹窗，说明“取消不会撤销已经发生的工具操作”；按钮为“继续运行”和“确认取消”，默认焦点在继续运行。Esc 或关闭只撤销本次确认意图，不发出取消请求。
