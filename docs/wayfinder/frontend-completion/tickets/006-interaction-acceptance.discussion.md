## 3. 执行期间编辑草稿：已确认

**做什么：**确定运行中及等待审批时是否允许编辑下一条消息草稿。

**为什么：**[PRD 7.3](../../../frontend/frontend-prd.md)要求禁用输入框，模板实际仍可编辑；已确认的运行投影契约要求按会话保存草稿，但把执行期间可编辑性留给本票据决定。

**API：**编辑本身只更新本地草稿；发送资格沿用已确认的宿主 ready、当前状态已核实、无提交 pending／结果待确认、无 running／interrupted 条件。只有用户主动发送才调用 `POST /api/threads/{thread_id}/stream`。

2026-10-04 已向用户提出：运行中或等待审批时，是否允许编辑下一条消息草稿？推荐允许编辑并保存，但禁止发送、不排队、不自动发送；底部主操作仍为“取消运行”或“处理审批”。这会调整 PRD 当前“输入框禁用”的规定。

用户答复：“允许编辑草稿，结束后手动发送（推荐）”。

已记录到[交互与验收阶段契约](006-interaction-acceptance.contract.md)，并同步 PRD 更新说明和 design.md 输入区规则。运行中／等待审批不禁用草稿编辑；普通发送继续禁用，不新增队列，也不因终态到达自动发送。草稿保存和接受后按版本清空沿用已定投影契约。

## 4. 输入正文与 Enter 边界：已确认

- PRD 已明确 Enter 发送、Shift+Enter 换行、组合输入期间不发送、空白消息不可发送，直接纳入实施要求。
- 当前 [App](../../../../frontend/src/App.tsx) 的发送入口对草稿调用 trim()，会删除首尾空白。[ChatRequest 与发送路由](../../../../app/routes/run.py)直接传递 body.message；[RunManager](../../../../packages/harness/shikigen/runtime/runs.py)创建 HumanMessage 时替换无效 Unicode surrogate，但没有裁剪首尾空白。
- 已确认的消息契约要求用户正文保留换行、空白和符号，因此需要明确发送前是否保留首尾空白。建议 trim 只用于判空，实际提交和保存接受情况使用原文。
- 用户答复：“只判空，原样发送正文（推荐）”。此项已确认：trim 只用于空白判定，实际 POST 和提交原文记录保留原始草稿，不删除首尾空白。

键盘实施要求沿用 PRD：Enter 仅在可发送且不处于组合输入时发出一次与按钮相同的发送动作；Shift+Enter 换行，不在组合输入确认时发送。发送请求期间可继续改写草稿，但不开放第二次提交；本次 POST 的有效 metadata 只清空对应草稿版本。

另向用户确认无法发送时的 Enter 行为，原建议为普通换行。用户明确选择：“不能发送时拦截 Enter，仅 Shift+Enter 换行”。以用户选择为准：无发送资格时拦截普通 Enter，不插入换行，也不触发发送、取消或审批；Shift+Enter 仍换行。组合输入事件优先交给输入法，不能为了拦截 Enter 而阻断候选确认；长按不能产生重复提交。快捷键细节及实机 IME 核对仍需后续统筹。

## 5. 临时会话标题：已确认

PRD 已规定服务端 title 缺失时显示“新会话”，打开后从首条 HumanMessage 派生本地临时标题；当前 hook 实际使用会话 ID 作为标题，没有派生或标题缓存。标题显示属于 UI 派生值，不改变会话／Run 身份。

建议优先使用真实服务端 title，否则从已读取的首条已提交用户消息提取短标题，并按会话 ID 缓存在本地、跨重启保留。打开该会话后按真实消息重新核对；新服务端 title 覆盖本地派生值。缓存失败保留内存显示，未取得消息时使用“新会话”。标题派生不取未发送草稿，也不以标题识别发送是否被接受。

用户答复：“本地缓存，跨重启保留（推荐）”。临时标题缓存已纳入本地保存范围；正文和会话身份仍以服务端事实为准。新增“临时会话标题”“消息草稿”词义写入 [CONTEXT.md](../../../../CONTEXT.md)，其中不记录缓存机制或其他实现细节。

## 6. 会话日期与显示时间：已确认

服务端 Thread 时间由 UTC ISO 8601 生成，见[数据库时间函数](../../../../packages/harness/shikigen/persistence/database.py)。PRD 要求以用户本地日期按“今天／昨天／更早”分组，用 updated_at 显示相对时间；当前模板仍显示原始 UTC 字符串。

建议一分钟内“刚刚”、不足一小时“N 分钟前”、不足一天“N 小时前”、不足七天“N 天前”，七天起显示本地日期；可查看完整本地日期、时间与时区。分组按本地日历边界计算，显示时间在可见时每分钟刷新并在重新显示时立即计算，不为刷新文案另发 HTTP。未来或无法解析的时间不补造相对值。

用户答复：“相对时间，7 天起显示日期（推荐）”。采用上述本地日历分组与相对时间规则，完整时间入口须可用键盘和触控到达；本地显示时钟刷新不改变 updated_at，不影响后端排序或 Run 状态。

## 7. 加载更早会话的入口：自动分页已确认

前置查询契约已固定每页 20 条、服务端更新时间倒序、第一页周期轮询与按 ID 合并，并将加载更多的游标与第一页轮询分开。当前 History 没有加载更多入口，初次空列表和过滤无匹配仍共用一个提示。

建议在会话列表底部提供“加载更早会话”按钮，用户每次点击读取一页；过滤只匹配已加载标题，标明范围，加载更多后按当前过滤继续显示；第一页轮询仍按既有规则执行。首次读取用等高 skeleton，更多页加载只在底部显示进度，失败原位重试且保留列表、选择和打开的对话。

用户选择：“滚动到底部自动加载下一页”。以此选择为准：会话列表到底后自动使用既有 next_cursor 读取下一页，主分页入口改为滚动触发，仍为每页 20 条，不改第一页轮询、ID 合并、已有分页位置与列表保留规则。

## 8. 自动分页与停止条件：已确认

过滤后可能只剩少量条目，没有足够高度产生滚动；单独依赖到底事件会使加载下一页和键盘操作不易到达。当前源码没有自动分页控制，需在实施时避免分页成功、空匹配或过滤变化引起连续请求。

建议自动分页为主，保留小型“加载更多”辅助入口。每次用户到达列表底部读取一页，请求期间不重叠；不因输入过滤、收到一页或结果未撑满视口就自动连续读完全部页。初次列表加载、底部加载、原位失败重试分别呈现，过滤仍明确限定已加载标题。

用户明确答复：“只用自动分页，如果加载的下一页不足20条，就停止加载下一页，并且显示‘没有更多’。”以用户要求为准，正常分页不提供“加载更多”按钮；失败的原位重试仍保留，不作为正常分页入口。

不足 20 条按服务端原始 data.length 判断，不能按过滤后的匹配数或 ID 去重后新增加的数量判断。next_cursor=null 同样结束分页，因此最后一页刚好 20 条也能显示“没有更多”；服务端应保证短页时 next_cursor=null，这表示查询当时该游标边界没有下一页，不承诺列表永久不再增长。

分页触发由列表到底及无过滤时填满可视区决定；过滤只作用于已加载标题，不因输入过滤而连续查询全部历史。内容不足以滚动时，用户继续向下滚动的意图与聚焦列表后的 End／PageDown 等到底操作仍可触发一页，不使用辅助按钮。请求 pending 不重叠，更多页加载或失败只改变底部状态；错误重试沿用既有分类和 Retry-After，底部可见不能造成无限失败重试。详细操作边界纳入最终契约核对。

## 9. 阅读位置：已确认

当前 Conversation 未维护跟随底部或会话阅读位置。PRD 已要求只有底部附近自动跟随，上翻时不能抢滚动；消息契约也要求本地图片与长工具输出不抢位置。

建议第一次打开会话定位最新，应用本次运行期间切回已看过的会话时恢复该会话上次阅读位置与跟随模式；应用重启后首次打开仍定位最新。用户上翻立即暂停自动跟随并显示“回到最新”，只有主动回到底部才恢复；新内容、图片加载与导航宽度变化保持正在阅读的消息锚点。用户主动成功发送可定位最新，“处理审批”按既有契约定位卡片。

用户答复：“首次最新，切回恢复阅读位置（推荐）”。采用按会话在本次应用运行期间保留阅读位置的方案；不跨重启恢复为历史位置。草稿、事实与阅读位置分别维护，窗口隐藏或 Workspace 卸载不主动丢掉本次阅读记录。

## 10. 空会话示例与已有草稿：已确认

PRD 已要求无会话时提供新建入口，空会话提供三条真实任务示例。当前 Conversation 的示例点击会直接调用 updateDraft(text)，已有草稿会被替换；示例本身不调用发送。

建议保留“只填写、不自动发送”的行为：草稿为空时填入示例并聚焦；已有草稿时把示例追加到末尾、以空行分隔并聚焦，不覆盖原文。任务示例基于已注册的目录／文件／检索工具，不使用伪造的运行结果。用户可自行编辑后发送。

用户答复：“保留原文，追加示例（推荐）”。采用填空或追加的方案，已有草稿保留原文；示例仅修改本地草稿，不能自动发送。现有三条任务示例对应目录／文件检索与网页读取能力；内置工具注册依据见[ToolRegistry](../../../../packages/harness/shikigen/tools/tool_registry.py)。

## 11. 命令面板内容与本地查找：已确认

用户答复：“搜索操作和已加载会话（推荐）”。命令面板采用本地搜索与两组列表，直接切换已加载会话；不增加全局服务端搜索。详情等不可用动作保留可读原因，不能执行隐藏的替代操作。

## 12. 全局快捷键范围：已确认

当前 App 在 window 上监听 Cmd/Ctrl+K、N，只检查组合输入，没有检查前景 dialog；B 尚未实现。原生 dialog 的焦点约束不会自动阻止 window 监听器。

建议 K／N／B 在草稿及普通搜索输入中也可用，分别调用命令面板、新建与导航动作；组合输入、长按及前景模态中不触发全局工作台动作。允许 K 关闭自身命令面板、B 关闭自身导航覆盖面板；其他模态不被这些键替换或关闭。Esc 只关闭当前层，按宿主展示 Cmd／Ctrl 并保留按钮。

用户答复：“输入中也可用，弹层有明确限制（推荐）”。采用上述输入可用、组合输入及前景模态受限的范围。快捷键与页面按钮共用可用性判断，不因键盘入口绕过创建 pending、Run 目标或发送限制。
