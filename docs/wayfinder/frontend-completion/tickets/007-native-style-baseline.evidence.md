## 1. 做什么、为什么、使用入口

- **做什么：**以用户指定的原稿为目标，核对项目截图与代码的比例和外观，指出补功能时需要恢复的原稿层级。

- **使用入口：**已有 Shikigen 原生窗口或用户提供的当前截图。原生启动入口为 frontend/ 中的 `pnpm tauri dev`，见 [frontend README](../../../../frontend/README.md)。样式核对不需要新增后端接口，业务呈现沿用已确认契约。

## 3. 尺寸对照

实施尺寸以 WebView 内容区 CSS px 表达，原生标题栏与图片像素分别记录。

| 区域 | 原稿／代码依据 | 截图近似表现 | 判断 |
| --- | --- | --- | --- |
| 展开导航 | 256 CSS px | 约 384 个图片像素 | 与约 1.5 倍缩放吻合 |
| 收起导航 | 64 CSS px | 约 96 个图片像素 | 同一缩放下保持原稿宽度 |
| 会话栏 | 256 CSS px | 两图均约 384 个图片像素 | 收起导航后仍独立保留 |
| 左侧总占用 | 展开 512、收起 320 CSS px | 展开约 768、收起约 480 个图片像素 | 主区按侧栏实际占用调整 |
| 网页应用栏 | 40 CSS px | 原生标题栏下约 60 个图片像素 | 原生标题栏与网页应用栏是两个区域 |
| 头像 | 28 CSS px | 约 42 个图片像素 | 头像列接近原稿 |
| 输入容器 | 内部最大约 840 CSS px | 约 1260 个图片像素，主区内居中 | 保持上限，居中位置随主区移动 |

边界尺寸来自人工查看原图，未逐边程序测量。结合总尺寸与代码，画面很接近 1440×900 内容区、约 1.5 倍显示；实际缩放尚未确认，这是推断，不能标作精确视口验收。2160 图片像素不直接作为 CSS 断点，字号也不按该倍数扩大。

## 6. 静态发现与未观测风险

- 768–1279px 导航仍强制 64px，按钮只切换 collapsed，256px 覆盖导航待实施。
- 折叠偏好先读 localStorage，缺值才按 innerWidth < 1440 决定；resize 不更新折叠状态，各宽度切换会写同一偏好，窄屏与桌面隔离待实施。
- 主按钮通用 hover 会覆盖靛蓝背景；两图没有悬停证据。
- 当前工具错误也复用 success 与勾号；两图展示正常结果，失败效果尚未观测。
- 详情没有专门的长 ID 换行规则，覆盖层固定从 y=40px 开始，未按托盘提示高度调整；实际溢出／遮挡未观测。
- 启动日志的 --surface-muted 未定义时回退 #F1F1EF；宿主页未取得截图，此处仍为源码事实。
