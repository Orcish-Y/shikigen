- [现有前端依赖](../../../../frontend/package.json)没有 Markdown 渲染库；库的选择与安全边界尚待写入完整方案。

## 用户逐项确认

### 正文按角色展示

用户选择：**Agent Markdown，用户原文**。

- Agent 回答支持段落、列表、表格和代码块。
- 用户消息保留原始换行与符号，方便核对实际发送内容。
- 工具输出采用下述独立规则。

### 工具输出保留原文与结构

用户确认推荐方案：**原文／JSON，不渲染 Markdown**。

- 工具字符串按原文展示，保留换行与符号，不把日志中的 Markdown 或 HTML 当作排版。
- content 数组按原顺序保留字符串与对象；结构化对象提供完整 JSON 只读查看，不能只抽取 text 字段而丢失其余内容。
- artifact 在有返回值时提供完整只读查看，不猜测图片、文件或可执行内容的含义。
- 展示、复制和导出均以接口实际返回的内容为范围。

### 工具调用与结果合并

用户确认推荐方案：**结果合并到调用卡片**。

- 调用卡片位于发起调用的 Agent 消息下方，多个工具按 tool_calls 原顺序排列。
- 通过 tool_call_id 匹配结果；结果到达顺序不改变工具卡片的排列顺序，不按工具名称或参数猜测关联。
- 找不到对应调用的 ToolMessage 保留为独立工具结果卡片，不丢弃结果。
- 卡片的合并只影响展示，完整调用与结果记录及其各自 seq 继续保留；正文消息按 seq 排列，结果更新到调用的展示位置。

### 工具卡片默认折叠，失败首次展开结果

用户选择：**默认折叠，失败首次展开结果**。

- 默认只显示工具名称与真实状态；展开卡片后查看结果，参数与 artifact 仍默认折叠。
- 收到 status=error 的工具结果时，首次自动展开对应卡片和结果区。
- 用户手动收起后，不因重复回放、更新或重新渲染再次自动打开。
- 失败状态依据 ToolContent.status；不能根据输出包含 Error 等文字推测状态。

### 长内容在区块内滚动

用户选择：**区块内滚动，并提供完整查看／复制**。

- 长代码、工具输出与 JSON 限制聊天中区块的高度，在区块内滚动；不因为视觉限制截断前端保存的数据。
- 完整查看沿用当前桌面抽屉与窄屏底部面板，只读展示接口返回的全部内容。
- 复制完整内容，不含行号、状态文案或界面上的省略标记。
- 详情打开和关闭只影响阅读，不改变运行、观察连接或审批操作。

### 取消与失败也保存消息

用户明确要求：**取消或者失败也需要保存完整消息**。

- 目标改为后端保存已经生成的正文，重新进入会话后可以读取；已保存内容进入已提交消息的导出范围。
- 先前“只在屏幕保留未保存片段、重开不保证恢复”的推荐方案未获确认，不作为最终规则。

用户随后选择：**保存正文，并给中止消息独立标记**。

- 保存截至后端停止接收该消息时已经接入的全部正文，不等待模型补写剩余回答。
- 中止的消息显示“因取消中止／因失败中止”；同一运行里已经正常生成的消息保持其原有完成语义。
- 正文保持原样，中止标记独立保存，不把提示文案拼进正文。
- 中止消息落库后属于已提交消息，可以通过历史和 SSE 完整消息恢复，也纳入会话导出。
- 原消息身份、预留 seq、原子结算、重复／迟到事件以及保存失败的处理需要在完整契约中明确。

### 明确文本块与未知对象

用户选择：**识别明确文本块，其余完整 JSON**。

- 字符串与 type=text 且 text 为字符串的对象，其文本按所属角色展示：Agent Markdown、用户原文、工具原文。
- 文本块包含额外字段时，同时提供完整原始 JSON 查看，不仅保存或复制 text 字段。
- 未知类型、无法按明确文本格式识别的对象显示完整 JSON，不因具有 text 字段就将其他内容丢弃。
- 保留数组原顺序，不猜测图片、文件或其他媒体语义。

### 导出消息与完整工具记录

用户选择：**消息与完整工具记录**。

- 导出当前会话在点击时已加载的已提交用户、Agent 与工具消息，包含工具参数、结果、状态和实际返回的 artifact。
- 已保存的中止消息包含正文和独立中止原因；本地草稿、仍未落库的预览和未提交审批选择不进入导出。
- 使用点击时的消息快照，并在文件中标明已加载范围，不宣称包含服务端全部历史。
- 首版不导出审批或其他运行事件；这些真实事件由运行详情呈现。

### 网页链接、本地图片与文件打开

用户确认网页链接使用系统默认浏览器，并补充要求：**本地图片自动加载，文件点击可以打开，打开前需要确认弹窗**。

- 先前“所有非网页地址均只读、所有 Markdown 图片均不自动加载”的建议已被用户修正，不作为最终规则。
- 本地图片预览和本地文件打开纳入首版；当前尚无对应文件访问桥接，需要补齐。
- 本地路径解析范围、图片来源格式、资源访问契约以及确认弹窗的目标绑定仍需确定。

用户随后选择：**仅当前 Agent 工作目录**。

- 本地图片和文件链接仅访问当前 Agent 的工作目录 workspace_root。
- 相对路径与现有文件工具使用同一根目录；目录内图片自动显示，文件每次经确认后打开。
- 不扩展为任意本地路径访问；图片／文件引用的识别入口及对应桥接仍待确定。

用户随后选择：**仅识别 Agent Markdown 明确链接**。

- 使用 Agent Markdown 中明确的图片语法和文件链接作为入口，例如 `![预览](images/result.png)`、`[报告](reports/result.pdf)`。
- 工具原文、代码和未知 JSON 保持原样，不自动猜测裸路径或媒体语义。
- 目录内本地图片自动预览；文件链接每次确认后用系统默认程序打开。
