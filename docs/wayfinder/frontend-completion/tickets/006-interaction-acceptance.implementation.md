# 首版聊天工作台实施与验收顺序

日期：2026-10-04。所属票据：[确定首版交互补全与验收顺序](006-interaction-acceptance.md)。状态：用户已完整确认，实施与验收顺序定稿；八批任务均待实施，应用验收尚未进行。决议见[交互与实施收尾决议](006-interaction-acceptance.resolution.md)。

本文件负责实施分批、依赖与验收覆盖。产品行为以各票据的契约为准，不从任务完成度反向改写契约。完整交互记录在[交互与验收契约](006-interaction-acceptance.contract.md)，整体确认见[收尾核对](006-interaction-acceptance.review.md)，源 PRD 见[首版 17 条验收标准](../../../frontend/frontend-prd.md)，视觉见 [design.md](../../../../frontend/design.md)。

## 1. 架构位置与实施原则

后端负责持久会话／运行／消息／事件，以及审批恢复和取消的真实结果。Tauri 负责宿主启动身份、窗口可见状态和受控系统打开。BackendSession 负责当前地址租约、HTTP／SSE 边界、结构化错误及请求失效。工作台数据层保存按会话隔离的事实、观察预览与本地输入，UI 从这些数据派生可用操作、列表和阅读状态。

用户主导代码实现。每批先讲该模块的位置、做什么／为什么／用什么 API，再由用户实现；需要助手写代码或修 bug 时另行明确委托。规划定稿不表示代码已完成，已有 Windows 宿主能力作为基线继续使用。

按能实际走通的工作路径分批：先读取与发送，再审批／取消，随后完整内容、资源、详情和交互收尾。样式从各批新增组件开始遵守原稿基准；最后一批集中复核整体比例及所有内容区视口，不把视觉要求推迟到最后才使用。

可以提前实现独立模块。实际依赖是查询与客户端边界先于消费 UI、稳定投影先于审批／详情消费、中止正文原子结算先于“取消后内容已保存”的承诺、资源接口与受控桥接先于本地预览／打开；建议顺序不限制用户自主安排。

## 2. 已确认的实施任务

### 会话定位与只读查询

**做什么：**补固定 20 条的会话游标分页、run_id／run_status 摘要、历史外层 run_status、Run JSON 快照和完整事件查询；接入客户端边界、真实会话列表与历史定位。补取得窗口可见状态所需的 Tauri 桥接，使轮询和观察可以遵守隐藏暂停规则。

**为什么：**前端首先要能知道正在查看谁、当前状态来自哪里，并区分宿主 ready、历史读取和观察连接；这是发送资格、审批恢复、用量摘要及详情读取的共同基础。

**API／位置：**`GET /api/threads`、`GET /api/threads/{thread_id}/messages`、新增 Run snapshot／events；后端 [Thread 路由](../../../../app/routes/thread.py)、[Run 路由](../../../../app/routes/run.py)、查询与持久层；前端 [BackendSession](../../../../frontend/src/backend-client.ts)、[会话数据层](../../../../frontend/src/useConversations.ts)。Tauri 新增 `get_workspace_visibility` 和 `workspace-visibility-changed`，返回／推送 `{revision, visible}`，先订阅再查询，窗口可见性与焦点分开；沿用既有宿主状态桥接。

**完成证据：**20／21／多页与相同更新时间的排序可判定，自动分页原始短页／空游标终止且显示“没有更多”；周期性第一页按 ID 合并，不清其他页、不改变选择与分页游标；隐藏暂停／重新显示刷新；JSON 查询不执行 Graph、不产生审批或取消写入，身份错误与 404／422／503／500 能被区分。

**依据：**[会话与运行查询契约](001-run-discovery.contract.md)、[运行投影与恢复契约的窗口可见桥接](002-run-projection.contract.md)。

### 运行投影、恢复与输入

**做什么：**将事实、预览、观察代次和本地提交记录的所有者移出可卸载的 Workspace；完整接入 SSE、全量 GET 重建、受限自动恢复、手动核实和按会话持久草稿；完成原文发送与输入／IME 行为。

**为什么：**后续审批、消息卡片和详情都依赖同一份运行事实。应先解决切换、迟到、失败和接受情况未知，再把这些规则复用于更多 UI。

**API／位置：**既有 Thread stream POST 与 Run stream GET，BackendSession 请求信号、SSE parser、会话数据层、App／Composer，以及窗口可见状态桥接。新增快照为纯读补充，不替代等待审批所需的全量 GET 校验。

**完成证据：**真实用户任务可发送并流式显示；完整消息覆盖预览且不重复；旧回调不能污染新会话；hidden／switch 只停止观察；普通 EOF 与 running 意外 EOF 分开；观察自动 GET 恢复遵守 1／2／5 秒及三次上限，列表五秒轮询不叠加该重试任务；发送 pending／结果未知不会自动重发，草稿跨重启保留且有效 metadata 不清除新版本。

**依据：**[运行投影与恢复契约](002-run-projection.contract.md)与本票据输入规则。

### 审批、取消与中止消息结算

**做什么：**先补后端取消／失败时已接入非空 AI 正文的原子保存，再接入完整审批卡片、选择恢复、取消确认和请求互斥。

**为什么：**用户取消后立即重开会话，应同时看到真实终态与已保存的生成内容。先完成原子结算，可以让前端审批／取消的正常路径和竞态核实都基于真实持久事实。

**API／位置：**Run 状态提交、消息缓冲及事件持久层；既有 approval-decisions POST、cancel POST、Run GET stream 与 JSON 快照；聊天审批卡片、底部操作、原生 dialog 和本地审批草稿。

**完成证据：**审批工具执行前停住；用户逐项批准或拒绝后沿用同一 run_id；同一请求重启后核实恢复选择；提交与取消 pending 互斥；取消与自然完成竞争按首个真实终态显示；取消／失败后重新读取仍有完整已生成正文和独立中止标记；提交回滚不展示虚假的保存成功，迟到事件不改终态。

**依据：**[审批与取消交互契约](003-approval-cancel.contract.md)、[消息与本地资源契约的中止保存规则](004-message-tools-export.contract.md)。

### 完整消息、工具与 Markdown 导出

**做什么：**保留公开消息完整字段，接入 Agent Markdown、用户原文、未知块 JSON、tool_call_id 关联的参数／结果／artifact、完整查看与复制，以及点击时已提交快照导出。

**为什么：**目前模板的 flatten 会丢字段，工具内容和导出范围也不完整。呈现层须能解释真实事实，而不能靠展示方便裁剪原始记录。

**API／位置：**历史与 SSE 完整消息；Conversation、工具／代码区块、共用只读前景面板、Clipboard 和 UTF-8 Markdown Blob 下载。采用已确认的 Markdown 渲染方案，网络／本地资源入口按下一批接入。

**完成证据：**重复／乱序回放、内容块原顺序、额外字段和空值保留；失败工具首次展开结果但尊重用户收起；长代码／JSON 完整复制；未提交预览不导出；中止正文、参数、工具结果和 artifact 导出完整，原文不能破坏导出记录边界。

**依据：**[消息、工具、导出与本地资源契约](004-message-tools-export.contract.md)。

### 工作目录资源与系统打开

**做什么：**补纯读工作目录／资源解析／图片读取接口及受控 Tauri 打开桥接，再连接 Agent Markdown 的本地图片自动预览、图片详情和每次文件打开确认。

**为什么：**图片自动展示和系统打开会跨越聊天内容、后端工作目录及原生能力三个边界。路径、真实目标、文件版本和本次启动身份需要在进入 UI 前取得可核实的结果。

**API／位置：**已定 workspace／resolve／image HTTP 契约，`open_web_url`、`prepare_workspace_file_open`、`open_prepared_workspace_file` 受控命令；资源 Blob／租约释放、文件确认与单一前景模态。

**完成证据：**目录内支持的图片可预览；越界、缺失、变更、过大和不支持格式分别反馈；文件每次确认并以系统默认程序打开；确认后目标变更或租约失效重新核实；取消确认没有系统打开；加载／失败不改变 Run 状态，图片展开不抢上翻阅读位置。

**依据：**[工作目录资源与系统打开契约](004-message-tools-export.contract.md)。

### 运行详情、用量与事件

**做什么：**接入进入会话的快照、按需事件读取、运行／连接／查询错误分区、真实用量和结算提示、有限后续核实，以及可复制的完整事件。

**为什么：**用户需要知道任务结果和统计是否结算，不能把未知当零，也不能因取消终态就认为用量必定已保存。该批复用前面已完成的查询边界和事实投影。

**API／位置：**Run snapshot／events、SSE metadata／events、取消返回快照；History 底部“本次运行用量”、详情 drawer／sheet、共享请求协调与计时器。

**完成证据：**未知和真实零分开，calls／by_model 如实展示；迟到快照不覆盖新阶段／新字段；取消后 usage 仍能补齐；正常 EOF 与取消补读不造成重复请求；后续核实遵守 5 秒、12 次及错误重试上限；drawer 关闭不停止 SSE，事件按事实去重并保留完整内容。

**依据：**[运行详情、用量与事件契约](005-run-details.contract.md)。

### 会话浏览、命令、响应式与视觉收尾

**做什么：**完成标题／日期／相对时间、列表加载与空状态、阅读位置、键盘与命令面板、桌面偏好／窄屏覆盖，以及整体比例和原稿层级复核。

**为什么：**前面各批已经能完成真实操作，本批集中核对这些操作在导航变化、长内容、键盘和小内容区下仍能到达，并把剩余模板行为替换为已确认产品规则。

**API／位置：**现有列表／消息／状态、共享页面动作、localStorage、dialog、滚动／视口能力、App／Sidebar／Conversation／styles.css。新控件沿用白色／Slate／Indigo、既有字体与图标系统。

**完成证据：**本票据最终契约逐项落实到下节矩阵；仅自动分页、原始短页终止、输入原文与 Enter、阅读锚点、本地命令与受限快捷键符合约定；1440×900、1280×800、1024×768、390×844 均可发送／审批／取消／重连，手机单菜单默认会话列表，桌面主动偏好不被窄屏覆盖，菜单两态一致，长内容不撑宽，顶部／底部提示不挡必要操作，触控与焦点可用。

**依据：**本票据最终契约、[视觉基准决议](007-native-style-baseline.resolution.md)与 [design.md](../../../../frontend/design.md)。

### 首版联合验收

**做什么：**按下面矩阵在真实 Windows Tauri 应用中验证完整路径、错误、重放、竞争、结算和各档内容区视口；记录实际结果与证据。

**为什么：**静态代码、示例预览、规划关闭或单个接口成功均不能证明首版流程和原生交互完成。

**API／位置：**复用各批已有接口、宿主日志和当前工作台。本文只安排以后验收，没有新增或运行测试／构建。

**完成证据：**各项具有可复查的预期／实际、数据身份和实机记录。未执行项保留“待验收”，失败项对应用户后续实现任务；验收发现新的产品问题时再开独立决策，而不能用模糊的“基本可用”代替已确认要求。

## 4. 用户新增要求与跨项场景

| 场景 | 必须观察的结果 | 主要责任任务 |
| --- | --- | --- |
| 取消／失败后重开 | 已接入非空 AI 正文完整保存，独立 generation_status／原因；不造未完成工具调用 | 中止消息结算；消息呈现 |
| 终态／写入竞争 | 正文封口、Run 终态与生命周期同事务；回滚无假成功；first terminal，迟到数据不改结果 | 中止消息结算 |
| 工作目录本地图片 | 仅 Agent 明确 Markdown 引用自动读取，支持格式预览，错误贴近图片，上翻位置稳定 | 工作目录资源；阅读位置 |
| 本地文件确认打开 | 真实路径可完整复制，每次确认、默认取消；变化／过期／租约失效核实；正常取消不开文件 | Tauri 打开桥接；模态 |
| 原文与草稿版本 | 首尾空白保留，全空白禁发；请求确认前新草稿不被迟到接受覆盖，旧原文可核对 | 输入；投影 |
| 跨重启本地恢复 | 草稿恢复为文字；审批选择先核实同一请求；本地持久数据不恢复为有效观察或执行 | 投影；审批 |
| 同 Run 审批多次 | checkpoint／Interrupt／动作内容变化后重新选择，不复用旧可提交身份 | 审批；投影 |
| 用量晚结算 | cancel 后终态不变，usage 可补齐；字段省略与 explicit null 分开，计时器受限 | 详情；请求协调 |
| 窗口隐藏／宿主换租约 | GET／轮询暂停，实际 Run 不 cancel；显示恢复，旧 startup 结果全部失效 | Tauri 可见状态；投影 |
| 长内容与提示并存 | 320px 区内代码／JSON、长参数／artifact／路径，输入增高及 TrayNotice 并存仍可阅读操作 | 各组件；视觉收尾 |
| 模态与键盘／触控 | 单前景模态、Esc 关闭当前层、关闭返回有效焦点；关键字号／44px 点击目标、中文输入法 | 模态；交互收尾 |
| 明确异常与未知响应 | 每个读取／提交／资源错误在所属区域显示；保留事实与草稿，不从未识别错误造 Run 终态 | 各操作边界；联合验收 |

- 每项记录场景、thread_id／run_id／必要启动身份、预期结果、实际结果和截图／日志位置；正文可读性、滚动和焦点需用真实操作检查，静态截图不足以证明。
- 验收包含真实模型正常运行、工具审批、拒绝、running／interrupted 取消、断流／重连、刷新／重开、会话切换及迟到／重复／竞争／用量结算。用于排查的示例或可控场景须注明范围，不宣称真实路径已通过。
- 按任务分别记录“待实施／实施中／待验收／已验收”。规划票据 closed 和地图 closed 均不代替上述完成标记。
- 新异常或实机阅读问题若只是实现缺陷，进入实施修正；若需要改变已确认产品规则，再建立新的决策记录。实施前可以明确的规则须在本票据定稿，实测才能知道的具体缺陷留在实施后。
