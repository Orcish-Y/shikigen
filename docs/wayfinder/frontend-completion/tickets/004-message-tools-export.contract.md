## 1. 做什么、为什么、用什么 API

| 做什么 | 为什么 | API / 数据 |
| --- | --- | --- |
| Agent Markdown、用户原文、工具原文／JSON | 让真实内容进入当前模板，保留完整数据 | 现有 Thread/Run messages 和 SSE message event |
| 关联工具调用与结果，展示真实状态与附加数据 | 用户能核对每次调用的参数和输出 | AI tool_calls 与 Tool tool_call_id / status / artifact |
| 取消／失败时保存已生成内容及中止原因 | 重开会话和导出后仍能读取这些内容 | 后端消息接入、取消和失败结算；AI generation_status 新字段 |
| 自动预览工作目录内的本地图片 | 显示 Agent 明确引用的本地图片 | 新增工作目录与只读资源 HTTP 查询、图片响应 |
| 网页在系统浏览器打开，文件经确认后打开 | 保持聊天工作台，明确本地文件打开意图 | 待新增的 Tauri 受控打开命令，内部使用 opener |
| 导出点击时已加载的已提交消息 | 得到范围明确、可核对的会话记录 | 本地快照、Markdown 序列化、Blob 下载；不新增导出 HTTP |

## 2. 数据所有者与消息身份

- 前置契约中的事实投影保存全部已提交消息；预览继续独立积累，不能因为 Run 已终结就由前端自行改成已保存消息。
- 保留 thread_id、run_id、seq、message_id、完整 content、tool_calls、tool_call_id、name、status、artifact 及实际提供的其他公开字段。区块折叠不改变数据。
- 消息事实按会话 seq 合并、排序和去重；同 seq 完整事实替换预览。多个同 seq delta 仍按到达顺序追加，不按文本去重。
- 工具关联以同一会话、同一 Run 的 tool_call_id 为准；不按名称、参数相似性或结果到达顺序匹配。
- 本地资源解析和打开绑定工作目录及地址租约；结果过滤沿用选择代次与租约规则，不回写另一个会话。

### AI 消息的生成结果

在 AIContent 中新增 generation_status；HumanContent、ToolContent 和 Run.status 保持各自含义。

| generation_status | 含义 | 消息显示 |
| --- | --- | --- |
| complete | 正常产生的完整 Agent 消息 | 正常正文，不加中止标记 |
| cancelled | 取消结算时保存的已有生成内容 | 因取消中止 |
| error | 失败结算时保存的已有生成内容 | 因失败中止 |

- 新写入 AI 消息显式提供该字段；旧消息缺省按 complete 兼容。幂等比较也按这一缺省语义处理，不能因为新增字段而让旧 checkpoint 的正常历史重放产生内容冲突。未知枚举值按协议问题处理，不猜测成正常完成或某种中止。
- 字段与 AIContent.content、tool_calls 同级，通过历史、Run messages 和 SSE message payload 一致提供；SSE 路径为 data.payload.generation_status，不新增 latest_run 包装。
- 中止提示在正文外显示，正文保留原样。同一 Run 中已正常提交的消息仍为 complete；Run 后来取消或失败不改写这些消息。
- ToolContent.status=error 不等同于 Run 失败，也不把某条已完成 AI 消息改成中止消息。

## 3. 取消／失败时保存生成内容

### 保存范围与边界

- “完整保存”指保存后端截至结算停止接收时已接入的全部正文；不等待模型补写剩余回答。
- 后端为所有有非空正文、尚未提交的 AI 消息保留原 message_id 和预留 seq；按原顺序拼接已接入片段，不裁剪空白、不另造消息身份或追加结束文案。
- 已提交的完整用户、Agent 和工具消息原样保留。没有产生正文时不创建空白中止消息。
- 当前公开 delta 只提供正文，不补造尚未完整提供的工具名称、参数、tool_calls 或 reasoning。中止消息不能构造可执行的部分工具调用。
- 断开观察、隐藏窗口、切换会话或客户端 Abort 不触发封存；只有后端实际取消或失败结算产生对应中止消息。
- 等待审批本身不属于消息生成中止。

### 原子提交与竞态

1. 后端协调消息接入与终态结算，确定停止接收的边界，取得尚未提交正文。取消不能只改变 Run 状态而遗失已接入正文。
2. 同一事务提交中止 AI 消息、Run 终态、对应生命周期事实和必要审批失效事实；中止消息写入使用已有预留 seq，不能调用只会分配新 seq 的通用事实路径。
3. 事务成功后发布完整消息与终态事实，再按既有取消协议请求协作停止。取消成功快照表示这些正文已经与终态共同提交，不等待所有工具副作用停止。
4. 与正常完整消息竞争时，以已成功提交的事实为准：正常完整消息先提交则保留 complete；封存先提交则保留中止正文和原因。迟到片段或旧 Graph 快照不能改写同一消息。
5. 取消与失败竞争继续服从第一次有效 Run 终态；后续结算不能重复创建消息或更改已经保存的中止原因。用量后续结算仍沿用原规则。

- 消息封存状态必须在成功提交后更新；事务回滚时保留尚未落库的正文，不能先清空缓冲。
- 存储不可写时不能宣称取消／失败消息已保存；沿用结构化错误和观察故障反馈。后端保留可重试的结算数据及其执行所有者，不能先销毁唯一正文缓冲；纯 GET 查询不承担补写职责，也不重跑模型或工具。
- 封存记录属于产品历史，不伪造 Graph 正常完成或自动继续执行。后续 Graph 根快照重复包含已封存历史身份时，不能把它作为新 Run 的新消息补写或覆盖原记录。
- 本目标覆盖能够进入结算的取消／执行失败；强杀进程前仅在内存中的片段不具备跨进程恢复保证，相关持久执行能力仍属地图的后续范围。

### 前端取得保存结果

- 收到完整中止消息后，用同 seq 事实替换预览，停止生成光标，显示中止标记，开放正常消息复制与导出。
- 获得终态时补读一次现有 GET Run messages，补齐可能未收到的最后消息。重复终态帧不反复发起同一次补读；请求仍受地址租约与目标检查约束。
- 终态已经确认、完整消息尚未读到时，可以保留现有正文并显示“正在读取已保存内容”；此时仍不是前端已确认的消息事实，不进入导出。
- 补读失败保留现有内容，显示实际读取错误并提供手动读取；不自动重复 POST，不改变 Run 终态，不以客户端预览补造后端消息。

## 4. 正文、内容块与 Markdown

| 内容 | 首版呈现 |
| --- | --- |
| Agent 字符串正文 | Markdown 段落、标题、列表、引用、表格、任务列表与代码 |
| 用户字符串正文 | 原文，保留换行、空白和符号 |
| 工具字符串正文 | 原文，保留换行和符号，不渲染 Markdown |
| type=text 且 text 为字符串的对象 | 文本按角色展示；额外字段通过完整原始 JSON 查看 |
| 其他对象或未知内容块 | 完整 JSON 只读展示，不只提取 text |

- content 数组按原顺序展示；不跨未知对象拼接 Markdown 结构。完整原始数组始终可查看和复制。
- 空字符串、空数组和 null 与字段省略按原数据保留。空工具输出说明“已返回，正文为空”，不因没有文字改成等待结果。
- 运行中的正文预览使用同一安全 Markdown 规则，并明确处于生成中；完整事实到达后重新以完整正文呈现。

### 安全渲染方案

- 实施组合采用 react-markdown、remark-gfm、rehype-sanitize；复用当前 React 组件与样式，不安装或启用执行 Markdown 中代码的能力。
- 原始 HTML 节点先转为文本，随后对渲染树按允许列表净化；不启用 rehype-raw、MDX、脚本、iframe 或表单。
- 允许列表仅保留首版正文所需结构与受控样式。任务列表为只读；消息中的勾选不变成可提交表单。
- 标题按当前聊天正文层级排版，表格在自身区块横向滚动；脚注标识绑定消息身份，避免跨消息跳错位置。
- 本地图片／文件引用在 Markdown 解析阶段识别为受控资源入口；原始路径不直接交给浏览器 href/src。解析保留 Windows 路径信息，不能让通用 URL 转换丢掉盘符后再猜路径。
- 网页链接只接受明确的 http/https；其他未支持协议提供只读文字和复制，不执行。网页图片不自动请求。
- Markdown 解析或组件呈现失败时保留原文供读取和复制，展示局部错误，不使整段会话消失或改写 Run 状态。

## 5. 代码、JSON 与完整复制

- 真实 Markdown 代码块进入当前 code-block 外观：Slate 浅灰底、1px 边框、8px 圆角、JetBrains Mono、标题与复制按钮；首版沿用当前单色代码文字。
- 语言标记只显示原内容明确提供的值；没有时显示“代码”。文件名只在内容明确提供且格式可识别时展示，不猜测文件名。
- 行号由代码计算并仅作展示；复制代码保留代码本身的完整换行和缩进，不含围栏、行号、状态或界面省略号，不通过渲染后的 DOM 反推原文。
- 长代码、工具输出与 JSON 的聊天区块最高约 320px，内部滚动；宽内容只在所属区块横向滚动，不撑宽会话。
- “查看完整内容”沿用桌面 400px 覆盖抽屉、窄屏底部面板，只读显示完整数据；关闭不改变观察、草稿或审批选择。
- 字符串复制原字符串；对象／数组复制完整格式化 JSON。正文为块数组时另提供“复制完整内容”，复制完整原始数组，不丢失非文本字段。
- JSON 不自动打开其中链接、文件路径或媒体。未提交预览的复制文案为“复制当前片段”，不声称它已经保存。
- 复制成功后显示“已复制”；失败显示“复制失败，可手动选择”，保留文本可选中能力。

## 6. 工具卡片与附加数据

- 调用卡片放在发起调用的 Agent 消息下方，按 tool_calls 原顺序排列；结果通过 tool_call_id 更新对应卡片。
- 合并仅影响阅读位置，原调用与结果记录及各自 seq 保留。结果不再伪装成第二条 Agent 回答。
- 无法找到唯一对应调用时保留独立工具结果卡片，显示真实 tool_call_id 和“未找到对应调用”；不猜参数或丢弃输出。
- 工具名称以调用记录为标题；结果自带不同名称时保留原值供详情核对。

| 事实 | 标题状态 | 展开内容 |
| --- | --- | --- |
| 尚无 ToolMessage | 等待结果，中性色 | 已知调用参数 |
| ToolContent.status=success | 已返回，绿色勾号 | 实际返回正文及原 status |
| ToolContent.status=error | 工具失败，错误文字与匹配图标 | 实际失败正文及原 status |

- “已返回”表示工具消息已返回，不推断命令退出码、任务目标达成或整个 Run 成功；内容出现 Error 等文字不改变记录中的 status。
- Run 已结束但未收到工具结果时，保留“等待结果”，同时说明所属 Run 已结束；不持续动画，不编造取消或失败 ToolMessage。
- 工具卡片默认折叠。首次遇到失败结果时打开卡片与结果区，参数及 artifact 仍折叠。
- 当前应用内按稳定调用身份保存展开选择，切换回来继续保留；用户手动收起后，重复回放、更新或渲染不再次自动打开。重启后重新应用默认展示规则。
- 参数提供完整 JSON、完整查看和复制，不提供另一套审批控件；批准／拒绝统一在已定审批卡片完成。
- 非 null artifact 显示“附加数据”折叠区，包含空字符串、0、false、空对象／数组；省略或 null 不展开空区，原始完整记录仍保留其区别。
- artifact 始终只读、完整，不推测文件、图片或媒体语义；首版本地资源入口采用下节明确的 Agent Markdown 引用。

## 7. 工作目录内的本地资源

### 路径与入口

- 仅识别 Agent Markdown 中明确的图片语法和本地文件链接，如 `![预览](images/result.png)`、`[报告](reports/result.pdf)`。不识别用户原文、工具原文、代码或任意 JSON 中的裸路径。
- 相对路径基于当前 Agent 已绑定的 workspace_root；不是 Vite 目录、Tauri 页面地址或浏览器当前 URL。
- 原引用可为相对路径、绝对本地路径或 file URI；统一转为本地路径后规范化，检查实际解析目标仍在当前工作目录内。目录外目标和指向目录外的链接不读取、不打开。
- 后端工作目录在装配时解析并与文件工具共用；不随进程 cwd 变化重新解释根目录。只提供必要目录信息，不向前端暴露完整配置或凭证。
- 资源身份绑定 workspace_id、后端启动租约、规范路径与文件版本。后端或工作目录更换后旧资源身份失效，重新解析消息中的原始引用。
- 历史相对引用也按当前工作目录解析，详情显示实际路径；本地内容来自当前磁盘，不宣称是生成时的图片或文件快照。

### 待新增的只读 HTTP 契约

| 查询 | 返回 / 行为 |
| --- | --- |
| GET /api/workspace | data: {workspace_id, root}；root 为与工具共用的规范绝对目录，workspace_id 为当前绑定的 opaque 身份 |
| GET /api/workspace/resources/resolve?path=... | data: {workspace_id, resource_id, absolute_path, relative_path, name, kind, mime_type, size, modified_at, can_preview}；仅解析存在的普通文件，不读取或执行任意配置 |
| GET /api/workspace/resources/{resource_id}/image | 返回允许预览的图片二进制；再次校验当前工作目录、文件与版本，不返回任意文件的活动网页 |

- path 作为结构化参数编码；kind 首版为 file，目录引用提示暂不支持文件打开。resource_id 仅对当前后端绑定有效，不作为持久 Run 实体。
- mime_type 未知则为 null；size、modified_at 来自实际文件，不能仅根据后缀断言图片已存在或可读。
- 请求不创建 Run、不调用 Graph、不运行工具、不修改文件。它们与前置纯读 Run 查询分开，不让资源读取触发恢复执行。
- 非法路径 422；目录外／不可读 403；文件或资源身份不存在 404；文件版本改变 409；图片超过 20MiB 返回 413；格式不支持返回 415。其他读取错误保留实际说明。
- JSON 与图片响应使用 no-store；图片返回正确的 image MIME 及 nosniff。资源错误只影响当前资源，不改成 Run 失败。

### 本地图片自动预览

- 在图片位置自动解析并加载，无需每张确认。可延迟到图片进入可视区域时读取，同一租约内相同资源请求去重。
- 首版预览 PNG、JPEG、GIF、WebP、BMP、SVG；仅加载核实后的图片二进制。SVG 只作为 img 的图片源，不插入 SVG/HTML DOM 或打开为活动页面。
- 前端通过当前 BackendSession 取得图片 Blob，再创建受控显示 URL；不把 Markdown 原始路径或网页图片 URL 直接放入 src。
- 图片宽度不超过正文区，保持比例；聊天中最大高度约 320px，完整查看复用只读详情层。alt 文案与原始引用可查看、复制。
- 加载、缺失、格式不支持、过大和读取失败在图片位置说明，保留原引用与手动重试；仍可通过文件入口准备确认打开。
- 切换会话、隐藏或租约失效时停止未完成读取，过滤迟到结果并释放不再使用的 Blob URL；重新显示按当前租约核实。已提交消息不因资源失败消失。

## 8. 网页打开与文件确认

### 受控 Tauri 桥接目标

| 命令 | 输入 / 返回 |
| --- | --- |
| open_web_url | 输入 url；Rust 校验 http/https 后用默认浏览器打开，返回系统已接受打开或结构化错误 |
| prepare_workspace_file_open | 输入 startupId、原引用 path；宿主从自己管理的后端地址核实工作目录与资源，返回 request_id、startup_id、workspace_id、absolute_path、name、mime_type、size、modified_at |
| open_prepared_workspace_file | 输入 request_id；重新检查租约、工作目录、文件路径与版本，仅打开已准备的同一文件，返回系统已接受打开或结构化错误 |

- request_id 为宿主生成的一次性打开意图，5 分钟后失效；绑定 main 窗口及后端租约。关闭确认、宿主失效或使用后不复用，不持久保存为长期许可。
- Rust 使用 tauri-plugin-opener 的 open_url / open_path；不拼接 shell 命令。关闭插件自动点击链接脚本，仅通过受控入口触发，不能由 Ctrl/Shift 或 _blank 绕过既定行为。
- 不向前端开放任意本地路径的通用 openPath 权限。宿主取地址和根目录时不能信任调用者传入的 baseUrl 或根目录。
- 文件每次点击都需新的确认；图片自动显示只是读取预览，图片的“用系统打开”同样遵循文件确认。
- 非 Tauri 示例预览不假装具有本地资源访问能力；入口说明桌面应用能力。

### 文件打开确认

- 点击文件链接先准备目标，未完成时显示“正在读取文件信息”；此步骤不打开文件。失败原位说明并保留原引用。
- 弹窗沿用当前原生 dialog、白底、细边框、标题条与遮罩。标题“打开本地文件？”，显示文件名、完整实际路径与“将使用系统默认程序打开”。
- 按钮“取消／确认打开”，初始焦点在取消；Esc、关闭和遮罩关闭不打开文件。提供复制完整路径，不提供记住跳过确认。
- 确认时核对原会话、消息和引用仍是当前目标；切换会话、引用改变、隐藏或租约失效时关闭确认，不能把意图带到新路径。
- 文件路径或版本变化时重新准备并要求新确认，不能静默改开另一个目标。文件不存在、无默认程序或打开失败显示实际错误。
- 发出打开命令后防重复点击；成功仅说明系统接受打开，不宣称文件已被阅读或处理。不自动重复打开，也不影响 Run、观察连接或审批。
- 文件确认、参数／代码／图片详情、运行详情和取消弹窗共用一个前景模态；关闭后返回有效入口或稳定工作区。

## 9. Markdown 导出

本节范围与正文格式已在最后完整核对中确认。

- 点击时捕获当前会话的已加载已提交消息快照，随后到达的消息不混入同一次文件；不为了导出另行获取全部服务端记录。
- 包含用户、Agent、工具调用参数及结果、真实工具状态、非 null artifact、中止正文和 generation_status。未提交预览、草稿、审批选择、审批与其他运行事件均不包含。
- 文件头说明会话标题／身份、导出时间、消息数、涉及 Run、已加载 seq 范围，并声明序号允许空洞、范围不代表服务端全部历史。空会话提示暂无已提交内容，不能把发送草稿导出成消息。
- 按原消息 seq 编排，每条 ToolMessage 只导出一次；UI 合并位置不导致结果重复。Agent 的 tool_calls 保留 id、name、完整 args 与实际字段。
- 正常完整的 Agent 字符串正文保留可阅读的 Markdown；取消／失败中止正文，或含未闭合代码围栏、HTML 区块等可能影响后续记录的正文，使用标为 markdown 的原文围栏保存。用户／工具字符串使用 text 原文围栏；content 数组和结构化数据采用完整 JSON。中止原因与工具状态写在正文外的记录说明中。
- 围栏长度按内容选择，避免原文中的反引号提前结束区块；不删正文、补写中止回答或丢弃对象字段。标题与元数据转义，不允许其改变导出结构。
- 本地图片／文件保留原始引用，不打包磁盘文件或嵌入图片二进制；导出不主动读取其他本地文件。
- 沿用 UTF-8 Markdown Blob 下载，安全文件名基于会话名与导出时间，标题缺省用“会话”；取消保存或下载失败不改消息与 Run。实际 Tauri 下载行为仍需后续实机验收。

## 10. 样式继承与下游验收

- 用户浅灰容器、Agent 白画布、左对齐、现有头像列和正文宽度保持一致；不为整段 Agent 回答加新气泡。
- 工具、代码和资源说明复用现有细边框、小圆角与 Slate 背景。中止标记用可读文字，取消用中性语义，失败用既有错误色扩展。
- 工具标题与关键状态使用至少 14px，触控操作至少 44px；长路径可换行并完整复制。异常反馈贴近所属内容，不只依赖颜色或 toast。
- details、按钮和 dialog 保持键盘可操作；只对必要状态适量播报，不逐 token、图片字节或重复历史播报。
- 本地图片和长输出不改变自动滚动策略、不抢夺上翻位置；具体全局滚动、键盘及四档视口验收由[确定首版交互补全与验收顺序](006-interaction-acceptance.md)统筹。
- [确定运行详情、用量与事件视图](005-run-details.md)消费真实终态和事件，不将中止消息误解为正常完成，也不将资源错误作为运行错误。
- [复核当前 Tauri 界面的视觉基准](007-native-style-baseline.md)已按用户提供的原稿与桌面截图定稿，其他实机检查纳入实施后验收；本契约不表示新增内容或完整视觉已通过验证。
