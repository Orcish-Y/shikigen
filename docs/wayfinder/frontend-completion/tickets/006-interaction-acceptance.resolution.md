# 确定首版交互补全与验收顺序：决议

日期：2026-10-04。状态：用户已完整确认，规划票据关闭；应用实现及实机验收待完成。

## 结论

用户在逐项选择输入、会话浏览、阅读、命令、快捷键和窄屏菜单后，对[首版交互与实施收尾核对](006-interaction-acceptance.review.md)真实答复“可以定稿（推荐）”。据此确认交互规则、边界细则、八批实施顺序、PRD 17 条与新增要求的验收覆盖，以及剩余实机问题的处理范围。

产品规则的维护入口为[首版交互补全与验收契约](006-interaction-acceptance.contract.md)；实施任务、实际依赖与逐项验收矩阵的维护入口为[首版聊天工作台实施与验收顺序](006-interaction-acceptance.implementation.md)。[讨论记录](006-interaction-acceptance.discussion.md)保留真实选择，视觉继续以 [design.md](../../../../frontend/design.md)为准。

## 做什么、为什么、使用什么 API

- **做什么：**补齐首版工作台剩余输入、列表、阅读、命令、快捷键、响应式和反馈规则，把既有前后端决策整理成用户可实施的顺序与可判定验收。
- **为什么：**查询、投影、审批、消息和详情的正常路径已有方案，完整首版还需要覆盖迟到、失败、草稿保留、长内容、窄屏及焦点，不以规划关闭代替实际完成。
- **API／入口：**沿用已定 Thread／Run HTTP 与 SSE、新增只读查询、窗口可见桥接、受控系统打开及本地草稿保存；命令、键盘、布局和阅读复用工作台动作及浏览器／原生 dialog 能力。具体接口不在本决议另建一套。

## 已确认的交互范围

- 运行中／等待审批允许编辑并保存草稿，普通发送禁用；结束后手动发送，不排队、不自动发送。trim 只判空，正文原样提交，接受确认只清对应版本。
- 可发送时 Enter 发送；不能发送时拦截 Enter，仅 Shift+Enter 换行；中文输入法候选确认优先，长按不重复提交。
- 临时标题按首条已提交用户消息派生并跨重启缓存、打开核实；真实服务端 title 优先。日期使用本地日历分组，七天起显示日期，完整时间可查看／复制。
- 会话列表只用自动分页，每页 20；按服务端原始短页或空游标终止，显示“没有更多”，不使用过滤／去重后数量，不提供正常“加载更多”按钮。
- 首次进入定位最新，本次应用内切回恢复锚点；上翻停跟随，新消息、图片和布局不抢位置。示例仅填入或追加草稿，不自动发送。
- 命令面板本地搜索操作与已加载会话；K／N／B 在普通输入中可用，受输入法、长按及单前景模态限制。小于 768px 的单菜单每次默认会话列表，同面板切换主导航，窄屏不写桌面主动偏好。

边界细则与完整验收要求由交互契约维护；其余查询、恢复、审批／取消、消息／工具／资源、详情／用量／事件和视觉决策继续沿用，不重新打开。

## 实施与验收安排

用户确认八批顺序：会话定位与只读查询 → 运行投影、恢复与输入 → 审批、取消与中止消息结算 → 完整消息、工具与导出 → 工作目录资源与系统打开 → 运行详情、用量与事件 → 会话浏览、命令、响应式与视觉收尾 → 首版联合验收。

用户可以提前实现独立模块。查询边界、事实投影、原子结算与受控桥接是实际依赖，样式从各批新增组件开始遵守原稿；代码仍由用户主导。

验收矩阵覆盖 PRD 首版全部 17 条、中止正文保存、本地图片与文件确认，以及错误、重放、迟到、竞争、结算和会话隔离。四档尺寸指 WebView 内容区 CSS 视口，记录实际尺寸与显示缩放；真实模型、键盘／输入法、滚动和焦点在实施后核对。

## 剩余 fog 与追踪结果

长内容／软键盘／托盘提示并存的阅读与操作范围、未分类异常的错误归属和事实保留规则已明确。具体实机缺陷在对应组件实施后发现并修正，需要改变已确认产品行为时再建立决策记录；保留视觉复核的全部检查，原生截图不再作为规划前置。

本票据关闭；七项子决策均已关闭，没有尚待明确的首版实现前问题，关闭[首版聊天工作台与后端恢复补全决策地图](../map.md)。PRD、差距审计、设计规范及文档入口同步规划状态。
