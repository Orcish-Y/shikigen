# 首版交互补全与验收契约

日期：2026-10-04。所属票据：[确定首版交互补全与验收顺序](006-interaction-acceptance.md)。状态：用户已逐项选择并完整确认，规划定稿；决议见[交互与实施收尾决议](006-interaction-acceptance.resolution.md)。应用实现与实机验收仍待完成。

真实答复与静态源码事实见[讨论记录](006-interaction-acceptance.discussion.md)。本文件汇总逐项选择、前置契约与已完整确认的边界细则；[收尾核对](006-interaction-acceptance.review.md)和[实施与验收顺序](006-interaction-acceptance.implementation.md)已确认。规划关闭不表示应用已经实现。

## 1. 做什么、为什么、用什么 API

**做什么：**补齐会话列表、输入、滚动、命令、键盘和响应式的剩余交互，最终整理覆盖 PRD 首版 17 条及中止消息保存、本地资源要求的实施与验收顺序。

**为什么：**既有接口、恢复、审批、消息和详情已确定，工作台仍缺少完整的阅读与操作规则，不能只按发送成功的主路径宣布首版完成。

**用什么 API：**沿用现有会话和 Run HTTP／SSE、前置票据确认的待补查询接口、草稿本地保存、浏览器键盘／滚动／视口能力及原生 dialog。既有接口、身份隔离和请求确认规则以[运行投影与恢复契约](002-run-projection.contract.md)及其他前置契约为准。

## 2. 执行期间草稿编辑（已确认）

- running 或 interrupted 时允许编辑并按会话保存下一条消息草稿，不禁用 textarea。
- 普通发送保持禁用；不提供排队发送，不自动创建下一次 Run。运行进入终态后，仍需用户主动发送，且须满足宿主就绪、当前状态已核实、无提交 pending／结果待确认等既有条件。
- running 时底部主操作仍为“取消运行”；interrupted 时仍为“处理审批”，定位聊天审批卡片，统一在卡片提交。卡片内取消和一次确认弹窗沿用[审批与取消交互契约](003-approval-cancel.contract.md)。编辑草稿不改变审批草稿或 Run 状态。
- 发出发送 POST 时保留本次提交原文和草稿版本；收到本次 POST 的有效 metadata 后只清空仍对应本次提交的草稿，不能覆盖用户后来改写的内容。失败和接受情况未知时保留原文，按前置恢复规则核实，不能自动重发。
- 切换、隐藏、布局变化、宿主退出 ready 和应用重开不主动丢弃草稿；本地保存失败保留内存文字并显示既有提示，沿用投影契约保存范围。
- 此规则取代原 PRD 中 running／interrupted 的“输入框禁用”，并不表示发送已开放。

**实施后验收：**在运行中和等待审批时编辑草稿，切换再返回仍保留；状态进入 completed／cancelled／error 不自动发送；迟到的发送接受 metadata 不清除新版本草稿；底部取消／处理审批入口可达，窄屏仍可编辑文字并完成当前运行操作。

## 3. 输入正文与发送（已确认）

- 空白判定可以使用 trim；全空白不发送。实际提交 `ChatRequest.message`、保存的本次提交原文和显示的用户正文均保留原始草稿的首尾空格、缩进、换行与符号，不将裁剪后的值作为正文。
- Enter 发送、Shift+Enter 换行、组合输入期间不发送沿用 PRD。Enter 与点击发送共用同一个动作和可用性判断；组合输入确认键不能触发提交，需在当前 Tauri WebView 中验收中文输入法。
- 无发送资格时拦截普通 Enter，不插入换行，不触发发送、取消或审批；此时仍可用 Shift+Enter 换行。组合输入优先交给输入法，不能因 Enter 拦截破坏候选确认。键盘长按不能产生重复提交。
- 发送 pending 期间仍可编辑草稿，普通发送继续禁用；确认接受时仅清空对应提交版本，不覆盖新内容。失败或接受情况未知时保留本次提交原文，新草稿已改写时不以旧原文覆盖它。

**实施后验收：**发送带首尾空格、多行缩进和末尾换行的文本，POST 原文与持久 HumanMessage 的正文一致；全空白不能提交；中文候选确认不发送且不被阻断，可发送时普通 Enter 只发一次；不可发送时普通 Enter 不提交也不换行，Shift+Enter 仍换行；请求确认前改写草稿不会丢失，也不形成第二次提交。后端既有无效 Unicode surrogate 替换规则继续沿用，不据此裁剪正常正文。

## 4. 会话标题（已确认）

- 显示优先级：服务端非空 title → 本地临时会话标题 → “新会话”。不再以会话 ID 作为普通标题，真实 ID 仍在详情中可读／复制。
- 打开会话后，从首条已提交用户消息的明确文本形成一行短标题；文本整理只用于标题，不修改消息正文。未知内容块不强行提取为标题，未发送草稿或未提交预览不能生成会话标题。
- 临时标题按会话 ID 本地缓存并跨重启保留；每次取得真实历史时核对来源并更新，有真实 title 时优先使用服务端 title。title 的 null 轮询结果不能无故清掉已经核对的本地派生值。
- 只为当前打开的会话按既有历史查询取得内容，不为了批量补标题读取所有会话的历史。缓存失败时保留内存显示并沿用本地保存不可用提示。
- 临时标题是显示辅助信息，不写回后端，不表示正式标题已保存，不作为 Run 发现或发送接受情况的依据。首版不增加标题 PATCH／编辑入口。
- 列表与工具栏使用同一个显示标题；长标题按现有宽度截断，并提供可用键盘／触控查看完整标题的入口。本地过滤和命令会话检索均匹配这个显示标题。

**实施后验收：**无 title、尚未打开的会话显示“新会话”；首次读取后派生标题，重启后可显示缓存，重新读取真实消息可核对；服务端真实 title 覆盖派生值；未提交输入不成为标题，多页轮询不清缓存，不把本地派生写回服务端。

## 5. 会话日期与更新时间（已确认）

- 排序使用服务端真实 `updated_at DESC, id DESC`，沿用查询契约；不以客户端现在时间、delta 到达时间、标题缓存时间或相对文案重新排序。
- 按用户本地日历日期分为“今天／昨天／更早”。跨日期判断使用日历边界，不将“昨天”定义为距今 24 小时内；空分组不展示。
- updated_at 距今不足一分钟显示“刚刚”，不足一小时显示“N 分钟前”，不足一天显示“N 小时前”，不足七天显示“N 天前”，七天起显示本地日期。分组与相对时间分别按日历日期及实际时间差计算。
- 完整查看入口包含本地日期、时间与时区，原始 UTC 时间可复制。入口支持键盘与触控，不能仅依赖鼠标 hover；沿用只读信息呈现，不触发 Run 查询或改变状态。
- 窗口可见时每分钟更新显示文案，重新显示时立即计算并重建日期分组；不为文案刷新追加 HTTP 请求。用户本地日期或时区变化后据当前环境重新计算。
- 晚于客户端当前时间的服务端时间直接显示本地绝对时间，不生成负数或虚假的“刚刚”；无法解析的时间显示“时间未知”，保留已有事实与可用操作，不补造时间。未来日历日期或无法确定日期的记录不能强行归为“更早”，单列“日期待确认”，保留真实排序，不影响切换会话。

**实施后验收：**本地午夜前后与 UTC 日期不同的会话分组正确；一天以内但属于昨天时按日历分组；一分钟／一小时／一天／七天边界文案正确，完整时间与原始 UTC 可查看／复制；隐藏再显示或跨日后立即更新且不额外增加查询，排序与服务端事实一致。

## 6. 会话列表分页、过滤与加载反馈（已确认）

- 面向用户的侧栏标题及必要入口使用“会话列表”，沿用已确认的会话用语；代码中的 History 名称和公开原始 JSON 字段不要求改名。
- 会话列表滚动到底部后自动加载下一页，每页固定 20 条。按已确认的 next_cursor 读取与合并，不自行构造游标。
- 正常分页只提供自动加载；不提供“加载更多”辅助按钮。列表可用键盘聚焦，到底／End／PageDown 等操作触发同一分页动作。无过滤且内容不足可视区时自动继续填充；过滤本身只匹配已加载显示标题，不因过滤变化而自动检索全部历史。过滤后内容不足以产生滚动时，用户继续向下滚动或键盘到底的明确意图仍可触发一页。
- 服务端本页原始 data 少于 20 条时停止加载并显示“没有更多”；原始页数不能换成过滤后匹配数或去重后新增数。`next_cursor=null` 也结束分页，覆盖最后一页恰好 20 条的情形。服务端保证短页的 next_cursor 为 null；这表示本次查询边界没有下一页，不宣称会话总数是固定的。
- 底部加载下一页与周期性第一页轮询各自遵守既有分页进度；轮询不覆盖下一页游标，不清更早会话，也不改变选择或草稿。
- 自动加载只服务会话列表，不滚动主时间线、不重建 SSE，也不改变 Run 状态。
- 首次没有可显示列表事实时显示与实际会话行等高的 skeleton；已有事实的刷新不清列表，不改成全屏 skeleton。加载下一页只在底部显示“正在加载…”，避免对话或列表闪空。
- 首次失败显示列表区域错误与重试；更多页失败保留列表、当前选择、对话和分页位置，显示底部原位“重试加载”。重试遵守既有错误分类与 Retry-After；失败状态不能由仍可见的底部哨兵触发无限重试。无效游标的显式重新加载沿用查询／投影契约。
- 区分读取中、读取失败、确实无会话、过滤无匹配和没有下一页；过滤显示“仅已加载会话”，无匹配保留清除过滤入口，不将未加载部分宣称为不存在。过滤隐藏当前行也不改变已选会话。

**实施后验收：**20／21／40／41 条、第一页及下一页都为空、重复 ID 与更新时间变化；短页或 null 游标显示“没有更多”，整页 20 条且有下一页继续；过滤仅匹配一两条或全无匹配时不因匹配数终止分页；列表未撑满、键盘到底、长按滚动、请求失败与 Retry-After，不产生重复或无限读取，也不影响当前会话、草稿和 SSE。

## 7. 聊天阅读位置与自动跟随（已确认）

- 本次应用启动后第一次打开会话，在正确身份的历史消息读取并呈现后定位最新；应用重启后仍从首次打开的最新位置开始。
- 切换再回到已看过的会话时恢复上次阅读位置与跟随模式，按会话在应用内存中保存；隐藏、布局切换或 Workspace 暂时卸载不主动删除本次记录。记录与消息草稿、审批草稿分别维护。
- 阅读位置以稳定的消息／卡片锚点及视口偏移恢复，不只盲目复用一个像素 scrollTop；新内容、工具内容变化、图片加载和宽度变化时保持正在阅读的位置。原锚点暂未呈现时等待该会话事实恢复；无法找到时落到最近存在的内容，避免误跳到另一会话。
- 位于底部附近且仍处于跟随模式时，流式增长跟随底部；用户主动上翻立即停止自动跟随，不因仍接近底部而马上重新打开。
- 暂停跟随时显示“回到最新”；新增内容可说明“有新内容”，不以 delta 数量伪造消息数。用户点击或主动滚回底部后恢复跟随，不自动改变草稿或运行状态。
- 用户主动发送并取得本次有效接受 metadata 后，可定位最新并恢复跟随；运行状态更新、自动查询／重连、审批事件到达、标题或用量变化都不能单独强制跳到底部。“处理审批”仅在用户主动点击时定位卡片，沿用既有交互。
- 工具／代码／JSON 的区内滚动不当作主时间线上翻。导航、会话列表、主时间线与详情分别滚动，列表加载或排序不推动主时间线。

**实施后验收：**首次打开长对话、上翻后连续 delta／完整替换／图片加载、切换再返回、隐藏再显示、宿主离开 ready 后恢复、导航展开和四档宽度变化；正在阅读的消息不被抢走，跟随／回到最新和主动定位审批符合意图。恢复后继续收到旧目标数据不能改位置；软键盘和输入增高仍使主操作、最后消息可达。

## 8. 空状态与任务示例（已确认）

- 没有成功读取的列表／历史事实时先显示读取或错误状态，不把待加载空数组当作“没有会话”或“空会话”。缓存数据刷新时保持已有内容并说明正在核实。
- 确实没有会话且没有已选有效会话时，沿用 PRD 的工作台说明和“新建会话”入口；输入与示例属于已创建并选中的会话，不将文字存到空 thread_id。会话读取失败或 404 的未发送文字仍按投影契约保留供复制／转到新会话。
- 创建 POST 已返回有效 thread_id 且用户的新建意图仍是当前意图时，按原 PRD 选中新会话；期间用户已经主动切换其他会话时，保留已创建条目并提示，不用迟到结果抢走当前选择。后续列表读取失败只显示列表读取错误，不能把已确认创建改成创建失败或自动重复 POST。新会话显示时间等待服务端事实，不用本地现在时间补造。
- 空会话显示当前模板的引导与三条真实任务示例：解释项目目录、搜索工具注册逻辑、总结指定网页；需要的路径／URL 由用户补充或 Agent 澄清，不伪造消息和工具结果。
- 示例点击只修改本地消息草稿：空字符串时填入；已有内容时保持原文，用空行分隔后在末尾追加。随后聚焦输入，用户自行编辑／主动发送；不创建 Run、不自动发送，也不修改审批选择。
- 新建或用户主动打开空会话后聚焦输入遵守当前身份；异步读取返回时若用户已切换会话、打开模态或移到其他输入，不夺回焦点。后台列表轮询、重连或用量更新不自动聚焦。

**实施后验收：**初次读失败、读取中、真的空列表、空会话和过滤无匹配各自显示正确；无会话时可新建并进入输入；已确认创建后的列表失败没有二次创建；已有多行草稿点击示例后原文完整保留，示例只追加且不发送；请求迟到不改另一会话草稿或抢模态焦点。

## 9. 命令面板（已确认）

- 沿用现有原生 dialog、约 480px 宽度与轻量行式控件；增加本地搜索框，按“操作／已加载会话”分组。
- 搜索仅过滤已加载显示标题和面板动作名称，不发服务端搜索，不自动读取未打开会话的历史。会话行可复用中文状态与更新时间辅助识别，不造模型或执行摘要。
- 动作包括新建会话、展开／收起主导航、打开当前运行详情及直接切换已加载会话；与页面按钮使用同一行为和可用性判断。无有效后端／目标 Run、创建 pending 等情形显示实际禁用原因。
- 输入搜索后用方向键选择可用项，Enter 执行当前可用项，Esc 关闭；组合输入确认不执行动作，长按不能重复创建。无匹配显示相应提示，不默认执行“新建会话”。搜索输入初始聚焦，长列表在面板内滚动。
- 会话切换和新建等动作执行后关闭命令面板；打开详情在同一前景模态中转为详情，不能再叠一个 dialog。关闭／返回按既有规则恢复有效焦点，执行动作不能取消其他 Run 或清草稿。
- 面板搜索与侧栏过滤分别维护；面板关闭不清侧栏查询、不改变分页位置。选中会话后按既定历史／Run 恢复链路读取，命令面板本身不新建第二条 SSE。

**实施后验收：**已加载标题及动作可查找，所有可用项可用键盘执行；无匹配或禁用项不触发新建，创建 pending 不重复；切换会话不串流，详情单前景打开、关闭返回焦点；过滤仅使用已加载数据，不额外搜索或全量读取历史。

## 10. 全局快捷键与前景模态（已确认）

- 按宿主展示 Cmd 或 Ctrl：K 打开命令面板，N 新建会话，B 切换主导航。草稿及普通搜索输入中同样可用；与页面按钮共用行为、可用性与请求 pending 判断。
- 仅处理对应的普通组合，不在输入法组合／候选确认期间执行，不因长按反复创建或切换。输入与搜索的普通编辑、复制及选择快捷键保留原行为。
- 前景模态中不触发全局工作台动作；仅 K 可关闭自身命令面板，B 可关闭自身主导航覆盖面板。其他详情、参数、图片、文件或取消弹窗不能被 K／N／B 替换，也不借这些键提交或打开新会话。
- Esc 只关闭当前前景层，不能同一次键盘事件继续关闭背后面板，不能取消运行、提交审批或丢弃选择。已有取消／文件确认的默认焦点和安全返回规则沿用前置契约。
- 桌面 B 保存用户主动的导航偏好；窄屏 B 操作覆盖导航，不覆盖桌面偏好。宿主占用某快捷键时仍可使用实际按钮，不以快捷提示承诺宿主未提供的原生能力。
- 单一前景模态维持焦点约束，关闭返回仍有效的入口，否则返回当前会话的合理焦点位置；不得返回已切换会话的失效 DOM。

**实施后验收：**草稿和过滤输入中 K／N／B 按预期执行且内容保留；组合输入、按键长按及模态中不会触发后台动作；K／B 关闭自身面板、Esc 只关当前层；取消／打开文件默认焦点正确，Tab 顺序／可见焦点／返回焦点在四档视口可用。
