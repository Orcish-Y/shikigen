# 视觉基准收尾安排

状态：用户于 2026-10-03 已确认“定稿基准，实机验收后置”。对应[复核当前 Tauri 界面的视觉基准](007-native-style-baseline.md)，最终结论见[决议](007-native-style-baseline.resolution.md)；规划基准已定稿，实机验收待实施后完成。

## 做什么

以用户指定的两份 HTML 原稿和两张项目桌面截图，确认实施前的样式基准。其余尺寸、弹层、宿主页与滚动／焦点的实机检查，安排在对应组件补齐后进行。

## 为什么

本地图的目的，是明确实施前方案。当前已知原稿比例、视觉系统、桌面两态现状和需要调整的差异；它们可以指导新增组件。审批、完整消息、资源和完整详情仍待实现，后续四档视口检查需要覆盖这些新增内容。

原票据把完整实机检查列为前置。用户已明确确认调整这个边界：先以已有原稿和桌面画面定稿基准，其他实机检查纳入实施后验收。

## 可以确认的基准

- 展开原稿统一菜单与基础视觉，折叠原稿提供 64px 图标栏比例；两态使用同一套视觉系统。
- 新页面和组件延续白色画布、Slate、Indigo、Geist／JetBrains Mono、Phosphor regular、细边框和紧凑排版。
- 几何规格以 WebView 内容区 CSS px 表达，原生标题栏、显示缩放和 PNG 像素分别处理。
- 原稿的示例控件与数据按已确认功能契约适配；新增审批、资源和详情复用既有内嵌区块与前景模态。
- 当前导航头、消息／工具排版与输入密度的对齐项，按 design.md 第 4、5 节实施。

## 继续保留的验收项

- 实际内容区尺寸、显示缩放和四档视口：1440×900、1280×800、1024×768、390×844。
- 中等窗口与窄屏导航、会话列表、必要状态和发送／审批／取消入口。
- 详情／命令／参数／图片／文件／取消面板的长内容、关闭、返回与焦点。
- 空会话、宿主启动／失败、托盘提示、独立滚动、自动跟随与键盘操作。
- 新功能的真实数据、异常、重放、迟到、竞争和结算场景。

这些项目须写入后续交互与验收方案，并在实施后实际检查。现有两张截图不会被标为完整响应式或功能通过。
