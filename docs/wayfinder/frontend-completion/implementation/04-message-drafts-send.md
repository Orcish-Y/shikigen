# 原文发送并保留持久消息草稿

Status: ready-for-agent

实施进度：待实施

来源：[统一实施规格](../../../../.scratch/frontend-completion/PRD.md)；[公共要求与依赖总览](index.md)。

**What to build:** 按原文发送消息，运行期间仍能编辑下一条草稿；重启后保留文字，发送结果未知时可以查询核对和主动决定后续动作。

**Why:** 让用户控制每次任务开始，保护请求确认前后编辑的内容，并避免重复执行。

**API／边界：**ChatRequest.message、发送 POST 的有效 metadata；本地命名空间／会话草稿和版本；历史／运行 GET 核实；共享发送动作。

**Blocked by:** [全量重建消息与当前运行事实](03-run-fact-reconstruction.md)。

## 验收条件

- [ ] trim 只判空，实际 POST、已提交用户正文和提交原文保留首尾空格、缩进、换行；全空白禁发，既有无效 surrogate 替换不裁剪正常正文。
- [ ] running／interrupted、发送 pending 时可编辑并保存草稿但不能普通发送；终态不自动发送，不排队；底部当前运行操作保留。
- [ ] 可发时 Enter 与按钮同动作，Shift+Enter 换行；不可发时 Enter 拦截且不换行、不取消、不审批，输入法候选优先，长按不重复。
- [ ] 保留提交原文和版本，只由本次 POST 的有效 metadata 确认接受并清对应版本；请求期间新草稿不被覆盖，GET／旧 Run metadata 或相同正文不证明接受。
- [ ] 接受前断连、解析、POST 500／中止等保留发送结果待确认，只 GET；有 run_id 后按已接受 Run 恢复观察。可查询并人工确认对应消息，或主动作为新任务发送，仍受当前资格约束。
- [ ] 按会话跨切换／重启保存草稿、版本和必要未知记录；旧 pending 重开后待核实，不恢复地址、计时器、连接或执行。本地失败回退内存并提示，会话 404 可复制或转移文字。
- [ ] 通过公开请求与持久消息验证原文一致和单次提交；实机验证中文 IME、运行期编辑、重启恢复、未知结果人工处理以及迟到接受不清新文字。
