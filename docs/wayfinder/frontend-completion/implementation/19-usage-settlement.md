# 有限核实待结算用量

Status: done

实施进度：已验收

来源：[统一实施规格](../../../archive/2026-10-07/development/frontend-completion/PRD.md)；[公共要求与依赖总览](index.md)。

**What to build:** 等待审批或终态时用量仍待结算可自动有限核实，达到上限明确暂停，用户可主动继续核实。

**Why:** 允许用量晚保存而不假定运行结束即结算，也不形成无限或并行轮询。

**API／边界：**同目标纯读 RunSnapshot、usage_pending、执行阶段确认；窗口可见输入、共享读取协调／重试预算与 Retry-After。

**Blocked by:** [查看当前运行详情与真实累计用量](17-run-details-usage.md)。

## 验收条件

- [x] 正常 interrupted／终态 EOF 补一次快照，有效取消快照立即显示结果再按需核实，与已有读合并，首次补读不算后续预算。
- [x] 只在当前目标、visible／ready、状态 interrupted／终态且已确认 pending=true 时开始；正常 running SSE 不叠用量轮询。
- [x] 完成请求后等 5 秒，本轮最多 12 次后续请求，失败／重试算次数，成功但 true 不重置；适用 false 立即停，数字不变／过时／EOF 不自行当已结算。
- [x] 可恢复错误用 1／2／5 秒三次与 Retry-After 的同一任务，不并开五秒与错误任务；三次仍失败或 404／500／协议问题停止，保留最后值和局部错误。
- [x] 达上限显示仍在结算且自动核实暂停，可主动继续读并启动新受限轮次；关详情摘要仍可核实，切换／隐藏／租约失效停止，返回同阶段不自动重置预算。
- [x] 旧阶段／旧同组字段响应不覆盖新值，取消后同 updated_at 的有效晚量可补；查询／结算失败不改 Run，消息保存／事件补读分别确认。
- [x] 可控公开查询验证时间、12 次、三次失败、Retry-After、重复触发、隐藏／切换和新阶段，在实机展示晚量与手动继续。
