# Shikigen 前端工作台 PRD

状态：Draft 0.3  
更新时间：2026-09-24  
布局基准：[主导航展开态](../design/demo.html)、[主导航收起态](../design/front-end-demo.html)  
能力依据：当前 FastAPI 路由、SSE 契约和 Runtime 状态模型

## 1. 产品定义

Shikigen 前端是一个面向 Agent 开发者的单用户聊天工作台，以对话为主要工作路径，将工具执行、审批和运行状态嵌入聊天体验。用户可以：

1. 在持久会话中向 Agent 发起任务。
2. 实时看到回答生成和已提交消息。
3. 知道一次 Run 正在运行、等待审批、完成、取消还是失败。
4. 在危险工具执行前检查参数，并逐项批准或拒绝。
5. 断开页面后重新观察已知 Run，而不重复执行任务。
6. 查看本次 Run 的 token 用量和持久事件。

首版定位为本地开发工具，不包含团队协作、账号、计费和多租户管理。

## 2. 设计基准与取舍

以 [design/demo.html](../design/demo.html) 为主导航展开态基准，以 [design/front-end-demo.html](../design/front-end-demo.html) 为主导航收起态基准。两份原型共同定义同一工作区的两种布局状态：顶部应用栏、可折叠主导航、独立的会话历史侧栏、主对话区和底部悬浮输入区。运行详情按需打开，不长期挤占对话宽度。

两份原型的菜单内容存在差异：导航名称、顺序和分组以新版 `demo.html` 为准；旧版仅作为 64px 图标栏的布局参考，收起时不切换成另一套菜单。

- 保留原型的浅色桌面应用风格：白色主画布、浅灰侧栏、细边框、靛蓝强调色、小圆角与轻阴影。
- 保留原型的消息组织：用户与 Agent 消息均左对齐，头像独立一列；用户正文置于浅灰容器，Agent 正文直接排在白色画布上，代码和工具结果使用内嵌区块。
- 保留原型的信息层级与控件位置；涉及未支持能力时，按第 6.4 节明确隐藏、禁用或替换，不让静态示例变成虚假功能。
- 首版沿用 FastAPI + HTTP/SSE。原型对话中的 Rust、Tauri、IPC 是示例内容，不构成桌面壳或通信技术选型要求。
- 原型中的模型名称、版本、耗时、token 数和历史消息均为占位数据，正式界面必须由实际数据驱动。

### 3.2 当前工具与 Agent 能力

当前内置工具包括：

- 当前时间和加法。
- 文件读取、写入、目录列表、文本搜索和 bash。
- Web Search 和 Web Fetch。
- task 工具，用于调用子 Agent。
- 配置文件中声明的 MCP 工具。

前端首版只展示运行中实际出现的工具调用。当前没有“获取全部工具”接口，因此不提供工具管理页。

## 4. 当前不支持的功能

以下能力不能在首版界面中伪造：

- 暂停正在运行的 Run。当前只有取消和因 HITL 自动中断。
- 会话重命名、删除、归档和服务端全文搜索；已加载会话的本地标题过滤可在前端实现。
- 会话内 Run 列表、Run 详情查询和全局 Run 列表。
- 在浏览器状态完全丢失后找到某个会话的 active run_id。
- 设置页中修改模型、MCP、工具权限或审批策略，以及单次请求的模型切换、深度思考和联网开关。
- 附件上传、图片输入和文件管理。
- 编辑已发送消息、重新生成、分支对话。
- 展示实时 reasoning。协议预留了字段，但当前 Loop 只发布 content。
- 结构化展示子 Agent、子任务、checkpoint 或 Goal 状态。
- 单次运行费用。当前只有 token 用量，没有价格或成本字段。
- 共享会话、清空已有 Thread 上下文、消息反馈、语音输入、知识库、流程编排和插件管理。
- 上下文窗口占用比例、实时 tokens/sec、单条消息或单个工具的准确耗时及用量。
- 登录、团队空间、远程多节点可靠事件投递。

## 5. 用户与核心任务

主要用户是正在开发和验证 Agent Harness 的开发者。

核心任务：

1. 发出一个自然语言任务，并持续观察结果。
2. 在 Agent 请求执行写文件或命令时，确认即将发生的操作。
3. 判断任务是否真正完成，而不是把 SSE 断开误认为完成。
4. 页面刷新或连接中断后，恢复已知 Run 的展示。
5. 查看工具结果和 token 用量，定位一次执行的问题。

### 6.2 桌面布局与视觉规格

| 区域 | 布局基准 | 要求 |
| --- | --- | --- |
| 顶部应用栏 | 全宽，高 40px | 固定在顶部；左侧品牌，中间连接状态，右侧命令入口 |
| 主导航 | 展开宽 256px，收起宽 64px，位于顶部栏下方 | 浅灰底、右边框；展开态顶部为约 48px 品牌与折叠控制行，中部为核心入口，底部为连接摘要和系统入口 |
| 会话历史侧栏 | 宽 256px，紧邻主导航 | 标题、新建和过滤固定在上部；列表独立滚动；用量摘要在底部 |
| 主对话区 | 双侧栏可见时，展开态左偏移 512px，收起态左偏移 320px | 白色画布，占据剩余宽度，无常驻右栏 |
| 会话工具栏 | 主区域顶部，位于应用栏下方 | 滚动时保持可见，不能被 40px 应用栏遮挡；窄宽度时收起次要操作 |
| 消息时间线 | 最大宽度 840px，水平居中 | 内侧水平留白约 12px，顶部和消息组间距约 24px |
| 悬浮输入区 | 最大宽度 840px，与消息区居中对齐 | 固定在主区域底部；外侧水平留白约 24px、底部约 16px；白色半透明底、细边框和柔和阴影 |
| 运行详情 | 从右侧打开的覆盖式抽屉 | 默认关闭；不形成常驻第三个内容栏 |

主对话区、会话工具栏和悬浮输入区共用同一左侧占用宽度：主导航实际占用宽度 + 会话历史实际占用宽度；覆盖式抽屉不计入占用。最大 840px 是上限，剩余宽度不足时内容自然收缩。

时间线底部留白随输入区实际高度调整，保证最后一条消息、工具结果和审批按钮不会被遮住。输入区外层的透明区域不拦截消息点击和滚动。

视觉规格：

- 主画布白色，侧栏与用户消息使用 Slate 浅灰系；边框接近 Slate 200，正文接近 Slate 900，次要信息使用 Slate 500/600。
- 主强调色采用原型的 Indigo 600（`#4f46e5`），用于发送按钮、Agent 头像底色、选中导航和交互反馈。
- 正文使用 Geist 加中文无衬线回退字体；代码、ID、用量和序号使用 JetBrains Mono 加等宽回退字体。
- 正文约 14px / 24px 行高，标题约 15px / 22px，代码约 12px / 20px，辅助信息约 11–12px；不将微小辅助字号用于审批正文。
- 常规间距采用 4、8、12、16、24px；主要消息区块和输入容器圆角约 8px，避免大面积厚重阴影。
- 首版默认浅色，与原型保持一致；深色主题作为后续增强，不要求默认跟随系统。
- 动效用于流式光标、运行状态和展开反馈；终态停止动画，状态不能只靠颜色表达。

### 6.3 响应式布局

以下断点是基于两份静态原型补充的产品规则，原型本身未实现响应式切换。

- 1440px 及以上：默认显示 256px 展开主导航 + 256px 会话历史，左侧占用 512px；用户可主动收起主导航，左侧占用变为 320px。
- 1280–1439px：未保存偏好时默认采用 64px 收起主导航 + 256px 会话历史；允许手动展开，此时对话按剩余宽度收缩，次要工具栏操作收入更多菜单。
- 768–1279px：主导航固定占用 64px，会话历史使用覆盖式抽屉；展开主导航时以 256px 覆盖面板显示，不继续挤压对话。两个侧栏覆盖面板互斥打开，关闭后回到 64px 图标栏。
- 小于 768px：单栏对话，主导航和历史入口合并到菜单，通过覆盖面板切换查看；主区域无左侧占用，顶部仅保留品牌、会话入口和必要状态。
- 桌面宽度下记住用户主动选择的主导航展开偏好；窄屏自动收起不覆盖此偏好，返回桌面宽度后恢复。
- 移动端运行详情使用底部 Sheet；审批仍以内嵌卡片为主，长参数可打开详情层查看。
- 输入区偏移随侧栏显示状态变化，宽度不溢出视口；工具栏允许换行或折叠，发送、取消、审批入口始终可达。
- 使用动态视口单位和安全区适配软键盘；长代码和 JSON 在区块内横向滚动，不撑宽页面。

## 7. 页面与交互要求

### 7.1 会话历史侧栏

上部为“会话历史”、新建按钮和“过滤历史会话”输入框；中部按更新时间倒序排列，按用户本地日期分为“今天 / 昨天 / 更早”；底部为当前 Run 用量摘要。这样既保留原型的浏览路径，也让主要空间用于会话内容。

每个条目显示：

- title，缺失时显示“新会话”；加载该会话消息后，可由首条 HumanMessage 本地派生临时标题。
- updated_at 的相对时间，以及当前浏览器已知的 Run 状态；未知时不补造状态。
- 选中项采用白底、边框和轻阴影，其余条目保持轻量悬停反馈；长标题截断并可查看完整内容。

交互与 API：

- 点击“新建会话”调用 `POST /api/threads`，成功后选中新 Thread 并聚焦输入框。
- 点击会话调用 `GET /api/threads/{thread_id}/messages`；若本地保存了该会话的 run_id，再通过 GET Run stream 重建运行状态。
- 过滤只匹配已加载的显示标题，不检索服务端全部消息；无匹配时保留清除过滤入口。
- 加载时显示与最终行高一致的 skeleton；列表失败原位重试，不清除已打开对话。
- 用量摘要始终标为“当前 Run”，取当前选中会话的已知 Run 数据，不汇总为账户额度或上下文占用；未知显示“暂无用量数据”。

限制：后端当前不会通过 HTTP 保存 title，也不返回 active run_id。临时标题刷新后可由消息重新派生，但不能误导用户为已保存。

### 7.2 对话时间线

消息按 `seq` 排序，不按到达时间排序。沿用原型约 28px 的头像列、角色名称行和正文列；用户与 Agent 均左对齐。

- 用户消息采用浅灰底、细边框和约 8px 圆角；Agent 正文直接置于白色画布，避免整段回答再套一层气泡。
- Agent 名称旁显示真实运行状态；正在输出时可显示光标，不显示虚构的速度、时间和 token 数。
- 代码块采用独立浅灰容器，头部显示已有语言标记、可选文件名和复制按钮；文件名仅在内容明确提供时展示。行号和行数由代码实际计算，复制得到完整原始代码，不包含行号。
- 工具调用内嵌展示工具名、参数、结果和真实状态，通过 `tool_call_id` 关联调用与结果；只有调用而没有结果时显示“等待结果”，不推断工具已开始执行。
- 正文、代码、工具输出均允许选中复制，不沿用原型 body 的全局禁止选择行为。

消息内容与数据来源：

- HumanMessage：用户内容。
- AIMessage：正文，以及可折叠的 tool_calls。
- ToolMessage：工具名、成功或失败状态、输出；artifact 只有在存在时展示。
- content 为 block 数组时，首版支持字符串和 JSON 对象的安全只读展示；未知 block 使用 JSON Viewer，不猜测媒体语义。
- Markdown 输出需做 HTML sanitization，代码块提供复制操作。

流式合并规则：

1. `delta` 到达后，以 `seq + message_id` 建立临时 AI 消息并追加 value。
2. 同 seq 的完整 `event/message` 到达后，用完整 payload 替换临时消息。
3. 重复完整事件按 seq 去重。
4. seq 允许空洞，不能等待连续序号才渲染。
5. SSE 结束只表示连接结束，最终状态以 lifecycle 事实或 metadata 为准。

### 7.3 底部悬浮输入区

采用原型的白色悬浮输入容器：上层多行文本，下层工具栏左侧显示必要状态、右侧放主要操作；外侧底部显示品牌与有效快捷提示。首版隐藏附件标签与未支持的工具按钮后，容器高度自然收缩，不保留空白占位。

输入框提示为“向 shikigen 发送指令或提问…”，另以辅助文案说明 Enter 发送、Shift+Enter 换行。文本增高到上限后内部滚动，不能持续挤压对话区。

空闲状态：

- 多行文本输入。
- Enter 发送，Shift+Enter 换行；输入法组合输入期间不触发发送。
- 空白消息不可发送。
- 发送时调用 `POST /api/threads/{thread_id}/stream`，请求期间防止重复提交；收到 metadata 后采用服务端 Run 状态。发送失败保留草稿。

running 状态：

- 输入框禁用，主操作变成“取消运行”。
- 取消需要一次明确确认，并说明已开始的外部工具副作用不保证撤销。
- 调用 `POST /api/threads/{thread_id}/runs/{run_id}/cancel`。

interrupted 状态：

- 输入框禁用。
- 审批面板成为主要操作。
- 仍允许取消整个 Run。

terminal 状态：

- completed、cancelled、error 后重新启用输入框，可在同 Thread 创建新的 Run。

### 7.4 审批面板

审批以内嵌卡片插入当前 Run 的消息时间线，复用原型工具区块的边框与间距；会话工具栏同时显示“等待审批”和定位入口，避免用户在历史位置阅读时漏掉请求。长参数可打开详情层，主要决策仍在对话路径内完成。

每个 Interrupt 显示 namespace，并按 action_requests 原顺序显示动作。每个动作展示：

- 工具名称。
- description。
- 完整 args，使用格式化 JSON 和等宽字体。
- allowed_decisions。
- approve 或 reject 选择。
- reject message，仅在拒绝时出现。

只有所有 Interrupt 的所有动作都做出选择，才启用“提交决策”。提交结构必须保持 Interrupt ID 和动作顺序。成功调用：

`POST /api/threads/{thread_id}/runs/{run_id}/approval-decisions`

提交成功后消费返回的新 SSE，run_id 保持不变。409 表示审批可能已被其他请求处理，前端应重新打开 GET stream 收敛当前事实；422 显示具体校验问题；503 按 `Retry-After` 提示重试。

审批状态：

- required：显示等待决策。
- resolved：锁定并显示已提交决策。
- invalidated：显示审批因 Run 取消而失效，不再允许提交。

### 7.5 运行详情抽屉

会话工具栏右侧提供“运行详情”按钮，在原型 Agent 配置的位置打开覆盖式抽屉；移动端使用底部 Sheet。关闭抽屉不停止观察，不丢失状态。仅展示当前响应真实提供的数据：

- status。
- thread_id、run_id，支持复制。
- usage 和 usage_pending。
- token 总输入、总输出、总量、calls、by_model。
- lifecycle 和 approval 的持久事件时间线。
- 观察错误及恢复入口。

没有数据时显示“等待运行数据”，不显示 0。`usage_pending=true` 时标记“仍在结算”；false 表示已保存当前已知用量，不宣称等同供应商账单。

### 7.6 顶部应用栏与会话工具栏

顶部应用栏负责品牌、当前会话的连接状态和本地命令入口；会话工具栏负责会话标题、Run 状态、已知用量、导出和运行详情。将连接与执行分开呈现，避免用户把断流误认为执行结束。

- 顶部连接状态来自 `connectionState`；工具栏运行状态来自 metadata / lifecycle。
- 未开始运行时显示“就绪”，它只是前端空闲状态，不新增服务端 Run 状态。
- 导出仅包含当前已加载的已提交消息与工具记录，不包含尚未提交的 delta；文件中标明范围，内容通过浏览器下载生成，不声称已导出服务端全部运行事件。
- 命令面板只提供真实可用动作；新建、切换会话和运行详情与页面按钮共用行为。没有当前 Run 时运行详情入口禁用并说明原因。

### 7.7 主导航展开与收起

主导航用于工作区级导航，会话历史用于当前聊天工作区内的 Thread 切换。两者保持独立，以便用户收起导航文字时仍可浏览历史。

- 展开态采用新版原型：顶部品牌与折叠按钮、“核心工作台”分组及带文字的导航项，底部连接摘要、命令面板、系统设置和本地用户区。
- 收起态保留相同顺序、选中态和可用性的图标；隐藏品牌文字、分组文字和统计徽标，为图标提供名称和悬停提示，并保留展开按钮。
- 点击折叠按钮或使用可用的 Cmd/Ctrl+B 切换；按钮提供 `aria-expanded`，切换后焦点仍停留在控制按钮。
- 折叠只修改前端布局状态与本地偏好，不发起 HTTP 请求，不重新加载会话，不中断 SSE，不清空草稿、审批选择或消息。
- 主导航中部在高度不足时独立滚动，顶部控制和底部命令入口保持可达；主区域及悬浮输入区同步调整位置。
- 两份 HTML 展示的是静态布局；折叠按钮、偏好保存和窄屏覆盖行为属于待实现交互，不能因原型存在按钮便视为已实现。

## 8. Run 状态模型

| 状态 | 界面文案 | 主操作 | 输入框 |
| --- | --- | --- | --- |
| running | 运行中 | 取消运行 | 禁用 |
| interrupted | 等待审批 | 提交审批 / 取消 | 禁用 |
| completed | 已完成 | 发送下一条消息 | 启用 |
| cancelled | 已取消 | 发送下一条消息 | 启用 |
| error | 运行失败 | 查看错误 / 发送下一条消息 | 启用 |

状态不得只靠颜色区分。running 使用进度反馈但不展示虚假百分比；interrupted 必须比普通通知更醒目；error 在对应 Run 时间线内展示，不只使用 toast。

## 9. 前端数据模型

建议将网络事件归一化为以下客户端状态：

```text
WorkspaceView
  selectedThreadId
  navigationExpandedPreference
  sidebarOverlay（none / navigation / history）
  historyFilter
  commandPaletteOpen
  runDetailsOpen

ThreadView（按 thread_id 隔离）
  thread
  draft
  messagesBySeq
  previewBySeq
  currentRun
    id
    status
    usage
    usagePending
    approvalRequests
    durableEventsBySeq
    connectionState
```

客户端 reducer 是唯一写入投影的入口。POST stream、GET stream 和审批恢复 stream 都复用同一个 SSE parser 和 reducer，避免三套行为分叉。

连接状态与 Run 状态必须分开：

- `connectionState`: connecting、open、closed、recoverable_error。
- `run.status`: running、interrupted、completed、cancelled、error。

连接断开时不得自动将 Run 标记为 error。若已知 run_id，提供“重新连接”调用 GET stream；每次重连先清空该 Run 的临时投影，再用全量流重建，不能把 GET stream 当作增量续传。

会话切换要求：

- 每条流、草稿和消息投影绑定 thread_id / run_id；切换后旧请求迟到的数据不得写入新会话。
- 切换会话时可用 `AbortController` 关闭旧 HTTP 观察连接；这不等于取消后台 Run，也不能自动调用 cancel 接口。
- 保存浏览器已知的 thread_id → run_id 映射以支持刷新和切回后的 GET stream 重建；本地存储不是服务端 active Run 的权威来源，状态以重新观察结果为准。
- 发送响应尚未取得 run_id 时发生断连，不能自动重发 POST；提示执行状态待确认，按现有恢复能力处理，避免重复执行。

## 10. HTTP 与前端动作映射

| 用户动作 | HTTP | 成功处理 |
| --- | --- | --- |
| 打开工作台 | GET `/api/threads` | 写入 Thread 列表 |
| 新建会话 | POST `/api/threads` | 选中新 Thread |
| 打开会话 | GET `/api/threads/{thread_id}/messages` | 重建已提交消息 |
| 发送消息 | POST `/api/threads/{thread_id}/stream` | fetch 解析 SSE |
| 观察已知 Run | GET `/api/threads/{thread_id}/runs/{run_id}/stream` | 全量重建并跟随 |
| 查询 Run 消息 | GET `/api/threads/{thread_id}/runs/{run_id}/messages` | 只读消息列表 |
| 提交审批 | POST `/api/threads/{thread_id}/runs/{run_id}/approval-decisions` | 消费恢复 SSE |
| 取消 Run | POST `/api/threads/{thread_id}/runs/{run_id}/cancel` | 使用返回快照更新状态 |

主导航展开与收起、本地偏好保存、过滤、命令面板、打开运行详情、复制和 Markdown 导出不新增 HTTP 接口。发送请求只提交现有 `ChatRequest.message`，不附带原型中的模型、附件或思考开关。

POST SSE 必须使用 `fetch()` 读取 response body，不能使用 EventSource。当前不支持 cursor、查询参数或 Last-Event-ID。

## 11. 错误和空状态

- 无会话：说明工作台用途，并提供“新建会话”。
- 空会话：聚焦输入框，提供三条真实任务示例，不伪造历史。
- 404：会话或 Run 已不存在，返回会话列表。
- 409：Thread 忙或审批冲突，优先重建已知 Run；若不知道 run_id，说明当前接口无法恢复。
- 422：保留用户审批选择，标出无效动作。
- 503：展示临时不可用和重试倒计时，遵守 Retry-After。
- SSE `error`：标记观察失败，提示读取持久事实或重连；不把 Run 判为失败。
- lifecycle error：在消息时间线和 运行详情抽屉中展示 Run 错误。
- 离线：保留当前页面投影，恢复网络后由用户触发全量重连。

## 12. 可访问性与交互质量

- 正文和控件满足 WCAG AA 对比度。
- 所有状态变化通过 `aria-live` 提供适量播报，delta 不逐 token 播报。
- 命令面板、运行详情和审批参数弹层具备焦点锁、Esc 关闭与返回焦点；关闭弹层不取消 Run 或丢弃已选审批决策。
- 图标按钮具有可访问名称，禁用导航有可读的原因说明；触控端操作目标不直接照搬原型的紧凑尺寸。
- 所有操作可用键盘完成，焦点样式始终可见。
- 动画遵守 `prefers-reduced-motion`。
- 流式输出时自动滚动只在用户位于底部附近时生效；用户向上阅读后不抢夺滚动位置。
- 取消、审批提交等操作必须显示 pending 状态，防止重复请求。

## 13. 首版验收标准

1. 用户能创建 Thread、发送消息并看到流式 AI 内容。
2. 完整消息到达后正确覆盖 delta，重连不会出现重复消息。
3. 页面能正确区分连接结束和 Run 完成。
4. write_file 或 bash 触发审批时，工具不执行，界面显示全部动作和参数。
5. 用户能逐项批准或拒绝，提交后同一 run_id 继续执行。
6. 用户能取消 running 或 interrupted Run，并看到已提交 cancelled 状态。
7. 已知 run_id 时刷新页面可以通过 GET stream 全量重建。
8. token 用量按 metadata 展示，usage_pending 语义正确。
9. 404、409、422、503 和观察 error 均有明确恢复路径。
10. 桌面支持两份原型的导航状态：256px 展开 / 64px 收起，配合 256px 会话历史分别形成 512px / 320px 左侧占用；40px 顶栏、最大 840px 对话区和悬浮输入区保持正确对齐，无常驻右侧 Inspector。
11. 在 1440×900、1280×800、1024×768 和 390×844 视口下，均可完成发送、审批、取消和重连；输入区不遮挡最后一条消息及审批按钮。
12. 用户消息、Agent 正文、代码块、工具结果按原型层级呈现；代码可完整复制，长内容不撑宽页面。
13. 本地过滤、日期分组、命令面板和 Markdown 导出可用；导出范围清楚，未支持控件按第 6.4 节处理。
14. 切换会话不会串入旧流消息，也不会隐式取消旧 Run；已知 run_id 时切回可恢复观察。
15. 不展示占位模型、伪造 reasoning、上下文百分比、实时速度或准确耗时；无用量数据显示未知而非 0。
16. 主导航展开、收起和窄屏覆盖遵守第 6.3 节；展开前后菜单一致，会话历史不随导航文字一起隐藏，草稿、审批选择和 SSE 观察不受影响。
17. 用户主动选择的桌面导航状态可在刷新后恢复；窄屏自动布局不覆盖偏好；折叠按钮可通过键盘操作，收起后仍可展开。

## 14. 开发前建议补齐的后端接口

当前接口可以完成一次前端演示，但要形成可靠工作台，建议先补两个 P0 能力：

### P0.1 会话的当前 Run 定位

问题：Thread 列表不返回 active run_id，浏览器刷新后可能只知道 thread_id。若该 Thread 正在 running 或 interrupted，发送新消息会得到 409，但前端无法定位应重建的 Run。

建议任选一种接口：

- `GET /api/threads/{thread_id}/runs?limit=...`
- 或让 `GET /api/threads` 返回 `active_run: {id, status}`。

建议优先采用 Run 列表，它同时解决历史 Run 导航。

### P0.2 Run 快照和事件查询

问题：Runtime 已有 `read_run()` 与 `list_run_events()`，HTTP 尚未暴露。前端只能通过 SSE 重建，难以做普通刷新、运行详情和错误恢复。

建议增加：

- `GET /api/threads/{thread_id}/runs/{run_id}`
- `GET /api/threads/{thread_id}/runs/{run_id}/events`

### P1

- `PATCH /api/threads/{thread_id}`：保存 title。
- Thread 搜索、归档或删除前，先明确产品语义和级联策略。
- 工具能力查询接口，再建设 Tools 页面。
- 只读配置查询和受控修改接口，再建设 Settings 页面。
- 结构化子 Agent 事件契约，再建设委派视图。
- 按需补充模型、reasoning、联网策略与附件的请求契约后，再启用输入区对应控件。
- 先定义上下文占用、工具耗时和吞吐速率的数据口径，再恢复原型中的统计徽标与进度条。

## 15. 交付顺序

1. 依据两份 HTML 原型搭建导航展开 / 收起骨架、浅色视觉 token 与响应式偏移，明确真实控件和禁用占位。
2. SSE parser、按会话隔离的 Run reducer 和契约测试。
3. 会话历史、日期分组、本地过滤、空状态与会话切换。
4. 消息时间线、代码与工具区块、悬浮输入区、发送与完整状态机。
5. 内嵌审批、取消操作和工具栏状态联动。
6. 运行详情抽屉、用量摘要、已知 Run 重连、命令面板和 Markdown 导出。
7. 对照原型验收布局、滚动遮挡、键盘操作和错误恢复。

前端只消费 HTTP 和 SSE 契约，将持久事实投影为界面；视觉与布局以 HTML 原型为准，功能可用性以真实接口为准。
