## Problem Statement

用户希望在 Shikigen 页面中接入、创建、编辑、删除和测试工具，让这些工具之后能被工作流和定制 Agent 使用。当前项目已有内置工具、LangChain BaseTool、ToolRegistry 和启动时的 MCP 加载机制，但缺少可保存的工具定义、工具管理页面、通用 Python/HTTP 工具及相应管理 API。

工具来源各不相同：MCP 服务提供工具目录，Python 源码声明函数参数，HTTP 接口通过手工配置或 OpenAPI 文档描述请求。用户不希望重复录入已经存在的结构，也不希望为了接入新类型把所有配置塞进一个不断增大的通用 config 字典。

后续工作流需要在两个非 LLM 节点之间按属性传值。工具模块必须提供明确的输入结构、真实的结构化结果、稳定工具引用和不依赖模型的执行入口。用户处于学习阶段，本次需要一个能理解、能使用并方便扩展的首版。

## Solution

在主导航增加“扩展”，下设“工具”“MCP 服务”“技能”。工具页面统一管理 MCP、Python、HTTP 三类可调用工具；MCP 服务页面管理连接，并通过发现、预览和勾选把服务工具加入工具库；技能显示“暂未开放”。工具编辑采用完整页面，包含基本信息、专属配置、输入/输出结构和手动测试。

前端组件选型确定为 shadcn/ui、rjsf（react-jsonschema-form）和 AI Elements。shadcn/ui 提供基础控件与统一样式；工具配置表单按定义 schema 用 rjsf 动态渲染，测试参数表单按当前有效 input_schema 动态渲染；AI Elements 承载适用的工具输入、输出和状态展示。schema 本身的参数表格/高级 JSON 编辑继续保留，测试参数也提供 JSON 编辑入口。

MCP 支持本地 stdio 与远程 Streamable HTTP。Python 使用固定 main 入口，保留具名参数，由源码静态解析输入；已识别属性只读，未知类型可通过下拉补齐。HTTP 支持手工创建和首版 OpenAPI 导入，一项工具对应一个请求。

工具保存到项目实际加载的 config.json，Python 源码另存到配置旁的受管理目录，工具定义只保存代码路径。公共数据基类与类型专属子类表达定义，各类适配器接入已有运行时工具机制。后续消费者按稳定 ID 使用最新已保存定义，也能直接执行工具，无需创建 Agent 或调用 LLM。

三类工具共用输入校验、超时、取消和完整结果契约，保留 JSON 对象、数组、标量、null 与文本的实际类型。本次交付工具模块和后端复用接口；完整工作流与定制 Agent 页面另行开发。

## User Stories

1. 作为工具库用户，我希望从主导航进入“扩展”，以便集中找到工具、MCP 服务和后续技能能力。
2. 作为工具库用户，我希望在一个列表查看 MCP、Python 和 HTTP 工具，以便统一管理可复用工具。
3. 作为工具库用户，我希望按名称搜索并按类型、启用状态筛选，以便快速找到目标工具。
4. 作为工具库用户，我希望看到工具来源、用途和真实的最近测试结果，以便判断应该选择哪项工具。
5. 作为工具库用户，我希望在完整页面创建和编辑工具，以便有足够空间处理代码、参数和结果。
6. 作为工具库用户，我希望分别设置页面名称、调用名称和用途说明，以便兼顾页面阅读与模型选择。
7. 作为工具库用户，我希望系统生成合法且唯一的调用名称并明确提示冲突，以便避免同名工具被静默忽略。
8. 作为工具库用户，我希望改名和改配置后工具 ID 保持不变，以便后续引用仍指向原工具。
9. 作为工具库用户，我希望为每项工具设置独立超时，以便限制不同工具的执行等待时间。
10. 作为工具库用户，我希望启用或禁用工具，以便控制后续消费者的调用资格。
11. 作为工具库用户，我希望仍能显式测试禁用工具，以便修复工具后再开放使用。
12. 作为工具库用户，我希望保存前编辑保持为草稿，以便试验配置时不影响已保存工具。
13. 作为工具库用户，我希望离开修改中的页面时选择保存、放弃或继续编辑，以便避免丢失修改。
14. 作为工具库用户，我希望保存失败时保留草稿，以便修正问题后继续操作。
15. 作为工具库用户，我希望通过简单参数表格与高级 JSON Schema 编辑同一份输入结构，以便从简单配置逐步学习复杂结构。
16. 作为工具库用户，我希望复杂 schema 的约束、说明和示例在编辑切换后保留，以便避免工具行为被无意放宽。
17. 作为工具库用户，我希望无效 JSON 保留原文并指出错误，以便定位和修正输入结构。
18. 作为工具库用户，我希望输出结构可以不填并查看真实返回内容，以便先使用尚未声明输出 schema 的工具。
19. 作为 Python 工具作者，我希望只编写顶层 main 与辅助函数，以便使用具名参数而无需把全部参数改成 args。
20. 作为 Python 工具作者，我希望系统静态解析参数名称、常见类型和必填性，以便避免重复录入。
21. 作为 Python 工具作者，我希望源码确定的属性只读预览、未知类型用下拉补齐，以便让表单与源码保持一致。
22. 作为 Python 工具作者，我希望补充参数说明、嵌套结构和业务约束，以便准确描述代码不能完整表达的输入要求。
23. 作为 Python 工具作者，我希望修改源码后保留兼容补充并看到不兼容变更，以便正确更新参数结构。
24. 作为 Python 工具作者，我希望解析和保存不执行用户代码，以便录入代码不会触发其业务操作。
25. 作为 Python 工具作者，我希望函数默认参数正常生效而测试输入不被自动填值，以便理解实际传入的参数。
26. 作为 Python 工具作者，我希望测试使用后端解释器和已安装依赖，以便不维护每工具独立环境。
27. 作为 Python 工具作者，我希望分别查看返回值与 stdout/stderr，以便调试时不混淆打印内容和业务结果。
28. 作为 MCP 服务用户，我希望单独保存 stdio 或 Streamable HTTP 连接，以便同一服务提供多个工具而不重复配置。
29. 作为 MCP 服务用户，我希望合法连接在服务暂时不可达时仍能保存，以便先完成录入。
30. 作为 MCP 服务用户，我希望分别测试连接、发现工具和执行业务工具，以便每次操作的效果明确。
31. 作为 MCP 服务用户，我希望发现后预览并勾选入库工具，以便只接入需要的能力。
32. 作为 MCP 服务用户，我希望远端工具身份和来源 schema 只读、本地信息可编辑，以便保留服务契约并优化工具说明。
33. 作为 MCP 服务用户，我希望重新发现同一来源时保留工具 ID 和本地配置，以便已有引用保持有效。
34. 作为 MCP 服务用户，我希望发现失败或本次未发现某工具时保留已有工具，以便暂时网络变化不会删除配置。
35. 作为 MCP 服务用户，我希望删除连接时确认其旗下工具并一起删除，以便避免留下无法使用的定义。
36. 作为 HTTP 工具作者，我希望手工设置方法、地址、请求头、参数映射与认证，以便接入单个接口。
37. 作为 HTTP 工具作者，我希望 path、query、headers、body 分组保留，以便不同位置的同名参数不会覆盖。
38. 作为 HTTP 工具作者，我希望上传或粘贴 OpenAPI JSON/YAML 文档，以便减少接口录入工作。
39. 作为 HTTP 工具作者，我希望接口名称、请求地址和参数分别读取，以便系统不会根据参数猜测接口身份。
40. 作为 HTTP 工具作者，我希望选择接口并在预览补齐地址、变量和认证，以便只保存可执行的所选工具。
41. 作为 HTTP 工具作者，我希望不支持的请求结构显示到具体接口与字段，以便取消该项后仍能导入正常接口。
42. 作为 HTTP 工具作者，我希望复杂输出不阻止受支持请求导入，以便仍能测试并查看实际响应。
43. 作为 HTTP 工具作者，我希望导入后可编辑、再次导入创建新工具，以便原工具不被意外覆盖。
44. 作为工具库用户，我希望在页面填写并保存密钥且读取时隐藏实际值，以便方便配置认证而减少回显泄露。
45. 作为工具库用户，我希望留空保留密钥、填写替换、显式清空删除，以便不会因为编辑其他信息而丢失认证。
46. 作为工具库用户，我希望通过 schema 动态表单或 JSON 编辑输入参数对象，测试已保存工具或有效草稿，以便在保存前验证实际行为。
47. 作为工具库用户，我希望测试不会自动保存草稿，以便测试与正式修改分别生效。
48. 作为工具库用户，我希望看到成功、失败、超时或取消及完整详情，以便知道真实执行结果。
49. 作为工具库用户，我希望取消等待中的测试，以便结束本次本机执行和连接等待。
50. 作为工具库用户，我希望测试运行中锁定编辑并在离开时先处理测试，以便结果始终对应实际测试内容。
51. 作为工具库用户，我希望测试后修改配置时标记旧结果，以便不会把修改前的成功当作当前结果。
52. 作为工具库用户，我希望非成功 HTTP 响应仍显示状态和响应内容，以便诊断接口问题。
53. 作为工具库用户，我希望 MCP 保留结构化结果、多内容块和错误内容，以便不会在适配过程中丢失信息。
54. 作为工具库用户，我希望超大返回或不支持的二进制响应明确失败，以便不会把截断数据当成完整结果。
55. 作为工具库用户，我希望工具保存保留项目其他配置与环境引用，以便管理工具不影响既有设置。
56. 作为工具库用户，我希望保存提交与旧文件清理问题分别反馈，以便不会误认为已生效的保存失败并重复创建。
57. 作为工具库用户，我希望保存响应不明时先重新读取核实，以便避免重复提交。
58. 作为工具库用户，我希望磁盘修改触发刷新或草稿冲突提示，以便不会覆盖外部修改或执行未经核实的旧内容。
59. 作为工具库用户，我希望删除工具明确说明引用影响且仅清理受管理文件，以便正确理解删除后果。
60. 作为后续工作流开发者，我希望按工具 ID 直接执行并取得真实 JSON 属性，以便在两个非 LLM 节点之间映射参数。
61. 作为后续工作流开发者，我希望每次下游调用严格校验实际输入，以便缺失字段或错误类型不会继续执行。
62. 作为后续 Agent 开发者，我希望按稳定 ID 构建 BaseTool 集合且缺失、禁用或构建失败时明确报错，以便正确装配所选工具。
63. 作为后续消费者开发者，我希望新调用使用最新保存内容、已开始调用继续使用取得内容，以便修改和删除的生效时点明确。
64. 作为工具类型扩展开发者，我希望新增专属定义和适配器即可接入，以便无需改造公共字段或创建混合配置。
65. 作为 MCP 后续升级开发者，我希望会话获取和释放留有独立边界，以便将来支持常驻会话和跨会话调用。
66. 作为工具库用户，我希望表单随工具类型和当前有效 schema 渲染字段、分组及嵌套结构，以便无需为每项工具重写参数页面。

## Implementation Decisions

- **工具页面原型**：涉及工具页的开发与验收，先读取并遵循[工具页面原型与参照规则](../../../../frontend/design.md#工具页面原型)。
- **组件选型**：使用 shadcn/ui 基础控件、rjsf 动态 schema 表单、Vercel AI Elements 中适用的工具展示组件。rjsf 使用与项目 shadcn 样式一致的主题，优先采用官方 shadcn 主题，必要的只读预览、类型补齐、凭据及空值控件通过定制字段或 widget 接入。沿用现有 React、Vite、Tauri、Tailwind、后端通信与运行事实；组件展示接收本项目工具结果，保留四种执行状态与完整详情。
- **复用已接入基础**：项目已具有 shadcn 基础控件、Radix Collapsible、统一主题语义和 AI Elements Reasoning 本地适配；四个 rjsf 包已固定为 6.11.0，Testing Library/jsdom 也已接入。工具专项复用这些基础及版本，仅按需追加 Form、Tool 相关业务适配和实际所需控件，不重复初始化组件库或迁移通信/消息状态。依赖安装不代表工具页面已完成，Reasoning 不代表全部 AI Elements 组件已经可用。
- **rjsf 实际接入**：激活 shadcn 主题在项目 Tailwind 构建中的样式扫描，沿用现有语义映射；主题包内控件不会自动同步本地控件，按需求通过 widgets/templates 适配，不导入带完整 reset 的第二套全局样式。校验器按真实 schema 的方言配置，并遵循不强制 format、不转换、不填默认和不删字段规则；不能把默认 draft-07 校验器当作所有来源 schema 已兼容。无法准确渲染的受支持结构保留原 schema，走高级 JSON 与后端诊断。实际业务 Form 需验证浏览器构建和 Tauri WebView 的校验环境。
- **AI Elements 工具呈现适配**：按当前项目的本地源码路线选取 Tool 等组件、记录固定来源及本地适配，保留既有阅读、完整查看和复制能力。显示状态来自真实测试进度及工具结果，成功、失败、超时、取消独立表达，不把取消当拒绝审批。结果区显式区分未取得内容与真实 null、false、0、空字符串/容器；不能沿用上游对结果真假值的过滤。业务 data 保持实际类型，JSON 格式化只服务显示与复制，不修改执行结果，不为使用展示组件改成 AI SDK transport 或另建 store。
- **动态表单的 schema 分工**：管理表单的渲染 schema 描述公共与类型专属工具配置，测试参数表单直接使用当前有效 input_schema 描述业务 inputs。uiSchema 仅控制布局、控件和只读展示，不作为另一份业务参数定义，不改变保存的输入约束。基础配置、类型配置和凭据等按相应管理 schema 渲染；源码、参数结构编辑和结果查看可作为专门区块或定制字段组合。
- **schema 编辑与参数填写**：rjsf 动态表单用于填写配置或实际参数值；编辑 input_schema 本身仍用已确认的简单参数表格、Python 解析预览和高级 JSON 编辑。Python 源码确定的参数属性及 MCP 来源结构保持只读，手动测试时这些参数的实际值可以填写。未知 Python 类型先补齐形成有效 schema，再渲染可测试参数表单。工具定义变动后重新使用有效 schema；不能为迎合控件而删除约束或悄悄丢弃原输入。
- **动态输入的真实值**：测试表单与高级 JSON 编辑共用一个 inputs 对象，能无损表达嵌套对象、数组、枚举、可选值及 null，保留未提供、空字符串、false、0、空数组/对象与 null 的区别；只有满足 schema 与位置规则的输入可测试。关闭业务输入的自动默认值、示例、首个枚举、布尔或数组占位填充，不使用类型转换或移除额外字段等自动修正。前端 validator 提供早期错误反馈，并遵循不强制 format 的既定策略；后端继续决定实际输入是否有效。动态控件不能准确表达某项受支持 schema 时，保留完整 schema 和输入并使用高级 JSON 入口，明确原因，不绕过后端校验。
- **定义与运行分层**：新增公共数据基类 ToolDefinition，以及 McpToolDefinition、PythonToolDefinition、HttpToolDefinition 专属子类，用 kind 区分 mcp、python、http。定义负责保存、校验和传输；运行执行由适配器负责。专属字段可以分组为明确子模型，不创建混合所有类型字段的通用 config 字典。
- **公共字段**：包含系统生成的稳定 id、kind、display_name、name、description、input_schema、可选 output_schema、enabled、created_at、updated_at、timeout_seconds。display_name 可中文和重复；name 是合法、工具库内唯一且避开内置工具名的调用名称。前端生成候选名称，后端提供名称校验且保存时再次检查；具体职责见[名称与稳定引用](../../../wayfinder/tools-workflow/tickets/002-definition-adapters-references.resolution.md#名称与稳定引用)。手动冲突明确阻止保存或装配，不能依赖 Registry 静默去重。
- **身份与类型**：编辑不改变工具 ID；工具类型创建后固定，换类型创建新工具。消费者保存 tool_id 并读取最新已保存定义。改参数后仍校验实际输入，不提供工具版本、自动参数迁移或历史定义快照。
- **适配器接入**：在后端代码登记 kind 到适配器的映射，按专属定义构建 BaseTool 并接入现有 ToolRegistry。管理服务统一负责保存、读取和选择检查；适配器不另建定义存储。新类型增加专属定义、适配器登记和对应表单。OpenAPI 是生成 HTTP 定义的导入器，不是第四种运行类型。
- **最小复用接口**：提供 get_tool 读取定义、build_tools 根据 ID 集合检查并构建 BaseTool、execute_tool 根据 ID 与 inputs 直接执行。缺失、禁用、未支持或构建失败明确返回问题，不静默跳过。直接执行不依赖 Agent、LLM 或完整 Run。BaseTool 封装保留完整工具结果，不能只取普通调用的正文而丢失状态及附加数据。
- **唯一输入定义**：input_schema 保存完整 JSON Schema，顶层为参数对象；无参数也声明对象结构。简单表格、高级编辑、源码解析候选和导入候选最终读写同一份 schema，不另存第二套参数配置。执行入口显式实施 schema 校验，不能把 BaseTool 接收字典等同于已校验。
- **严格输入校验**：校验类型、必填、枚举、范围及嵌套约束，不自动类型转换、不注入 schema 默认值或示例。保留和展示 format，首版不强制检查 format。不支持或无法解析的 schema 明确失败，不能跳过校验。运行时输入校验与 OpenAPI 导入支持子集分别处理。
- **输出与字段传递**：output_schema 描述业务 data，保持可选，不做输出转换或从单次测试自动生成。工具结果保留对象、数组、标量、null 与文本实际类型。后续映射先取得上游真实值、检查上游 status、组装下游 inputs，再按下游 schema 校验；本模块提供这些契约，映射 UI 和调度不在本次实现范围。
- **统一结果**：结果包含 status、data、error、duration_ms、details。status 为 success、error、timeout、cancelled；成功 error 为 null，其他情况提供可识别 code、脱敏 message 和必要位置。失败取得实际业务响应时仍保留 data，否则为 null。details 保留类型专属事实，duration_ms 包含已完成清理。未知异常转为执行错误，不当作成功内容。
- **预算与限额**：每工具 timeout_seconds 默认 30，范围 1–300 秒；预算覆盖启动或连接、业务执行及读取结果，清理可额外耗时。MCP 连接测试和发现默认 30 秒，可按连接调整。原始实际返回上限 1 MiB，按 UTF-8 JSON/文本及 MCP 编码内容计量，超出明确 output_limit 错误，不提供截断成功数据。Python stdout/stderr 仅保留最后 64 KiB 并标记截断。
- **取消与清理**：手动测试可取消；Python 终止并回收本次子进程，HTTP/MCP 取消本次等待并清理持有连接。首版不自动重试、撤销或承诺远端操作和派生进程已经停止。超时和取消分别表达。
- **Python 专属定义**：持久定义保存 code_path，不内联源码，不配置 entry_function。唯一入口为顶层同步 main，可包含辅助函数；按 inputs 字段名绑定参数。支持普通具名参数、函数默认参数、仅关键字参数及受 schema 控制的额外关键字参数。不支持仅位置参数、可变位置参数、异步或生成器入口、类方法；缺少、重复或不支持入口明确诊断。
- **Python 静态解析**：用 AST 读取入口和参数，录入、解析、保存不执行或 import 用户代码，不 eval 注解或默认表达式。识别 str、int、float、bool、普通 list/dict、list[T]、dict[str, T] 及常见可空注解。是否必填由是否存在函数默认值决定，与是否允许 null 分开；默认表达式仅展示，不自动作为测试输入。
- **Python 参数编辑**：源码确定的名称、类型、必填性和默认值只读。未知类型显示“待补”，下拉选择字符串、整数、数字、布尔、对象、数组等 JSON 类型；形成有效 schema 后才能保存或测试。高级编辑可补说明、示例、约束、未明确的容器内部结构及额外关键字业务字段，不能改写源码明确属性。普通容器可明确开放；额外属性也必须由 schema 声明或显式允许。仅补 JSON 类型不自动构造自定义 Python 对象。
- **Python 源码同步**：源码修改后自动静态解析，保存或测试前重新核对。保留同名兼容字段补充和仍未知类型的既有选择；新增未知类型待补。删除、改名、类型不兼容、必填性变化明确展示；改名按删除加新增，不猜迁移。新增明确注解以源码为准，冲突要求重新补齐。解析失败保留原文及补充，不使用未经核实的旧结构继续执行；解析候选不作为第二套持久定义。
- **Python 执行**：每次调用使用后端同一解释器启动独立本机子进程，在独立临时工作目录运行取得的源码并清理临时执行文件。支持标准库和已安装依赖，不自动安装依赖或建立每工具环境。本机权限子进程不是安全沙箱。输入校验后在执行子进程核对实际签名和参数绑定；函数默认值按 Python 规则生效。返回严格 JSON，NaN、Infinity、不可序列化对象明确失败；打印是调试内容而非返回协议。
- **MCP 连接定义**：连接独立于工具保存并有稳定 ID；stdio 配置 command、args、env、cwd 等，Streamable HTTP 配置 url、headers 等。MCP 工具保存 server_id、remote_name 与发现得到的结构，同一连接供多个工具引用。工具所属连接、远端身份和来源输入/输出 schema 只读；本地名称、说明、启用、超时可编辑，后端同样检查此边界。
- **MCP 发现生命周期**：连接格式合法即可保存，可达性失败不阻止录入。测试连接、工具发现和业务调用分别操作；保存与发现不调用业务工具。先发现和预览，再勾选添加或应用更新。相同连接 ID 加远端身份对应一项入库工具，再次发现保留原 ID。选中更新仅更新远端来源结构，保留本地名称、说明、启用及超时；未选变更不写入。发现失败保留原结构；本次未发现项标记提示，不自动删除或禁用。远端改名不猜为原工具改名。
- **MCP 连接编辑与会话**：连接命令、地址和凭据可修改并保留连接 ID，提示重新发现核对结构，不自动改已入库 schema；工具换连接需重新发现创建。首版每次操作独立初始化会话、结束后关闭，不保证 stdio 进程状态跨调用保留。适配器通过会话提供者获取和释放会话，为后续常驻或跨会话调用留边界，当前不实现会话池。
- **MCP 结果保真**：业务 data 优先 structuredContent，没有时为原始内容块数组；details 保留完整原始返回及来源，多块、错误内容和附加数据不能只经过有损转换器。isError、SDK 协议或来源输出校验异常均为失败，保持清楚诊断。来源 output_schema 保持只读。
- **HTTP 专属定义**：保存单请求方法、HTTP/HTTPS 地址模板、固定请求头、参数位置与映射、必要序列化规则、JSON 请求体规则、认证要求与绑定、可选导入来源。支持 GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS。inputs 按 path、query、headers、body 分组。映射只存位置、目标名、取值位置及序列化，不复制类型与必填定义；保存前核对 schema、映射、地址占位符的一致性。
- **HTTP 参数范围**：path/header 支持字符串、整数、数字、布尔等标量的 simple 序列化；query 支持 form 标量及标量数组，依 explode 编成重复键或逗号分隔，未声明时遵循对应默认值。body 支持 application/json 及嵌套对象、数组。手工与导入共用该请求范围；不支持的类型或序列化明确诊断。
- **HTTP 缺失与空值**：可选参数缺失则不发送；path/query/header 的显式 null 报错，空字符串保留。body 字段 null 和整个 body 显式 null 保留为 JSON null，body 缺失不发送请求体。布尔编码为 true/false，其余按已保存规则编码，不能直接采用 SDK 对缺失与 null 的模糊默认行为。
- **HTTP 认证与响应**：支持无认证、Bearer、API Key 的 header/query 位置；凭据独立于业务输入。认证目标冲突明确报错。HTTP 工具不跟随重定向；2xx 成功，其他状态失败且保留受支持响应体与状态。合法 JSON 保留 JSON，否则返回受支持文本；空响应保持为空，文件和二进制明确未支持。details 保留状态、响应类型和脱敏响应头，输出 schema 不强制验证。
- **OpenAPI 入口**：上传或粘贴单份 JSON/YAML 文档，识别 OpenAPI 3.0.x、3.1.x 的常用子集。流程为解析、选择接口、预览补配置、保存；一 operation 一 HTTP 工具，只保存勾选项。预览及保存不调用接口；HTTP 手工创建仍可用。
- **OpenAPI 名称和地址**：方法与路径来自 operation，调用名称优先从 operationId 生成，缺失则从方法和路径生成合法候选，预览可修改；不依据参数猜名称。parameters 与 requestBody 提供业务输入。服务器按 operation、path、文档级优先读取，多地址可选择，相对地址和变量需补齐成有效地址；调用名称不决定请求目标。summary/description 预填本地信息，无用途说明需补充。
- **OpenAPI 参数与引用**：合并路径级及 operation 级参数，按名称和位置识别，operation 覆盖路径级，同层重复冲突报错。路径占位符必须有对应必填参数。支持所选请求使用的内部引用，包括 schema、parameter、requestBody；无法解析、循环或外部引用阻止受影响接口保存。保留常见类型、对象、数组、必填、枚举、数值范围、字符串模式及长度、数组边界、普通附加属性约束、说明和示例。
- **OpenAPI 可空及不支持项**：处理 3.0 nullable 和 3.1 普通结构加 null 的常见等价表达；通用组合结构、自定义 dialect 明确未支持，不删约束后导入。请求不支持文件、表单、cookie、path/header 对象或数组、label/matrix、query 对象、deepObject、spaceDelimited、pipeDelimited、parameter content 和特殊保留字符规则。多请求媒体类型可选受支持 JSON；仅有未支持类型时诊断。嵌套对象本身不是循环引用。
- **OpenAPI 认证**：operation 级要求优先，缺省继承文档级，显式无认证按文档执行。多个备选方案允许选择受支持方案；同一方案多个要求必须全部满足。认证缺失需补齐，不支持要求或凭据位置冲突明确诊断，不降级成匿名调用，也不把密钥暴露为模型参数。
- **OpenAPI 诊断与输出**：按接口显示“可保存／需要补配置／未支持”，包含方法、路径、字段或引用位置、原因和可采取动作。所选输入全部就绪才整批保存；未选复杂接口不阻挡正常项。保留相关来源片段。只有一种受支持 JSON 成功输出时预填可选 output_schema；多结构、复杂或未声明输出则留空说明并保留来源，不阻止受支持请求导入。
- **HTTP 导入后编辑**：名称、说明、地址、方法、参数映射、schema、认证可编辑，保留 ID；执行以保存定义为准。再次导入生成新预览和新 ID，不覆盖旧工具，不做来源同步、合并或版本迁移。
- **配置存储**：扩展现有配置模型，在项目实际加载的原始 JSON 中保存 tool_library，包含 tools 与独立 mcp_connections。保留既有其他分组、相对路径和环境引用，不序列化已展开的 runtime.config 覆盖原文。工具库字符串、schema、示例和来源按字面保存读取，不套用既有递归环境展开；原分组继续原行为。新连接与原有启动 MCP 自动装配集合分开，工具保存不自动挂载当前聊天 Agent。
- **代码持久化与保存顺序**：持久代码路径相对配置文件目录解析，不依赖进程 cwd。完整新代码先写入受管理目录的新生成文件并关闭，保留旧引用文件；新配置临时文件在同一文件系统准备完整，再替换原配置，最后清理已不被引用的旧生成文件。工具 ID 不变，文件生成标记不是工具历史版本。配置替换成功是提交点；此前失败保持原定义与代码，此后清理失败返回已保存及清理警告。仅清理规定目录内受管理、生成且未引用文件，不删除任意用户文件。
- **批量及不明保存结果**：创建、编辑、发现应用和导入保存先校验整批名称、来源身份、schema、类型权限和映射；所选批次一次配置提交，验证失败不能保存一半。响应区分未提交失败与已提交带清理问题。断开而未获结果显示“工具保存结果待确认”，重新读取核实，不自动重试创建或认定未生效。首版不提供多文件事务或断电恢复保证。
- **凭据录入与隐藏**：页面密码框直接录入，真实字符串保存到同一配置，首版不加密。管理读取仅返回已设置标志；留空保留、填写替换、显式清空删除。实际值只供内部执行使用；管理响应、日志、诊断、错误、展示结果及后续消费者结果对已知凭据遮盖。工具草稿或填写密钥不写浏览器本地存储。
- **生效与执行内容**：每次新调用读取最新保存定义、连接、凭据和完整源码，并固定为本次执行内容；之后修改、禁用或删除影响下一次调用，当前调用继续且可独立取消。已经构建的 BaseTool 每次新调用也重新检查最新定义和资格。源码读取与保存清理协调，执行用取得的临时副本，避免取得旧路径后文件先被清理。工具库热更新无需重启，其他配置继续既有规则。
- **外部编辑与冲突**：打开列表/详情、手动刷新、保存和开始已保存调用时检查配置及代码变化，不增加后台监视器。未编辑页重读，脏草稿保留并提示冲突，编辑/删除带读取版本，提交前再次核对；服务协调自身写入。外部编辑器不参加该协调，首版按先外部保存、再刷新页面编辑使用，不承诺同时外部写入互斥。缺失、坏配置不偷偷执行缓存；缺失代码、非法路径、源码接口不一致定位到受影响工具。仅函数体兼容修改可供新调用使用，接口不兼容需重新解析、补齐、保存。
- **删除语义**：工具确认后直接删除，无回收站；说明未来 ID 引用报不存在，不查询尚未实现的消费者引用表。删除 MCP 连接先列旗下工具及数量，再一次移除连接与其工具。删除配置提交后代码清理失败返回“已删除，文件清理失败”，不当作删除未生效。删除不撤销已开始调用。
- **页面导航与布局**：将原禁用工具入口改为“扩展”，下设工具、MCP 服务、技能；技能暂未开放。沿用全局应用栏、导航、冷灰侧栏和靛蓝操作色，聊天历史仅用于聊天。列表展示公共信息、类型和来源，支持搜索筛选；编辑用完整页面与显式保存、返回。MCP 连接列表可进入所属工具；读取失败保留可读旧视图并明确未核实，不能把它作为执行依据。
- **schema 编辑体验**：简单表格只编辑可准确表达字段；复杂结构摘要进入高级编辑。单字段改动保留其他关键字、约束、说明和示例，不从简化表格重建全部 schema；无法无损表达时禁止简单改类型。高级 JSON 错误保留文本并阻止保存/测试。HTTP 保留分组及映射一致性，MCP 来源只读，Python 遵循解析预览规则。无输出 schema 明确显示“未声明输出结构”。
- **草稿与启用**：显式保存；页面内存维护工具、连接及导入草稿，不跨重启恢复。离开脏页面提供保存并离开、放弃、继续；失败保留内容。新工具默认启用；正常消费者禁用即失败。显式手动测试允许禁用工具，使用独立测试意图和同一执行器，正常 execute_tool 不提供绕过启用检查入口。
- **手动测试交互**：实际输入为 JSON 对象，以 rjsf 按当前有效 input_schema 动态生成表单，并提供共用 inputs 的高级 JSON 编辑和参数说明；结果使用适用的 AI Elements 展示组件，显示状态、耗时、data、错误及专属详情并支持完整查看复制。同一编辑页一次测试，运行期间锁编辑与保存，可取消。离开先选择取消测试并离开或继续测试，之后再处理脏草稿。完成恢复编辑；再改相关配置标为“修改前的测试结果”。最近结果及时间仅当前页面内存可用于列表，无记录显示未测试，不写配置或历史库，不推断持续在线。
- **后端公开管理契约**：新增工具列表/详情、创建/更新/启用/删除、MCP 连接管理、连接测试/发现/应用、Python 静态解析、OpenAPI 预览/批量保存、开始/查询/取消测试行为。管理返回稳定 ID、编辑版本及脱敏配置，Python 编辑可读源码但持久定义只有路径。发现应用检查连接与库版本；测试临时身份可观察和取消，不建立持久测试历史或完整 Agent Run。具体方法、路由、DTO 按项目风格落实，不创建无约束覆盖整份配置的 API。
- **现有系统接入**：沿用 FastAPI runtime 注入、资源生命周期与现有前端 BackendClient 的宿主身份和取消机制，新增工具操作与页面导航。需要新 HTTP 方法时同步桌面 CORS。后端决定保存、编辑和执行是否有效，UI 只提供早期反馈。直接使用的 schema 校验依赖显式声明；已有聊天、内置工具、旧配置 MCP 与宿主行为应保留。

## Testing Decisions

- 用户已确认以后端公开 HTTP API 为主要集成测试边界：沿用 create_app 注入 runtime 与 HTTPX ASGITransport 的现有测试方式，把临时配置、存储、管理服务和统一执行器一起检查。优先断言响应、真实请求、磁盘已保存内容及清理后可观察行为，不依赖私有函数、类层级、适配器调用次数或内部字段组织。只在外部失败难以稳定制造时对最窄 I/O 边界注入故障。
- Python 测试执行真实本机子进程；HTTP 和 MCP 使用本地可控测试服务，MCP 分别覆盖 stdio 和 Streamable HTTP。测试不依赖用户密钥、公网服务或 LLM。临时项目配置和测试服务退出后清理；取消与超时测试以可控阻塞条件同步，避免仅依赖固定 sleep。
- 主 API 场景覆盖创建、详情、搜索/筛选所需信息、编辑、启用/禁用、删除及稳定 ID；重复调用名称、内置名称冲突、固定类型、MCP 来源只读、读取版本冲突都必须被后端拒绝。独立连接与库保存不自动挂载现有聊天 Agent。
- 输入与解析场景覆盖多具名参数、默认值与 nullable 的区别、关键字参数、额外关键字字段、未知类型补齐、缺少或重复 main、不支持签名、静态解析不执行代码。严格类型、必填、枚举、范围、嵌套输入和源签名绑定失败在业务执行前得到诊断；修改源码后兼容补充保留，不兼容变化明确要求处理。
- 配置行为覆盖其他分组、环境引用、相对路径和工具库字面字符串保持；改变启动 cwd 不改变代码路径基准。新代码写入或配置替换失败保留原工具；提交后清理失败显示已提交警告。批次任一无效不部分提交，保存回复未知后重读可核实。只清理受管理生成文件，坏配置、缺失代码及不兼容外部修改明确失败。
- 生效场景用可控正在运行调用验证取得内容后修改、禁用、删除不会改变该调用，下一次使用最新内容或明确拒绝；包含已构建 BaseTool 的再次调用。小范围后端公开复用接口测试确认 get_tool、build_tools、execute_tool 与 API 共用结果和校验、保留完整结果；不为每类适配器再建一套测试架构。
- MCP 场景覆盖连接暂时失败可保存、连接测试与发现不执行业务工具、仅勾选入库、重复发现保留 ID 和本地编辑、选中结构更新、发现失败与未发现项保留。执行覆盖 structuredContent、多块原始结果、isError、协议异常和会话清理，不声称验证了远端业务撤销。
- HTTP 场景由本地服务断言实际方法、地址、编码、请求头和 JSON body；包括同名 path/query、query 两种数组序列化、可选缺失、空字符串、非法 null、body 缺失与整包 null、认证注入。覆盖 JSON、文本、空、非 2xx、重定向、二进制和超大响应，确认失败事实及受支持内容保留。
- OpenAPI 场景通过公开预览/保存入口覆盖 JSON/YAML、两种版本、名称与参数独立、地址优先级与变量、参数覆盖、内部引用、嵌套和可空、认证备选/组合、逐接口诊断、复杂输出不阻断请求。支持项与不支持项混合时取消无效项能保存其余；所选无效不能保存一半；再次导入新 ID 且旧定义不变。
- 统一执行场景覆盖四种 status、实际数据类型、输入错误不触发业务调用、超时和取消清理、Python 默认参数及严格 JSON 返回、调试输出截断、实际结果上限。所有管理读取、错误、结果和可复制内容检查已知凭据不回显；留空保留、替换、显式清空分别验证。
- 前端沿用现有 Node test 与公开状态/BackendClient 行为测试，覆盖草稿保存失败保留、未知保存结果先核实、宿主失效取消旧请求、脏页面离开、运行中锁定及取消、旧测试结果标记、schema 无损编辑和 Python 属性权限。补充针对确认交互的页面验收：扩展导航、完整编辑页、只读属性、下拉补齐、错误定位、键盘/焦点和真实结果完整查看；不为静态文案或实现结构写镜像测试。
- 动态表单验收覆盖三类配置 schema、嵌套参数、数组、枚举、可选/可空字段、schema 更新与 JSON 模式无损切换。对带 default、必填布尔、minItems 的 schema，未操作表单不能自动产生业务值；显式 false、0、空字符串与 null 仍按原值提交，无法表达时能通过 JSON 入口处理。Python/MCP 属性只读不阻止填写测试值；前端 format 提示不得额外阻止后端允许的输入。shadcn/rjsf 样式和 AI Elements 的完整结果、错误/超时/取消展示在实际页面验收，不仅断言某个组件被调用。
- 复用现有 Testing Library/jsdom 挂载真实 rjsf 业务 Form 和工具结果组件，操作 DOM 验证初始未自动填值、真实提交 inputs、模式切换、错误定位、格式策略及 null/false/0/空字符串结果可见。保留真实业务状态与 BackendClient，模拟 HTTP 传输边界，不以自建假表单代替 rjsf；样式、滚动、焦点和实际 AJV 校验在 Tauri 页面验收，依赖导出或空页面构建不能替代这些证据。
- 既有参照包括后端 ServerTests 的公开 HTTP 生命周期/错误行为、WorkspaceResourceTests 的文件替换与版本冲突、配置测试的校验和凭据保护、工具 Registry 与 MCP loader 契约；前端已有 BackendClient 宿主身份测试、会话草稿和取消状态测试、工具结果完整展示与原生交互验收。复用方法，不复制旧 MCP loader 的静默跳过或自动重试语义到新工具库。
- 开发阶段按改动执行相关后端 unittest、前端 pnpm test 与 pnpm build，并完成上述页面和 Windows 文件保存/清理验收。规格发布阶段只检查文档结构、链接和决议覆盖，不把它报告为应用测试通过。
