## 拆分原则与发布安排

- 每票交付一条可演示或可公开查询验证的用户路径；所需持久契约、API／原生入口、客户端、呈现与边界验证在该票内完成，已有能力直接复用。
- 第一票把会话事实／输入所有者的必要整理接入真实读取路径；完整 SSE 接入继续由对应票交付。各票从开始沿用定稿风格，票据正文使用领域术语、接口名和可观察行为，不绑定源码位置。
- 工作 frontier：阻塞票全部完成即可开始，每次推进一票；顺序是建议，用户可自主安排已就绪分支。阻塞关系表示可复用输入或行为的真实前提，不以相邻序号制造依赖。
- 已按用户后续提出的目录与文件粒度要求，发布到 docs/wayfinder/frontend-completion/implementation/：每票一个文件，索引按依赖顺序编排、Blocked by 使用完整标题链接；状态 ready-for-agent 表示描述自足，实施仍由用户主导。
- 父规格、地图和既有决议保持其完成状态；此草案的确认只针对实施拆分。

## 跨票完成要求

- 每票验收针对用户可见行为、公开请求／响应及已提交事实，不断言私有状态组织；优先复用现有 HTTP／SSE、BackendSession、Runtime 和原生验收入口。具体错误只影响所属区域，保留事实和输入。
- 所有写操作由用户主动，未知结果先 GET 核实；状态、字段省略／null、身份过滤、重试和 Retry-After 沿用来源契约，不随票据拆分新建一套语义。
- 每票所需验证由后续实施者执行和记录；本轮只规划票据，没有新增或运行代码／测试。最终联合验收补齐组合和实机证据，各票的边界验证仍在各自票内完成。

## 1. 打开会话并核实运行状态

**What to build：**从工作台新建或打开会话，读取完整历史，确认当前／最近运行身份和中文状态；重新进入工作台后已有记录和输入仍可继续使用。

**Why：**先建立查询和会话数据归属，让后续操作有可信目标；将必要的数据所有者整理放进这条可演示的读取路径。

**API／边界：**既有创建会话、历史查询与宿主状态；历史外层 run_status；新增纯读 RunSnapshot 查询；BackendSession 地址租约和选择代次。

**Blocked by：**无，可立即开始。

- [ ] 历史保留完整公开记录并按 seq 排序，每条外层 run_status 来自所属 Run 查询时状态，同 Run 在一次响应中一致；空历史、读取中和读取失败分开。
- [ ] 末条消息定位 run_id／run_status，快照 id 与 SSE run_id 在边界统一并核对 thread_id；未开始、运行中、等待审批、已完成、已取消、运行失败使用中文，未知不能当未开始。
- [ ] Run 快照只读已提交事实，no-store，不调用会写入恢复错误的旧 interrupted 校验路径；归属错误 404、暂不可读 503／Retry-After、损坏 500 不改变 Run。
- [ ] 会话事实、选择和内存输入归属不随 Workspace 卸载；宿主租约撤销和旧选择的迟到响应不能写入新目标，既有正常发送和观察路径保持可用。
- [ ] 新建返回有效 thread_id 且用户意图仍当前时选中，否则保留条目并提示；结果未知只读列表核对，不自动再建；已创建后的列表失败不撤销创建。
- [ ] 没有会话时不把草稿存到空 ID；当前有服务端 title 时使用它，否则先显示新会话，完整 ID 保留可查。
- [ ] 通过公开 HTTP／Runtime 查询验证纯读与身份，在当前 Tauri 工作台演示新建、打开、终态读取及宿主非 ready 后恢复记录。

## 2. 自动分页浏览带状态的会话列表

**What to build：**按真实更新时间浏览带中文状态的会话，滚动到底自动读取更早的 20 条，并能区分加载、无匹配、失败和没有更多。

**Why：**为会话浏览建立真实分页与状态摘要，避免列表更新或过滤改变当前对话。

**API／边界：**GET /api/threads 的 data／next_cursor；只接受可选 cursor；共享会话数据层、列表滚动与本地过滤。

**Blocked by：**打开会话并核实运行状态。

- [ ] 响应保留既有会话字段，增加同一当前／最近发起 Run 的 run_id／run_status；尚无 Run 时两者均 null，旧 Run 晚结算不改变最近发起身份。
- [ ] 每页固定 20，updated_at DESC／id DESC；游标不透明并冻结签发时的时间／ID 边界，无效 422；状态和影响排序的更新时间同次提交，查询和 delta 不更新时间。
- [ ] 到底／聚焦列表的 End 或 PageDown 自动读下一页，无正常加载更多按钮；原始 data 少于 20 或 next_cursor=null 停止并显示没有更多，不使用过滤数或去重新增数判断。
- [ ] 按 ID 更新、插入和去重，保持真实排序、当前选择和草稿；独立保有分页进度，第一页请求不删除更早页，缺项不解释为删除。
- [ ] 无过滤且不足可视区可自动填充；过滤只匹配已加载显示标题，明确标范围，过滤后明确向下滚动仍可触发一页，不因键入过滤读完全部历史。
- [ ] 首次无事实使用等高 skeleton，刷新保留列表，更多页底部加载／原位失败重试；失败哨兵不无限请求，Retry-After 及无效游标显式重载可用。
- [ ] 公开接口与页面覆盖 0／20／21／40／41 条、相同时间、重复 ID、游标边界变化、过滤少匹配和失败，主聊天阅读与观察不受分页影响。

## 3. 全量重建消息与当前运行事实

**What to build：**发送或重开会话时，以同一投影接入真实消息、流式预览、运行状态和审批事件，全量回放后不重复、不串会话。

**Why：**让所有 UI 消费完整事实，并建立后续恢复、审批、工具与详情的共同输入。

**API／边界：**既有发送 POST SSE、Run GET stream；metadata／event／delta／error 四类公开帧；完整历史与按会话／Run 隔离的数据。

**Blocked by：**打开会话并核实运行状态。

- [ ] 历史 running／interrupted 建立既有 GET stream；完整消息按会话 seq 合并，保留公开字段和原内容结构；同 seq 完整事实覆盖预览，重复只一条。
- [ ] 同 seq 多 delta 按到达顺序追加，不按文字或 seq 去重；新 GET 有效 metadata 后仅重置目标 Run 预览，metadata 前失败保留已显示正文。
- [ ] 有效 SSE metadata 决定观察中 Run 当前状态，历史 lifecycle 和旧列表／快照不覆盖；终态不回退，interrupted 可继续 running，省略字段保留，null 按字段契约解释。
- [ ] 持久事件按 thread_id／run_id／seq 保留与合并；同 seq 冲突和无法校验载荷作为协议问题，不伪造已确认事实；seq 空洞和一次查询缺项不删除旧事实。
- [ ] GET 全量回放经后端 checkpoint／审批一致性校验，前端按 required／resolved／invalidated 重建；当前仍 interrupted 且正常回放结束才具备可审批身份，JSON 查询不替代它。
- [ ] 租约、选择、Run 与观察代次共同过滤迟到帧；新 Run 从自身事实开始，切换关闭旧观察不调用 cancel；GET stream 不加 cursor 或 Last-Event-ID。
- [ ] 以公开 SSE 验证重复、乱序、旧 metadata、同 seq 增量、等待审批正常 EOF 与新目标迟到，页面可演示真实发送和刷新恢复。

## 4. 原文发送并保留持久消息草稿

**What to build：**按原文发送消息，运行期间仍能编辑下一条草稿；重启后保留文字，发送结果未知时可以查询核对和主动决定后续动作。

**Why：**让用户控制每次任务开始，保护请求确认前后编辑的内容，并避免重复执行。

**API／边界：**ChatRequest.message、发送 POST 的有效 metadata；本地命名空间／会话草稿和版本；历史／运行 GET 核实；共享发送动作。

**Blocked by：**全量重建消息与当前运行事实。

- [ ] trim 只判空，实际 POST、已提交用户正文和提交原文保留首尾空格、缩进、换行；全空白禁发，既有无效 surrogate 替换不裁剪正常正文。
- [ ] running／interrupted、发送 pending 时可编辑并保存草稿但不能普通发送；终态不自动发送，不排队；底部当前运行操作保留。
- [ ] 可发时 Enter 与按钮同动作，Shift+Enter 换行；不可发时 Enter 拦截且不换行、不取消、不审批，输入法候选优先，长按不重复。
- [ ] 保留提交原文和版本，只由本次 POST 的有效 metadata 确认接受并清对应版本；请求期间新草稿不被覆盖，GET／旧 Run metadata 或相同正文不证明接受。
- [ ] 接受前断连、解析、POST 500／中止等保留发送结果待确认，只 GET；有 run_id 后按已接受 Run 恢复观察。可查询并人工确认对应消息，或主动作为新任务发送，仍受当前资格约束。
- [ ] 按会话跨切换／重启保存草稿、版本和必要未知记录；旧 pending 重开后待核实，不恢复地址、计时器、连接或执行。本地失败回退内存并提示，会话 404 可复制或转移文字。
- [ ] 通过公开请求与持久消息验证原文一致和单次提交；实机验证中文 IME、运行期编辑、重启恢复、未知结果人工处理以及迟到接受不清新文字。

## 5. 断流后的有限 GET 恢复与手动重连

**What to build：**意外断流后自动有限次数恢复同一运行，停止后保留手动重连和状态查询，正常等待审批或终态结束保持真实结果。

**Why：**把观察故障与执行结果分开，提供可预测且不会重复执行的恢复路径。

**API／边界：**同 Run GET stream／纯读查询；结构化 HTTP 与 SSE error；统一读取任务、计时和 Retry-After。

**Blocked by：**全量重建消息与当前运行事实。

- [ ] 分别显示未建立、连接中、已建立、重试等待、正常结束、暂停和恢复停止；running 意外 EOF 可恢复，interrupted／终态正常 EOF 不重连，不将连接错误写成 Run error。
- [ ] 网络、GET 503／可恢复 SSE error 按 1／2／5 秒最多三次 GET；不早于 Retry-After，同一故障的 error 与 EOF 不重复安排，同目标无并发连接。
- [ ] 首帧 metadata 不重置失败计数，连续正常 30 秒或正常 interrupted／终态 回放完成才重置；三次失败后保留事实和手动入口，列表轮询不不断重开恢复。
- [ ] 手动重连、重新进入／显示和有效新租约可开启新轮次，复用任务并遵守等待；主动 Abort／失效不消耗次数或取消后台任务。
- [ ] 404、GET stream 400、GET 500、不可恢复 SSE error／解析失败停止自动恢复并提供对应手动路径；长工具无输出不按超时判失败。
- [ ] POST 错误只核实，不自动重发；保留 status／detail／Retry-After、SSE code／message／recoverable，未分类错误保留说明，不自动重启宿主。
- [ ] 以可控公开网络边界验证次数／间隔、Retry-After、metadata 后即失败、重复 EOF、失效计时器及手动竞争，并在工作台演示断流恢复。

## 6. 隐藏暂停读取并轮询会话状态

**What to build：**可见窗口每五秒刷新第一页会话，隐藏到托盘后暂停读取但后台任务继续，重新显示立即核实并恢复当前会话。

**Why：**将窗口生命周期接到既有读取、草稿和恢复规则，保护后台任务与列表分页进度。

**API／边界：**get_workspace_visibility、workspace-visibility-changed 的 revision／visible；现有宿主状态；第一页 GET、历史与观察读取协调。

**Blocked by：**自动分页浏览带状态的会话列表；原文发送并保留持久消息草稿；断流后的有限 GET 恢复与手动重连。

- [ ] 先订阅可见事件再查询，按 revision 接受，实际成功 hide／show 后更新；失焦不算隐藏，失败操作不伪造可见性，查询失败保留已知值、首次未知按可见。
- [ ] visible 且 ready 每 5 秒请求第一页，不重叠，按 ID 更新已有字段／插入并排序；失败保留列表，503 推迟下一轮，不叠额外三次重试。
- [ ] 第一页轮询不清更早页、不改下一页游标、选择或草稿；发现不同 run_id 先读历史核实，再切观察目标，旧摘要不抢新目标。
- [ ] 切换、隐藏、宿主非 ready 时停 SSE、相关 GET 和计时器，不 cancel；输入、完整事实及未知提交记录保留，未确认 POST 的中止不撤回后端执行。
- [ ] 重新显示／选择／ready 合并触发一次历史定位和适用观察恢复；同一失败轮次不被后台轮询绕过，布局与详情开关不触发重新进入。

## 19. 有限核实待结算用量

**What to build：**等待审批或终态时用量仍待结算可自动有限核实，达到上限明确暂停，用户可主动继续核实。

**Why：**允许用量晚保存而不假定运行结束即结算，也不形成无限或并行轮询。

**API／边界：**同目标纯读 RunSnapshot、usage_pending、执行阶段确认；窗口可见输入、共享读取协调／重试预算与 Retry-After。

**Blocked by：**查看当前运行详情与真实累计用量。

- [ ] 只在当前目标、visible／ready、状态 interrupted／终态且已确认 pending=true 时开始；正常 running SSE 不叠用量轮询。
- [ ] 完成请求后等 5 秒，本轮最多 12 次后续请求，失败／重试算次数，成功但 true 不重置；适用 false 立即停，数字不变／过时／EOF 不自行当已结算。
- [ ] 可恢复错误用 1／2／5 秒三次与 Retry-After 的同一任务，不并开五秒与错误任务；三次仍失败或 404／500／协议问题停止，保留最后值和局部错误。
- [ ] 达上限显示仍在结算且自动核实暂停，可主动继续读并启动新受限轮次；关详情摘要仍可核实，切换／隐藏／租约失效停止，返回同阶段不自动重置预算。
- [ ] 旧阶段／旧同组字段响应不覆盖新值，取消后同 updated_at 的有效晚量可补；查询／结算失败不改 Run，消息保存／事件补读分别确认。
- [ ] 可控公开查询验证时间、12 次、三次失败、Retry-After、重复触发、隐藏／切换和新阶段，在实机展示晚量与手动继续。
